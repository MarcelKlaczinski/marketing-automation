### 3.3 Tier-Derivation from tool_persona_scores (Marcel: data-driven)

**Goal:** Bad/Good/Great tiers automatic from scores.

**Approach options:**

**Option α — Threshold-based:**
```typescript
function deriveTier(score: number): 'bad' | 'good' | 'great' {
  if (score >= 0.75) return 'great';
  if (score >= 0.45) return 'good';
  return 'bad';
}
```

**Option β — Relative-ranking (terciles):**
```typescript
// Sort tools by score, split into 3 tiers by position
// Top third = great, middle = good, bottom = bad
```

**Option γ — Per-persona contextual:**
```typescript
// Tier depends on which persona the carousel targets
// Tool great for beginners might be "good" for power-users
```

### Discovery-Recommendation: **Option β (relative-ranking terciles) with Option α fallback**

Reasoning:

1. **Relative-ranking always produces balanced tiers** — no "all tools are great" degenerate case
2. **Threshold-based (α) risks empty-tiers** — if all selected tools score high, no "bad" tier
3. **Per-persona (γ) is V2** — adds complexity, Marcel said "automatic"
4. **Pragmatic:** Pick N tools (3-5), rank by persona-score, split into tiers. For 3 tools = 1 per tier. For 5 = 2/2/1 OR 1/2/2.
5. **"Bad" framing-note:** Per Marcel reference "Writing? Bad→Good→Great" — but Toolwiki shouldn't label real tools "Bad" (legal/affiliate-relationship risk). **Reframe tiers:** "Solide / Stark / Spitze" OR "Gut / Besser / Am Besten" — keeps tier-energy without trashing tools Marcel may have affiliate-deals with.

**CRITICAL Marcel-decision needed (Q-new):** Tier-labels. "Bad/Good/Great" works for generic-references but Toolwiki has affiliate-relationships. Recommend positive-framing tiers.
