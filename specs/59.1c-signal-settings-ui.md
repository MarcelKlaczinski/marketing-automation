## Goal

Surface in Settings UI everything users need to configure external signal sources and adapter credentials. Two distinct pages:

1. **Settings → Credentials** (existing page, extended) — generic credential management for adapters that aren't operationally configurable: Anthropic, Voyage, DataForSEO, Replicate, plus the new credential-only entries for ProductHunt (signal source uses OAuth keys), Reddit (OAuth), GitHub (PAT).

2. **Settings → Signal Sources** (new page) — operational config for each signal source: enable toggle, source-specific config (subreddits, topics, queries, feeds), cron toggle, verify connectivity, per-source manual trigger. Vendor-RSS gets full CRUD.

After 59.1c lands, Marcel can fully self-serve every signal source from UI: connect credentials, configure operational parameters, enable cron, test connectivity, trigger manual collection. No more DB-direct config edits.

## What this is NOT

- Not redesigning the existing Credentials page (just extending the adapter list)
- Not changing the signal-collector worker behavior
- Not changing adapter packages (Reddit, GitHub, ProductHunt, HackerNews are all backend-complete)
- Not Cold-Start changes (defaults still come from project creation init)
- Not analytics on signal collection (volume, conversion to briefs — Phase E)
- Not vendor-rss feed health monitoring (last-fetch status, error tracking — 59.7 polish)

### A.2 Vendor-RSS Schema Migration

**File:** `packages/db/src/schema/project-config.ts`

Current shape:
```typescript
vendor_rss: z.object({
  enabled: z.boolean().default(false),
  feeds: z.array(z.string().url()).default([]),
}),
```

New shape:
```typescript
vendor_rss: z.object({
  enabled: z.boolean().default(false),
  feeds: z.array(z.object({
    id: z.string().uuid(),
    url: z.string().url(),
    label: z.string().min(1).max(100),
    enabled: z.boolean().default(true),
    addedAt: z.string().datetime(),       // ISO timestamp
    lastVerifiedAt: z.string().datetime().nullable().default(null),
  })).default([]),
}),
```

**Backward compatibility (one-shot migration via JSONB transform):**

```sql
-- migrations/0XXX_vendor_rss_feeds_to_objects.sql
UPDATE project_configurations
SET signal_sources = jsonb_set(
  signal_sources,
  '{vendor_rss,feeds}',
  COALESCE(
    (
      SELECT jsonb_agg(jsonb_build_object(
        'id', gen_random_uuid()::text,
        'url', feed_url,
        'label', regexp_replace(feed_url, '^https?://(www\.)?', ''),  -- domain as default label
        'enabled', true,
        'addedAt', NOW()::text,
        'lastVerifiedAt', null
      ))
      FROM jsonb_array_elements_text(signal_sources->'vendor_rss'->'feeds') AS feed_url
    ),
    '[]'::jsonb
  )
)
WHERE jsonb_typeof(signal_sources->'vendor_rss'->'feeds') = 'array'
  AND jsonb_array_length(signal_sources->'vendor_rss'->'feeds') > 0
  AND signal_sources->'vendor_rss'->'feeds'->0 IS NOT NULL
  AND jsonb_typeof(signal_sources->'vendor_rss'->'feeds'->0) = 'string';
```

The migration is idempotent: it only converts arrays whose first element is a string. Already-converted arrays (objects) are skipped.

**Adapter compatibility:** The signal-collector worker code that consumes `vendor_rss.feeds` needs to read `.url` from objects instead of treating items as strings. Find and update:

```bash
rg -n "vendor_rss.*feeds" apps/api/src/workers packages/adapters
```

Likely 1-3 callsites. Each becomes `feed.url` instead of `feed`. Also filter out `feed.enabled === false`.

### A.3 Vendor-RSS Feed CRUD Endpoints

Three new endpoints under existing project routes.

**A.3.1 POST /api/projects/:slug/signal-sources/vendor-rss/feeds**

Add a feed with URL validation + RSS parse verification.

```typescript
// Body
const addFeedSchema = z.object({
  url: z.string().url(),
  label: z.string().min(1).max(100),
});

// Handler
async function handleAddFeed(c: Context) {
  const { slug } = c.req.param();
  const input = addFeedSchema.parse(await c.req.json());

  const project = await loadProjectBySlug(slug);
  if (!project) return c.json({ ok: false, error: "project_not_found" }, 404);

  // Check for duplicate URL
  const config = await loadActiveConfig(project.id);
  const existing = config.signalSources.vendor_rss.feeds.find(f => f.url === input.url);
  if (existing) {
    return c.json({ ok: false, error: "feed_already_exists" }, 409);
  }

  // Verify the feed parses
  const verifyResult = await verifyRssFeed(input.url);
  if (!verifyResult.ok) {
    return c.json({
      ok: false,
      error: "feed_verification_failed",
      message: verifyResult.error,
    }, 422);
  }

  // Append to config
  const newFeed = {
    id: crypto.randomUUID(),
    url: input.url,
    label: input.label,
    enabled: true,
    addedAt: new Date().toISOString(),
    lastVerifiedAt: new Date().toISOString(),
  };

  const updatedFeeds = [...config.signalSources.vendor_rss.feeds, newFeed];

  await updateSignalSourcesConfig(project.id, {
    vendor_rss: {
      ...config.signalSources.vendor_rss,
      feeds: updatedFeeds,
    },
  });

  return c.json({ ok: true, data: { feed: newFeed } }, 201);
}
```

`verifyRssFeed(url)` lives in `packages/adapters/vendor-rss/src/verify.ts` (create if doesn't exist):

```typescript
// packages/adapters/vendor-rss/src/verify.ts
import { parseFeed } from "<rss-parser-of-choice>";

export async function verifyRssFeed(url: string): Promise<{ ok: boolean; error?: string; title?: string }> {
  try {
    const response = await fetch(url, {
      headers: { "User-Agent": "toolwiki-rss-verify" },
      signal: AbortSignal.timeout(10_000),
    });
    if (!response.ok) {
      return { ok: false, error: `HTTP ${response.status}` };
    }
    const text = await response.text();
    const parsed = await parseFeed(text);
    if (!parsed || !parsed.items) {
      return { ok: false, error: "Not a valid RSS/Atom feed" };
    }
    return { ok: true, title: parsed.title };
  } catch (err) {
    return {
      ok: false,
      error: err instanceof Error ? err.message : String(err),
    };
  }
}
```

If no RSS parser is currently in deps, reuse whatever the signal-collector worker uses (check `packages/adapters/vendor-rss` first; if missing, propose `rss-parser` or `@extractus/feed-extractor`).

**A.3.2 PATCH /api/projects/:slug/signal-sources/vendor-rss/feeds/:feedId**

Edit feed (rename label, toggle enabled).

```typescript
const updateFeedSchema = z.object({
  label: z.string().min(1).max(100).optional(),
  enabled: z.boolean().optional(),
}).refine(d => d.label !== undefined || d.enabled !== undefined, {
  message: "At least one of label or enabled must be provided",
});

async function handleUpdateFeed(c: Context) {
  const { slug, feedId } = c.req.param();
  const input = updateFeedSchema.parse(await c.req.json());

  const project = await loadProjectBySlug(slug);
  if (!project) return c.json({ ok: false, error: "project_not_found" }, 404);

  const config = await loadActiveConfig(project.id);
  const feedIndex = config.signalSources.vendor_rss.feeds.findIndex(f => f.id === feedId);
  if (feedIndex === -1) {
    return c.json({ ok: false, error: "feed_not_found" }, 404);
  }

  const updatedFeed = {
    ...config.signalSources.vendor_rss.feeds[feedIndex],
    ...(input.label !== undefined && { label: input.label }),
    ...(input.enabled !== undefined && { enabled: input.enabled }),
  };

  const updatedFeeds = [...config.signalSources.vendor_rss.feeds];
  updatedFeeds[feedIndex] = updatedFeed;

  await updateSignalSourcesConfig(project.id, {
    vendor_rss: { ...config.signalSources.vendor_rss, feeds: updatedFeeds },
  });

  return c.json({ ok: true, data: { feed: updatedFeed } });
}
```

**Note**: URL is not editable — to change a URL, delete + re-add (avoids dedup complexity).

### A.5 Verify Manual Trigger Endpoints

**POST /api/projects/:slug/signal-sources/:source/trigger**

Enqueue an immediate collection job for the source. Returns the job ID for status tracking.

```typescript
async function handleManualTrigger(c: Context) {
  const { slug, source } = c.req.param();
  if (!["reddit", "github", "hackernews", "producthunt", "vendor_rss"].includes(source)) {
    return c.json({ ok: false, error: "invalid_source" }, 400);
  }

  const project = await loadProjectBySlug(slug);
  if (!project) return c.json({ ok: false, error: "project_not_found" }, 404);

  // Enqueue via existing signal-collector queue (per 59.1a pattern)
  const jobId = `manual-${source}-${project.id}-${Date.now()}`;
  await signalCollectorQueue.add(
    "collect-adapter",
    { projectId: project.id, adapter: source },
    { jobId, attempts: 1 },
  );

  return c.json({ ok: true, data: { jobId } }, 202);
}
```

Reuses existing signal-collector queue + worker dispatch. No new worker code needed.

### C.2 SettingsSignalSourcesPage.vue

```vue
<template>
  <div class="signal-sources-page">
    <h1 class="page-title">{{ $t("settings.signalSources.title") }}</h1>
    <p class="page-description">{{ $t("settings.signalSources.description") }}</p>

    <SignalSourceCard
      v-for="source in sources"
      :key="source.id"
      :source-id="source.id"
      :credentials-status="credentialsStatus(source.id)"
      :config="getSourceConfig(source.id)"
      :cron-active="getCronState(source.id)"
      @save-config="onSaveConfig"
      @toggle-enabled="onToggleEnabled"
      @toggle-cron="onToggleCron"
      @verify="onVerify"
      @manual-trigger="onManualTrigger"

<script lang="ts">
import { defineComponent } from "vue";
import { useQuery } from "@tanstack/vue-query";

export default defineComponent({
  name: "SettingsSignalSourcesPage",
  setup() {
    const { data: project } = useQuery({
      queryKey: ["project", "current"],
      queryFn: () => apiClient.projects.getCurrent(),
    });
    const { data: systemStatus } = useQuery({
      queryKey: ["system-status"],
      queryFn: () => apiClient.system.status(),
      refetchInterval: 30_000,
    });
    return { project, systemStatus };
  },
  data: () => ({
    sources: [
      { id: "reddit", requiresCredentials: true, configurable: true },
      { id: "github", requiresCredentials: true, configurable: true },
      { id: "producthunt", requiresCredentials: true, configurable: true },
      { id: "hackernews", requiresCredentials: false, configurable: true },
      { id: "vendor_rss", requiresCredentials: false, configurable: true, hasCrud: true },
    ],
  }),
  computed: {
    projectSlug(): string {
      return this.$route.params.slug as string;
    },
  },
  methods: {
    credentialsStatus(sourceId: string): "configured" | "not-configured" | "error" | "not-required" {
      const source = this.sources.find(s => s.id === sourceId);
      if (!source?.requiresCredentials) return "not-required";
      return this.systemStatus?.data?.adapters?.[sourceId]?.status ?? "not-configured";
    },
    getSourceConfig(sourceId: string) {
      return this.project?.data?.signalSources?.[sourceId];
    },
    getCronState(sourceId: string): boolean {
      const map: Record<string, string> = {
        reddit: "redditSignalCronEnabled",
        github: "githubSignalCronEnabled",
        hackernews: "hackernewsSignalCronEnabled",  // verify exists
        producthunt: "producthuntSignalCronEnabled",
        vendor_rss: "vendorRssSignalCronEnabled",
      };
      const flagKey = map[sourceId];
      return this.project?.data?.[flagKey] ?? false;
    },
    async onSaveConfig({ sourceId, config }: { sourceId: string; config: any }) {
      await apiClient.signalSources.updateConfig({
        slug: this.projectSlug,
        source: sourceId,
        config,
      });
      this.$q.notify({ type: "positive", message: this.$t("settings.signalSources.configSaved") });
    },
    async onToggleEnabled({ sourceId, enabled }: { sourceId: string; enabled: boolean }) {
      await apiClient.signalSources.updateConfig({
        slug: this.projectSlug,
        source: sourceId,
        config: { enabled },
      });
    },
    async onToggleCron({ sourceId, active }: { sourceId: string; active: boolean }) {
      const map: Record<string, string> = {
        reddit: "redditSignalCronEnabled",
        github: "githubSignalCronEnabled",
        hackernews: "hackernewsSignalCronEnabled",
        producthunt: "producthuntSignalCronEnabled",
        vendor_rss: "vendorRssSignalCronEnabled",
      };
      await apiClient.projects.update({
        slug: this.projectSlug,
        body: { [map[sourceId]]: active },
      });
    },
    async onVerify(sourceId: string) {
      const result = await apiClient.system.verify({ adapter: sourceId });
      if (result.data.ok) {
        this.$q.notify({ type: "positive", message: this.$t("settings.signalSources.verifySuccess") });
      } else {
        this.$q.notify({ type: "negative", message: result.data.error });
      }
    },
    async onManualTrigger(sourceId: string) {
      const ok = await this.$q.dialog({
        title: this.$t("settings.signalSources.confirmTrigger.title"),
        message: this.$t("settings.signalSources.confirmTrigger.message", {
          source: this.$t(`settings.signalSources.sources.${sourceId}.name`),
        }),
        cancel: true,
        persistent: true,
      }).then(() => true).catch(() => false);
      if (!ok) return;

      const result = await apiClient.signalSources.trigger({
        slug: this.projectSlug,
        source: sourceId,
      });
      this.$q.notify({
        type: "positive",
        message: this.$t("settings.signalSources.triggerStarted", { jobId: result.data.jobId }),
      });
    },
  },
});
</script>
```

<script lang="ts">
import { defineComponent, PropType } from "vue";

interface Feed {
  id: string;
  url: string;
  label: string;
  enabled: boolean;
  addedAt: string;
  lastVerifiedAt: string | null;
}

export default defineComponent({
  name: "VendorRssConfigEditor",
  emits: [],  // CRUD goes directly via apiClient, not via parent save event
  props: {
    config: { type: Object as PropType<{ feeds: Feed[] }>, required: true },
    disabled: { type: Boolean, default: false },
  },
  data: () => ({
    newFeedUrl: "",
    newFeedLabel: "",
    adding: false,
  }),
  computed: {
    feeds(): Feed[] {
      return this.config?.feeds ?? [];
    },
    projectSlug(): string {
      return this.$route.params.slug as string;
    },
    canAdd(): boolean {
      try {
        new URL(this.newFeedUrl);
        return this.newFeedLabel.length >= 1 && !this.adding;
      } catch {
        return false;
      }

  },
  methods: {
    async onAdd() {
      this.adding = true;
      try {
        await apiClient.signalSources.addVendorRssFeed({
          slug: this.projectSlug,
          body: { url: this.newFeedUrl, label: this.newFeedLabel },
        });
        this.newFeedUrl = "";
        this.newFeedLabel = "";
        await this.$queryClient.invalidateQueries({ queryKey: ["project", "current"] });
        this.$q.notify({
          type: "positive",
          message: this.$t("settings.signalSources.vendorRss.feedAdded"),

      } catch (err: any) {
        const errorKey = err?.body?.error;
        let message = this.$t("settings.signalSources.vendorRss.addError");

          message = this.$t("settings.signalSources.vendorRss.duplicateFeed");

        @click="onAdd"
      >
        {{ $t("common.add") }}
      </GlassButton>

      {{ $t("settings.signalSources.duplicateItem") }}
    </p>

<script lang="ts">
import { defineComponent, PropType } from "vue";

export default defineComponent({
  name: "StringListEditor",
  emits: ["update:modelValue"],
  props: {
    modelValue: { type: Array as PropType<string[]>, default: () => [] },
    placeholder: { type: String, default: "" },
  },
  data: () => ({
    newItem: "",
  }),
  computed: {
    isDuplicate(): boolean {
      const trimmed = this.newItem.trim();
      return !!trimmed && this.modelValue.includes(trimmed);
    },
  },
  methods: {
    onAdd() {
      const trimmed = this.newItem.trim();
      if (!trimmed || this.isDuplicate) return;
      this.$emit("update:modelValue", [...this.modelValue, trimmed]);
      this.newItem = "";
    },
    onRemove(index: number) {
      const next = [...this.modelValue];
      next.splice(index, 1);
      this.$emit("update:modelValue", next);
    },
  },
});
</script>

## Risks & Mitigations

**R1: Vendor-RSS migration corrupts existing feeds**
- *Mitigation*: Migration is idempotent (checks if items are strings before converting). Test on a copy of staging data first. Backup before running.

**R2: verifyRssFeed times out on slow RSS endpoints**
- *Mitigation*: 10s AbortSignal timeout. User sees clear error message. Feed not added.

**R3: Per-source config endpoint conflicts with existing project PATCH**
- *Mitigation*: Session 1 explicit decision step before implementing. Reuse if possible; new endpoint only if reuse causes weird overloads.

**R4: HackerNews cron flag doesn't exist in projects table**
- *Mitigation*: Verify in implementation. If missing, add column + same pattern as Reddit/GitHub cron flags. ~30 min if needed.

**R5: SDK regen breaks existing pages**
- *Mitigation*: Run typecheck immediately after regen. Type drift should be additive only.

**R6: i18n key explosion (100+ new keys)**
- *Mitigation*: Bulk-add per source namespace in a single edit pass. Use code-gen if pattern is mechanical. DE + EN side-by-side editing reduces drift.

**R7: User adds bad feed URL that crashes signal collector later**
- *Mitigation*: verifyRssFeed at add-time catches most cases. Collector itself should already have per-feed error catching (verify in worker code).

**R8: vendor-rss schema change breaks signal-collector mid-deploy**
- *Mitigation*: Migration + worker code change in same deployment. Atomic deploy. If concerned, deploy migration first (worker still works with arrays of strings because the migration converts them), then deploy new worker code.

## Decisions Made

**D1: Two-page split (Credentials + Signal Sources).**
Credentials is generic credential CRUD for any adapter. Signal Sources is operational config for signal-collection sources. Some sources appear in both (Reddit, GitHub, PH have credentials in Credentials page, operational config in Signal Sources page). Cross-reference banner connects them.

**D2: ProductHunt credentials in Credentials page, enable toggle in Signal Sources page.**
PH config is just a boolean today (bare flag). Credentials (api_key + api_secret) are credential management, the enable toggle is operational. Splitting them follows the page pattern. PH's config editor is just an info placeholder.

**D3: Vendor-RSS gets full CRUD (per user decision Option A).**
Schema migration to object array with id/url/label/enabled/addedAt. Three endpoints. Full edit UI.

**D4: G1+G3 fixes in separate prep commit (per user decision).**
59.1c-prep is its own spec. 59.1c assumes those fixes are in.

**D5: Reddit/GitHub use shared `StringListEditor` component.**
Same pattern (list of strings, add/remove). One component, multiple uses. Reduces code duplication.

**D6: Inline label edit (click-to-edit) for vendor-rss feeds.**
No separate edit modal. Click label → input appears → Enter or blur saves. Escape cancels. Lower friction than modal flow.

**D7: Manual trigger requires confirmation dialog.**
Triggering a collection costs nothing (free APIs) but generates external API calls. Confirmation prevents accidental triggers.

**D8: Verify call timing.**
Verify on add-feed (one-shot, blocks add until confirmed). Verify on demand for credentials (button click). No automatic background re-verification (would burn quota; Phase E if needed).

**D9: Cron toggle separate from enable toggle.**
Source can be enabled without cron (manual trigger only). Cron requires source enabled.

**D10: vendor-rss CRUD endpoints are nested under /signal-sources/vendor-rss/ not /projects/:slug.**
Resource-oriented URL. Cleaner than overloading project PATCH.

**D11: All operations go through TanStack Query invalidation, not local optimistic updates.**
Simpler than optimistic UI. Latency is acceptable (~100-300ms per action). Edge cases (concurrent edits, failures) handled naturally.

## Discovered During Implementation

### ProductHunt boolean merge bug (critical)
`SignalSourcesSchema` stores `producthunt` as a plain `z.boolean()`, not an object. The generic `updateSourceConfig` merge helper `{ ...currentSource, ...partial }` spread a boolean as if it were an object — this passes TypeScript but produces an invalid shape that `SignalSourcesSchema.parse()` rejects at runtime. Fix: special-case `source === 'producthunt'` to extract `partial.enabled ?? currentBoolean` directly. Pattern documented in root `CLAUDE.md`.

### VendorRssConfigEditor i18n oversight
Spec did not specify i18n keys for the URL and Label form field labels (only placeholders were specced). Two keys added to both DE and EN: `vendor_rss.urlField` and `vendor_rss.labelField`. Using `'URL'` as a hardcoded string and `common.addKeyword` ("Keyword hinzufügen") as the label field label would both have been wrong.

### Signal sources route extraction
`signal-sources.ts` was split out into `apps/api/src/routes/projects/signal-sources.ts` (separate file) rather than adding to the already-large `projects.ts`. The Hono router is mounted in `server.ts` at `/api/projects` alongside the main projects router — both share the same path prefix.

## Deviations from Spec

- **Section A (Backend)** implemented in Session 1 with hackernews/producthunt/vendor_rss cron columns added (spec only called for github as A.1 — mirrored all remaining sources for completeness).
- **Verify button logic simplified**: spec had two separate v-if blocks for verified-credential sources vs. public API sources; collapsed into `v-if="!requiresCredentials || credentialsStatus === 'configured'"` in SignalSourceCard.
- **StatusBadge `publicApi` variant maps to `"pending"`**: spec did not specify which StatusBadge variant to use; `"pending"` (amber) was chosen as the closest semantic match for "uses public API, no credentials needed".
