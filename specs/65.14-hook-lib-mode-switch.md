## 3. Architecture Decisions

### 3.1 New Hook-Pool Composition

**Target distribution (~30-40 total, replacing 60 generics):**

Per format-type × locale, aim for **~3-4 hooks per pattern × 5 patterns = 15-20 per format-type-locale**:

| Pattern | Example DE | Example EN |
|---|---|---|
| **Number-driven** | "{n} KI-Tools die {painPoint} killen" | "{n} AI Tools to kill {painPoint}" |
| **Tier-comparison** | "{toolA}: Schlecht. {toolB}: Gut. {toolC}: GENIAL." | "{toolA}: Bad. {toolB}: Good. {toolC}: GREAT." |
| **Year-anchor** | "{n} KI-Tools die du 2026 wirklich brauchst" | "{n} AI Tools you'll actually use in 2026" |
| **Contrarian** | "RIP {established}: {n} Tools die ihn ersetzen" | "RIP {established}: {n} AI Tools That Will End It" |
| **Curator-confidence** | "Ich habe {n} KI-Tools getestet. Nur {k} überlebten." | "I tested {n} AI Tools. Only {k} survived." |

**5 patterns × 5 format-types × 2 locales × 3 variants each = 150 hooks max.**

**Pragmatic V1.6 scope:** 30-40 total (5 patterns × 3-4 format-types × 2 locales × 1-2 variants).

### 3.2 Per-Format-Type Hook Density

Not all patterns fit all format-types:

| Format-Type | Number | Tier | Year | Contrarian | Curator |
|---|---|---|---|---|---|
| `story_arc_clickbait` | low | low | medium | **HIGH** | medium |
| `lifestyle_listicle` | **HIGH** | medium | **HIGH** | low | medium |
| `opinion_recommendation` | medium | **HIGH** | medium | **HIGH** | **HIGH** |
| `top_n_comparison` | **HIGH** | **HIGH** | **HIGH** | low | medium |
| `head_to_head` | low | **HIGH** | low | low | low |

**Discovery-Recommendation:** Pattern-density per format-type ist intuitive — story-arc needs narrative-hook (Contrarian fits), top-n needs ranking-energy (Number+Tier), head-to-head needs binary-framing (Tier).

### 3.3 Variable-Pool Extension

New patterns introduce new variables needing population by brief-generator:

| Variable | Source |
|---|---|
| `{painPoint}` | Brief-topic (LLM-derived OR persona-mapping) |
| `{toolA}`, `{toolB}`, `{toolC}` | Tool-IDs from formatConfig |
| `{established}` | Brief-topic OR explicit field (e.g. "ChatGPT" / "Notion" — known incumbents) |
| `{n}`, `{k}` | formatConfig.topN OR derived (k = n/2 für drama-effect) |

**Brief-generators need extension** to populate these variables. Per format-type:

```typescript
// story_arc_clickbait generator (extension):
hookData.variables.painPoint = await llmDerivePainPoint(brief.topic, profession);
hookData.variables.established = formatConfig.competitorTool ?? null;

// opinion_recommendation generator:
hookData.variables.n = formatConfig.totalToolsTested ?? 10;
hookData.variables.k = formatConfig.recommendedCount ?? 3;
```

**Verify:** Spec 65.5 brief-generator shape — variables-population is per-generator-specific.

### 3.4 Deprecation Path für Generic 60-Hook Pool

**Option α — Delete:** Remove generic hooks via migration, force-pick from new pool.

Pros: Clean, no drift
Cons: Existing briefs' `hookData.hookId` → orphan references (FK-NULL)

**Option β — Tag as 'deprecated':** Add `hook_templates.deprecated_at TIMESTAMPTZ`, filter in pickHook.

Pros: Audit-trail, no FK-break
Cons: Pool grows over time

**Option γ — Tag as 'subtle' mode + use für SEO:** Repurpose generic hooks für SEO-mode (article-titles), drama-hooks für Social.

**Verify:** Per §2.5 Q9, article-titles likely DON'T use hook-pool. If confirmed, Option γ is moot — just deprecate.

### Discovery-Recommendation: **Option β (deprecated_at tag + filter)**

Reasoning:

1. **No FK-orphan risk** — existing briefs' hookId references stay valid
2. **Audit trail** — future-Marcel sees what was deprecated, why
3. **Reversible** — wenn drama-hooks underperform, can re-enable generic pool
4. **Migration is single ALTER TABLE** — cheap
5. **pickHook filter is one-line change** — `WHERE deprecated_at IS NULL`

### 3.5 SEO/Social Mode-Switch Architecture (Marcel: Discovery evaluiert)

**Core problem (per Live-Test feedback):**
> "Spec 64.16 verbietet 'compelling'/'Drama'/'2026:' in SEO-Article-Titles. Das gilt nicht für Social-Hooks — die Nische erfordert genau diese Energie."

**Option α — projects.social_drama_allowed boolean toggle:**

```sql
ALTER TABLE projects ADD COLUMN social_drama_allowed BOOLEAN DEFAULT TRUE;
```

Pros: Single per-project toggle, Marcel can opt-out
Cons: Coarse-grained (project = all-or-nothing), doesn't map to "SEO vs Social" distinction directly

**Option β — Context-aware via outputTarget:**

```typescript
// In pickHook + brief-generator:
const dramaAllowed = brief.outputTargets.includes('social');
const hooks = await pickHook({
  projectId,
  formatType,
  language,
  dramaAllowed,  // NEW
});

// pickHook filters: WHERE drama_intensity IN ('subtle', dramaAllowed ? 'aggressive' : nothing)
```

Pros: No new toggle needed, signal already in brief
Cons: Requires `hook_templates.drama_intensity` column, all 30-40 new hooks need tagging

**Option γ — drama_intensity field on hook_templates:**

```sql
ALTER TABLE hook_templates 
  ADD COLUMN drama_intensity TEXT NOT NULL DEFAULT 'moderate'
  CHECK (drama_intensity IN ('subtle', 'moderate', 'aggressive'));
```

Combined with context-aware filter (Option β logic):
- `'subtle'`: SEO-safe, no drama-words (Spec 64.16 compliant)
- `'moderate'`: default, mild drama (number-driven, year-anchor)
- `'aggressive'`: full drama (RIP-style, "Will End It", "killed", "destroyed")

Filter logic in pickHook:
```typescript
// When outputTarget includes 'social': allow all intensities
// When outputTarget is 'article' only: allow 'subtle' only
const allowedIntensities = brief.outputTargets.includes('social')
  ? ['subtle', 'moderate', 'aggressive']
  : ['subtle'];
```

### Discovery-Recommendation: **Option γ (drama_intensity field + context-aware filter)**

Reasoning:

1. **Three-tier granularity** matches reality — not binary "SEO vs Social", actually 3 modes
2. **Per-hook taggable** — Marcel can fine-tune which hooks are too drama
3. **Future-proof** — if Spec 64.16 evolves, just retag hooks
4. **Single source of truth** — hook-pool itself knows its intensity, no project-level config drift
5. **Generic 60-hook pool naturally classifies as 'subtle'** — backfill on deprecation = mark as 'subtle' (NOT deprecated)
6. **Distribution-Layer ready** — different platforms may want different intensities (LinkedIn=subtle, TikTok=aggressive)

**Implication for §3.4:** Generic 60 hooks NOT deprecated — re-classified as `'subtle'` intensity. Available for SEO-mode use. Real "delete" only for hooks that are quality-bad (not pattern-bad).

### 3.6 LLM-Picker Context Extension (Marcel-Decision)

**Current state (per Spec 65.4):**

```typescript
// pickHook prompt sees:
- Available hooks (LRU-filtered pool)
- Format-type
- Language
```

**Extension target:**

```typescript
// pickHook prompt should see:
- Available hooks (LRU + drama-intensity filtered)
- Format-type
- Language
- Brief.topic (from generator's topic-derivation)
- Featured tool names (from formatConfig.featuredToolId / toolIds)
- Profession/lifeArea/stance variables (from hook-variables population)
```

**LLM prompt-shape:**

```typescript
const PICK_PROMPT = `
Pick the best hook für this carousel context.

Brief topic: "${brief.topic}"
Featured tools: ${tools.map(t => t.name).join(', ')}
${profession ? `Target profession: ${profession}` : ''}
${lifeArea ? `Target life-area: ${lifeArea}` : ''}

Available hooks (already filtered by drama-intensity for output-target):
${hooks.map((h, i) => `${i+1}. [${h.pattern}] — uses variables: ${Object.keys(h.variables).join(', ')}`).join('\n')}

Pick the index (1-${hooks.length}) of the hook that best matches:
- Topic-coherence (does the hook angle fit the brief?)
- Tool-fit (does the hook work with these specific tools?)
- Drama-pattern-match (is this hook's pattern strong for this format-type?)

Return JSON: {"selectedIndex": 1-${hooks.length}, "reasoning": "1 sentence"}
`;
```

**Cost-impact:** Haiku 4.5 + jsonMode + ~500 tokens output ≈ €0.005-0.008 per pick. Per Marcel's estimate +~€0.005 confirmed in range.

| Risk | Severity | Mitigation |

| Drama-hooks erzeugen sich-überlappende variants (5 RIP-hooks pro language too similar) | Medium | Seed-script ensures diversity via 5-pattern split; manual review at seed-time |

### Spec deviations from §3-§10

1. **Tier-comparison adapted to single-tool anchored form.** Spec §3.1 sketch had `{toolA}: Schlecht. {toolB}: Gut. {toolC}: GENIAL.` — that requires multi-tool variables. story_arc_clickbait and opinion_recommendation are single-tool by config shape. Reshaped seed to `Schlechte {profession}: viele. Gute {profession}: wenige. {profession} mit {tool}: unschlagbar.` and `Gratis: nicht genug. Günstig: zu wenig. {tool}: alles.` — same pattern energy, no generator surgery. Multi-tool `{toolA/B/C}` deferred to V1.7+.
2. **`briefTopic` is derived per-generator.** Spec §3.6 sketched `brief.topic` as if it existed pre-`buildBriefText` — it doesn't (`topicTitle` is LLM-generated downstream). Each generator now builds a 1-line topic-summary string from its `config + tools + profession/lifeArea/stance`.
3. **`{established}` filter is post-fetch, not SQL pre-filter.** Pure-SQL filter would require `jsonb @> '["established"]'` — over-engineered for a per-call check. Picker now over-fetches 20 candidates, then `pool.filter((h) => !h.variables.includes("established")).slice(0, 10)`. The SQL `dramaIntensities` pre-filter still does the heavy lifting; post-filter only narrows by `{established}` availability.
4. **`competitorTool` lives on Family-B configSchema, not at definition level.** Spec §3.3 was silent on storage location. Putting it on `format_config` jsonb avoids a DB-migration on `recurring_content_definitions` and keeps the field discoverable via the existing per-format Zod-schema validation. Settings-UI V1.6 uses the JSON-editor; a dedicated custom-form widget is deferred to V1.7+.
5. **65.4 existing test fixture needed widening.** Adding `outputTargets` as required on `PickHookInput` broke existing `pick-hook.test.ts` calls. Added `outputTargets: { article: false, social: true }` to all 5 existing test sites; the existing `HookTemplate` literal in `buildHookPickerUserMessage` test needed `dramaIntensity: "subtle"` to match the widened type.
