# Spec 60.6 — Social Template Selection, UI Picker & Pipeline Auto-Trigger

**Date:** 2026-05-19
**Theme:** 60 — Social System Completion
**Prerequisite:** 60.5 done
**Estimated effort:** ~1.5 days

---

## TL;DR

Three parallel workstreams, all wiring existing infrastructure that was never
connected:

1. **UI Picker** — `ArticleSocialTab.vue` calls the two existing backend endpoints
   (`/all-templates`, `/template-suggestions`) and renders a template picker with
   eligibility state, LLM suggestions, and a generate button per template.

2. **Pipeline Auto-Trigger** — `BlogPipeline.afterComplete()` already fires when
   `socialAutoRenderLocales` is set, but picks no template. Extend it to read
   the top-1 LLM suggestion from `article_discovery.suggestedTemplates` and pass
   `templateKey` explicitly to the render job.

3. **Suggestion Tracking** — Four new columns on `social_posts` to close the
   analytics loop: `suggestedTemplate`, `suggestionConfidence`, `suggestionReason`,
   `userOverride`.

## Section A — Current State (from Discovery)

### What exists and works
- `GET /articles/:articleId/all-templates` → all templates + per-template
  eligibility result + existing render status + slide URLs
- `GET /articles/:articleId/template-suggestions` → LLM suggestions from
  `article_discovery.suggestedTemplates` paired with current render statuses
- `templateRegistry.listEligibleFor(article, discovery)` → typed eligibility results
- `BlogPipeline.afterComplete()` → auto-enqueue hook (fires when
  `projects.socialAutoRenderLocales` is set)
- `POST /articles/:articleId/generate-templates` → client-driven multi-template
  render with explicit `templateKeys[]`

### What is missing
- `ArticleSocialTab.vue` calls neither endpoint — no picker UI
- `afterComplete()` sends no `templateKey` — pipeline falls back to default
  comparison routing only
- `social_posts` has no suggestion tracking columns
- No analytics on LLM suggestion accuracy

### C.2 Extend `BlogPipeline.afterComplete()` — top-1 suggestion routing

**File:** `packages/pipelines/src/article/blog/pipeline.ts`

Current `afterComplete()` enqueues `article:social-image` without `templateKey`.

New logic:

```typescript
// packages/pipelines/src/article/blog/pipeline.ts

async afterComplete(ctx: PipelineContext) {
  const { projectId, articleId } = ctx;

  const project = await db.query.projects.findFirst({
    where: eq(projects.id, projectId),
  });

  if (!project?.socialAutoRenderLocales) return;

  // Fetch top-1 LLM suggestion from discovery
  const discovery = await db.query.articleDiscovery.findFirst({
    where: eq(articleDiscovery.articleId, articleId),
  });

  const suggestions: TemplateSuggestion[] =
    discovery?.suggestedTemplates ?? [];

  const top1 = suggestions
    .filter(s => s.confidence >= 0.6)   // min confidence threshold
    .sort((a, b) => b.confidence - a.confidence)[0];

  const locales = project.socialAutoRenderLocales === 'one'
    ? ['de']
    : ['de', 'en'];

  for (const locale of locales) {
    await enqueueSocialRenderJob({
      articleId,
      projectId,
      locale,
      theme: 'dark',
      templateKey: top1?.templateKey ?? null,  // null = pipeline decides
      suggestionMeta: top1
        ? {
            suggestedTemplate: top1.templateKey,
            suggestionConfidence: top1.confidence,
            suggestionReason: top1.justification,
          }
        : undefined,
    });
  }
}
```

### D.3 Computed

```typescript
computed: {
  // Sorted: suggested first, then eligible, then ineligible
  sortedTemplates(): EligibilityResult[] {
    const suggestionKeys = new Set(this.suggestions.map(s => s.templateKey));
    return [...this.allTemplates].sort((a, b) => {
      const aIsSuggested = suggestionKeys.has(a.templateKey) ? 1 : 0;
      const bIsSuggested = suggestionKeys.has(b.templateKey) ? 1 : 0;
      if (aIsSuggested !== bIsSuggested) return bIsSuggested - aIsSuggested;
      if (a.eligible !== b.eligible) return a.eligible ? -1 : 1;
      return 0;
    });
  },

  topSuggestion(): TemplateSuggestion | null {
    return this.suggestions
      .sort((a, b) => b.confidence - a.confidence)[0] ?? null;
  },

  canGenerate(): boolean {
    return !!this.selectedTemplateKey &&
      this.allTemplates.find(t => t.templateKey === this.selectedTemplateKey)
        ?.eligible === true;
  },
}
```

### D.5 Key UI rules

**Suggestion block:**
- Only shown when `topSuggestion` exists with `confidence >= 0.6`
- Shows template label, confidence as percentage, justification text (truncated
  to 80 chars)
- "Generieren" button in accent color to distinguish from regular generate buttons
- Clicking auto-sets `selectedTemplateKey` + calls generate

**Template rows:**
- Ineligible templates shown but disabled (grayed out) with `reason` tooltip
- Each eligible template has its own "Generieren" button — no global submit
- No radio/checkbox selection needed — each row generates independently
- Template label from `template.label[locale]`

**Already-generated section:**
- Shows `social_posts` rows for this article ordered by `createdAt DESC`
- Thumbnail from `content.slides[0].url` (first slide PNG)
- Re-render button → `POST /social-posts/:id/re-render`

**Locale + Theme toggles:**
- `QBtnToggle` for both
- Applied to all "Generieren" actions on the page
- Defaults: locale = article.locale, theme = 'dark'

### D.6 Generate action

```typescript
methods: {
  async generateTemplate(templateKey: string): Promise<void> {
    this.generating = true;
    try {
      const suggestion = this.suggestions.find(
        s => s.templateKey === templateKey
      );
      await apiPost(
        `/articles/${this.articleId}/generate-templates`,
        {
          templateKeys: [templateKey],
          locale: this.selectedLocale,
          theme: this.selectedTheme,
          suggestionMeta: suggestion
            ? {
                suggestedTemplate: suggestion.templateKey,
                suggestionConfidence: suggestion.confidence,
                suggestionReason: suggestion.justification,
              }
            : undefined,
        }
      );
      // Optimistic: reload after short delay
      setTimeout(() => this.reloadGeneratedPosts(), 3000);
    } finally {
      this.generating = false;
    }
  },
}
```

## Section H — Patterns Established by 60.6

**(96) LLM template suggestions live in `article_discovery.suggestedTemplates`
JSONB, not in `social_posts`. When wiring suggestions to the UI, always fetch
from `/template-suggestions` endpoint — never re-query `article_discovery`
directly from the frontend.**

**(97) Confidence threshold for auto-trigger: 0.6. Below this, the pipeline falls
back to `templateKey: null` (existing auto-routing). Never auto-trigger with
a low-confidence suggestion — it's worse than the deterministic fallback.**

**(98) `userOverride` semantics: true = user explicitly chose a template different
from the LLM suggestion. False covers both "no suggestion existed" and "user
followed the suggestion". Only set true when both `suggestedTemplate` is set AND
`templateKey !== suggestedTemplate`.**

## Deviations from Original Spec

### D.1 Suggestion columns on `template_renders`, not `social_posts`

Spec B.1 said to add `suggested_template`, `suggestion_confidence`, `suggestion_reason`,
`user_override` to `social_posts`. After discovering that `POST /generate-templates`
writes to `template_renders` (not `social_posts`), the columns were added there instead.
Migration: `0063_suggestion_tracking_template_renders.sql`.

### D.2 `suggestionReason` always null in pipeline auto-trigger path

The spec pseudocode referenced `top1.justification` in `afterComplete()`, but
`ArticleDiscoverySuggestedTemplates` (the actual DB type) is
`Array<{ templateKey: string; confidence: number }>` — no `justification` field.
`suggestionReason` is only populated from the UI picker path (where the client can
optionally include it). The pipeline auto-trigger path leaves it null.

## Discovered During Implementation

- **`bridge()` override for pipeline-level-to-step injection**: When a value is known
  at pipeline-input time but must reach a step that is downstream of other steps (not
  step 1), override `Pipeline.bridge()` to inject it into the step's input. Add the
  field as an optional Zod field on the intermediate output schema so Zod won't reject
  it when the intermediate step doesn't set it. See `SocialImagePipeline.bridge()` and
  `templateKeyOverride` on `GenerateCaptionOutputSchema`.

- **`isOverrideTemplateKey` guard required when templateKey is `string`**: When the
  template key comes from user input or pipeline input (typed as `string`, not a literal
  union), call `isOverrideTemplateKey(key)` before `getOverrideSchema(key)`. Without the
  guard TypeScript rejects the call at compile time. See `RenderSlidesStep.execute()`.
