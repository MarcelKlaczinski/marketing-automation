# Spec 11.5: Resend Adapter

**Phase:** 2 (Cold-Start for KI-Wissensraum) — small refactor spec
**Estimated Effort:** ½ day
**Dependencies:** Spec 00, Spec 01, Spec 03 (cost tracker), Spec 04 (magic link auth — we replace its email.ts), Spec 11 (anthropic adapter — pattern reference)
**Status:** Ready for implementation
**Recommended Model:** Sonnet 4.6

---

## Goal

Refactor the raw `fetch()` call to Resend's API in `apps/api/src/lib/email.ts` (a documented Phase-1 deviation) into a proper typed adapter at `packages/adapters/resend/`. The adapter:

1. Follows the Spec 11 (Anthropic) pattern: typed entry points, cost-tracker integration, project-scoped operations
2. Uses Resend's official Node SDK instead of raw fetch
3. Handles the dev-fallback case (no `RESEND_API_KEY` set → log to console) cleanly
4. Tracks email sending in `cost_logs` (Resend has `costServiceEnum: "resend"` already)
5. Exposes a typed `sendEmail()` and a specialized `sendMagicLinkEmail()` that consumes the generic API

This is a **small refactor**, but it's the right time to do it: before Phase 2 grows more raw-fetch debt.

## Non-Goals

- No React Email integration (Resend supports `<Email>` components — we use plain HTML strings for MVP, switch later)
- No bounce/complaint webhook handling (Phase 4 if email volume grows)
- No batch sending API (we send 1-3 emails/day for magic links)
- No template management (templates are TypeScript functions returning HTML — simpler)
- No multi-recipient (`to: string[]`) — magic links go to one person at a time
- No tenant-scoped sender domains (all emails come from one configured domain for MVP; SaaS pivot adds per-tenant)
- No `from` per-call override — single configured sender, plus the dev-mode fallback

## User-Facing Behavior

After this spec, `apps/api/src/routes/auth.ts` uses the typed adapter:

```typescript
import { resend } from "@marketing-auto/adapter-resend";

await resend.sendMagicLinkEmail({
  to: email,
  verifyUrl,
  expiresInMinutes: 15,
  // optional: projectId for cost-log attribution. For platform-wide auth emails:
  // omit projectId — adapter logs against a synthetic "platform" pseudo-project (see Decision 4)
});
```

For non-magic-link transactional emails (alerts, briefings later), the generic API:

```typescript
import { resend } from "@marketing-auto/adapter-resend";

await resend.sendEmail({
  projectId: "...",                    // for cost attribution
  operation: "cost-alert",
  to: "marcel@example.com",
  subject: "Daily cost report — KI-Wissensraum",
  html: "<p>...</p>",
  text: "...",                         // optional plain-text fallback
  estimatedCostEur: 0.0001,
});
```

The dev-mode fallback (no `RESEND_API_KEY`) keeps working: link logged to console, no cost tracked.

export type SendEmailInput = {
  /**
   * Project to attribute the cost to. For platform-wide emails (auth, system notifications)
   * use `null` — adapter falls back to `PLATFORM_PROJECT_ID`. See Decision 4.

  to: string;

  /** Subject line. */
  subject: string;

  /** HTML body. */
  html: string;

  /** Optional plain-text fallback body. Strongly recommended for deliverability. */
  text?: string;

  /** Optional reply-to address. Falls back to from if not set. */
  replyTo?: string;

  /** Pre-flight cost estimate in EUR (negligible — Resend free tier). */
  estimatedCostEur?: number;
};

export type SendEmailResult = {
  /** Resend's email ID, returned in their dashboard for tracking. */
  emailId: string;
  /** Whether the call actually went to Resend (false in dev-fallback mode). */
  delivered: boolean;

  to: string;
  verifyUrl: string;
  expiresInMinutes: number;
  /** Optional: attribute to a project. Defaults to platform-wide. */
  projectId?: string;
};

export class ResendError extends Error {
  constructor(message: string, public readonly cause?: unknown) {
    super(message);
    this.name = "ResendError";
  }

### The Adapter

`packages/adapters/resend/src/client.ts`:

```typescript
import { Resend } from "resend";
import { getEnv, createLogger } from "@marketing-auto/shared";
import { track, resendCostEur } from "@marketing-auto/cost-tracker";
import {
  type SendEmailInput,
  type SendEmailResult,
  type SendMagicLinkInput,
  ResendError,
} from "./types.ts";

const log = createLogger("resend");

let _client: Resend | null = null;
function getClient(): Resend | null {
  if (_client) return _client;
  const env = getEnv();
  if (!env.RESEND_API_KEY) {
    return null;  // dev fallback mode
  }
  _client = new Resend(env.RESEND_API_KEY);
  return _client;
}

/**
 * Synthetic project ID for platform-wide emails (auth, system alerts).
 * We need a UUID to satisfy the cost_logs.project_id FK.
 *
 * The "platform" project is created by a one-time seed (see Implementation Order step 7).
 * This UUID is stable; the seed inserts a row with this exact ID into `projects`.
 */
export const PLATFORM_PROJECT_ID = "00000000-0000-0000-0000-000000000001";

/**
 * Generic transactional send. All emails — auth, alerts, future briefings — go through here.
 */
export async function sendEmail(input: SendEmailInput): Promise<SendEmailResult> {
  const env = getEnv();
  const client = getClient();

  // Dev-fallback: no API key → log and return synthetic result. NO cost tracked.
  if (!client || !env.RESEND_FROM_EMAIL) {
    log.warn(
      { to: input.to, subject: input.subject, operation: input.operation },
      "Resend not configured — email logged to console (dev fallback)",
    );
    console.log(`\n📧 Email (would-be-sent) — ${input.subject}\n   To: ${input.to}\n   ${input.html.slice(0, 200)}${input.html.length > 200 ? "…" : ""}\n`);
    return { emailId: "dev-fallback", delivered: false };
  }

  const projectId = input.projectId ?? PLATFORM_PROJECT_ID;
  const fromEmail = env.RESEND_FROM_EMAIL;

  log.debug({
    projectId,
    operation: input.operation,
    to: input.to,
    subjectLen: input.subject.length,
    htmlLen: input.html.length,
  }, "Sending email via Resend");

  const result = await track({
    projectId,
    service: "resend",
    operation: input.operation,
    estimatedCostEur: input.estimatedCostEur ?? 0.0001,
    fn: async () => {
      const sendInput = {
        from: fromEmail,
        to: input.to,
        subject: input.subject,
        html: input.html,
        ...(input.text && { text: input.text }),
        ...(input.replyTo && { replyTo: input.replyTo }),
      };

      const { data, error } = await client.emails.send(sendInput);

      if (error) {
        // Resend SDK returns error as object on failure; throw for cost-tracker + BullMQ retry
        throw new ResendError(
          `Resend send failed: ${error.message ?? JSON.stringify(error)}`,
          error,
        );
      }
      if (!data) {
        throw new ResendError("Resend returned no data and no error");
      }
      return data;
    },
    computeCostEur: () => resendCostEur({ count: 1 }),
    metadata: (data) => ({
      emailId: data.id,
      to: input.to,
      subject: input.subject,
    }),
  });

  log.info(
    { projectId, operation: input.operation, emailId: result.id, to: input.to },
    "Email sent",
  );

  return { emailId: result.id, delivered: true };
}

/**
 * Magic-link login email. Wraps sendEmail with auth-specific copy.
 * Replaces the raw fetch() implementation in apps/api/src/lib/email.ts.
 */
export async function sendMagicLinkEmail(input: SendMagicLinkInput): Promise<SendEmailResult> {
  const html = `
    <div style="font-family:-apple-system,sans-serif;max-width:480px;margin:24px auto;color:#1a1a1a;">
      <h1 style="font-size:18px;margin:0 0 16px;">Sign in to Marketing Automation</h1>
      <p style="font-size:14px;line-height:1.5;margin:0 0 24px;">
        Click the button below to sign in. This link expires in ${input.expiresInMinutes} minutes
        and can only be used once.
      </p>
      <a href="${input.verifyUrl}"
         style="display:inline-block;background:#0066ff;color:#fff;padding:12px 24px;
                border-radius:6px;text-decoration:none;font-weight:500;">
        Sign in
      </a>
      <p style="font-size:12px;color:#666;margin:24px 0 0;line-height:1.5;">
        If you didn't request this, you can safely ignore this email.<br>
        Or copy this link: <span style="word-break:break-all;">${input.verifyUrl}</span>
      </p>
    </div>
  `.trim();

  const text = [
    "Sign in to Marketing Automation",
    "",
    input.verifyUrl,
    "",
    `This link expires in ${input.expiresInMinutes} minutes.`,
  ].join("\n");

  return sendEmail({
    projectId: input.projectId ?? null,
    operation: "magic-link",
    to: input.to,
    subject: "Sign in to Marketing Automation",
    html,
    text,
  });
}
```

### CLAUDE.md

`packages/adapters/resend/CLAUDE.md`:

```markdown
# Resend Adapter

Transactional email via Resend. Replaces the raw fetch() implementation that lived in
apps/api/src/lib/email.ts during Phase 1.

## Hard Rules

- ALL email sending goes through this adapter — never `resend` (the SDK) directly
- ALL calls require `operation` for cost-log attribution
- For platform-wide emails (auth, system notifications), pass `projectId: null` — the adapter
  attributes to PLATFORM_PROJECT_ID synthetic project
- Dev mode (no `RESEND_API_KEY`): adapter logs the email content to console and returns
  `delivered: false` — NO cost tracked, NO error thrown. Tests can rely on this.

## Common Mistakes

- DO NOT pass `to: string[]` — multi-recipient is not supported. If you need broadcast,
  loop and call sendEmail() per recipient
- DO NOT skip the `text` fallback — Resend's deliverability scoring penalizes HTML-only
- DO NOT use `from: "..."` per-call — sender domain is configured globally via RESEND_FROM_EMAIL.
  Per-tenant senders are a SaaS-era concern.
- DO NOT call sendEmail() from request-handling code without queueing — Resend's API can take
  500ms-2s and you'll block the response. Use BullMQ for transactional flows.
  (Magic-link is the exception: it's already in the auth route which can wait synchronously.)
```

/**
 * One-time seed: creates the synthetic "platform" project that owns
 * cost_logs from non-tenant operations (auth emails, system alerts).

 * Idempotent — safe to run multiple times.

const [existing] = await db
  .select({ id: projects.id })
  .from(projects)
  .where(eq(projects.id, PLATFORM_PROJECT_ID))
  .limit(1);

  console.log("ℹ️  Platform project already exists");
  process.exit(0);

  id: PLATFORM_PROJECT_ID,

## Open Questions / Decisions Made

**Decision 1: Resend SDK version `^6.12.2`.**
Verified current version on npm. Major version 6 is stable, TS-first, ESM-native — fits Bun.

**Decision 2: Dev-fallback returns success, not error.**
If we threw, the auth flow would break in dev. The fallback prints the magic link to console (you copy-paste it into the browser) — exactly what Spec 04 already does. Adapter preserves that behavior, just relocated.

**Decision 3: No cost-tracker call in dev fallback.**
Cost tracker requires a `projectId` FK and persists rows. In dev fallback we want zero side effects. Calling `track()` only happens after the API-key check passes.

**Decision 4: Synthetic `PLATFORM_PROJECT_ID` for non-tenant emails.**
Cost-logs has `project_id` as a non-nullable FK. Auth emails are platform-wide, not tenant-attributable. Three options considered:
- Make `project_id` nullable → requires migration + breaks the multi-tenant invariant
- Pick a "real" tenant arbitrarily → wrong attribution, confuses cost dashboards
- **Synthetic platform project** with stable UUID → clean, queryable ("show me all platform spend"), trivial migration (just a seed)
  We chose the synthetic project. UUID `00000000-0000-0000-0000-000000000001` is recognizable as not-real.

**Decision 5: No batch-send method.**
Resend supports `emails.batch.send([...])` for up to 100 emails. We don't need it for MVP. If we ever do (e.g., bulk-notify subscribers), add `sendBatch()` then.

**Decision 6: HTML strings, not React Email components.**
React Email is great but adds a build step (TSX → HTML). For our 1-2 email templates (magic link, future cost alerts), inline HTML strings are simpler and equally maintainable.

**Decision 7: `projectId: null` API explicitness.**
Forcing the caller to choose between a real project ID and `null` (instead of just omitting) makes the platform-attribution case visible in code. Less footgun than defaulting to platform silently.

**Decision 8: `apps/api/src/lib/email.ts` becomes a shim, not removed.**
Keeping the file with the old export name means `auth.ts` doesn't change. Easier rollback if something breaks. The shim is two lines and zero overhead.

**Decision 9: Estimated cost defaults to €0.0001.**
Resend's free tier is 3000/month, paid tier is ~$0.0001/email. Below cost-tracker's precision threshold but non-zero so cost-log queries don't filter it out.
