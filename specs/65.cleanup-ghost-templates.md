## 3. Architecture Decisions

### 3.1 Two Categories: UnsupportedTemplateKey vs DeprecatedTemplateKey

**Current state (per 65.7-followup):**

`UnsupportedTemplateKey = "news-slide" | "concept-explainer-deck" | "price-comparison"`

These are templates that **were never shipped + likely never will be in V1 scope**.

**Ghost-templates from V1-cut variants:**
- `opinion-recommendation-dramatic`
- `opinion-recommendation-minimal`
- Possibly: `story-arc-clickbait-dramatic`, `story-arc-clickbait-minimal`, `lifestyle-listicle-dramatic`, `lifestyle-listicle-minimal`

These were **planned variants that V1 collapsed into single template + config-knob**. Semantically different from "never shipped":

- `UnsupportedTemplateKey` = "doesn't exist, future maybe"
- `DeprecatedTemplateKey` = "was planned, V1-cut, ships as config-knob now"

### Discovery-Recommendation: **Separate `DeprecatedTemplateKey` union from `UnsupportedTemplateKey`**

```typescript
// packages/social/src/templates/types.ts

/**
 * Templates planned in Spec 65.7 but V1-cut.
 * These format-types now ship as single templates with config-knobs
 * (e.g. opinion-recommendation has toneIntensity: 'dramatic' | 'balanced' | 'minimal').
 * 
 * Kept in TemplateKey union for:
 * - Audit trail (planned variants visible in code)
 * - Backward-compat (old test seeds, possible old DB rows don't break compile)
 * - Future-cut signal (if engagement data justifies splitting, just re-implement)
 * 
 * NEVER dispatch these — worker throws Unknown templateKey on receipt.
 */
type DeprecatedTemplateKey =
  /** @deprecated V1-cut: ships as opinion-recommendation + toneIntensity='dramatic' config */
  | "opinion-recommendation-dramatic"
  /** @deprecated V1-cut: ships as opinion-recommendation + toneIntensity='minimal' config */
  | "opinion-recommendation-minimal"
  // ... others surfaced by audit
  ;

// Existing:
type UnsupportedTemplateKey = "news-slide" | "concept-explainer-deck" | "price-comparison";

// New: clean union of templates that ARE shippable
export type ShippedTemplateKey = Exclude<TemplateKey, DeprecatedTemplateKey | UnsupportedTemplateKey>;

// Exhaustivity now covers all 4 categories (Family-A, Family-B, Unsupported, Deprecated)
type _AssertNever<T extends never> = T;
const _exhaustivityCheck = null as unknown as _AssertNever<
  Exclude<TemplateKey, FamilyATemplateKey | FamilyBTemplateKey | UnsupportedTemplateKey | DeprecatedTemplateKey>
>;
void _exhaustivityCheck;
```

Reasoning:

1. **Semantic clarity** — "deprecated" ≠ "unsupported"; future-Marcel grokt the difference
2. **JSDoc @deprecated triggers IDE strikethrough** + deprecation-message tooltip
3. **Worker-dispatch unchanged** — Memory D30's exhaustivity-guard pattern just gains 4th category
4. **Type-level prevention test** can use `ShippedTemplateKey` as canonical "what's actually shippable"

### 3.2 Type-Level Prevention Test (Marcel-Decision)

**Goal:** Assert that bootstrap-registered templates == ShippedTemplateKey union. Compile-time guard catches drift at PR-time.

**Implementation:**

```typescript
// packages/social/test/templates/template-registry-coverage.test.ts
import { templateRegistry } from "../../src/templates/registry";
import { bootstrapTemplates } from "../../src/templates/bootstrap";
import type { ShippedTemplateKey } from "../../src/templates/types";

describe("template-registry coverage", () => {
  beforeAll(() => {
    bootstrapTemplates();
  });
  
  test("bootstrap-registered template-keys cover all ShippedTemplateKey union values", () => {
    const registered = new Set(templateRegistry.list().map(t => t.id));
    
    // Each ShippedTemplateKey value must be registered
    // (compile-time + runtime cross-check)
    const shippedKeys: ShippedTemplateKey[] = [
      'comparison-grid-3', 'comparison-grid-5',
      'head-to-head-vs', 'head-to-head-deep-dive',
      'story-arc-clickbait', 'lifestyle-listicle', 'opinion-recommendation',
      // + audit-confirmed pre-65.7 templates
    ];
    
    for (const key of shippedKeys) {
      expect(registered.has(key)).toBe(true);
    }
    
    // No deprecated keys in registry
    expect(registered.has('opinion-recommendation-dramatic' as any)).toBe(false);
    expect(registered.has('opinion-recommendation-minimal' as any)).toBe(false);
    // ... others
    
    // Exact match: bootstrap-set == ShippedTemplateKey set
    expect(registered.size).toBe(shippedKeys.length);
  });
  
  test("DeprecatedTemplateKey marker types stay in union for backward-compat", () => {
    // Type-level only — this test just affirms the convention via const-satisfies
    const ghostsStillInUnion: TemplateKey[] = [
      'opinion-recommendation-dramatic',
      'opinion-recommendation-minimal',
    ];
    expect(ghostsStillInUnion).toBeDefined();
  });
});
```

**Compile-time exhaustivity** (already established per 65.7-followup) automatically catches additions to TemplateKey union that aren't in one of the 4 categories.
