## Goal

Complete Phase A by extracting the implicit "gap-type → article-type" routing logic out of `apps/api/src/routes/projects.ts` into a dedicated **TopicRoutingPolicy** (pure functions), making the existing `/generate` and `/automate` routes consume **TopicBriefs as the Single Source of Truth**, and resolving four critical tech debts identified in the Ist-Zustand-Analyse:

1. **Tech Debt #1** — Gap-detection ignores `source='generated'` articles → fixed (filter removed)
2. **Tech Debt #5** — Implicit gap-type → article-type coupling in route handlers → fixed (policy extracted)
3. **Tech Debt #6** — `/suggest` silent side-effect on `clusters.satelliteKeywords` → fixed (side-effect removed; data lives in brief)
4. **Tech Debt #7** — Fragile `cornerstoneKeyword` matching in `TopicIntakeStep` → fixed (brief-sourced as primary, cluster-match as legacy fallback)

Spec 54.3 delivers:

1. A **TopicRoutingPolicy module** (`packages/pipelines/src/routing/`) with pure functions that take a `TopicBrief` and return a `RoutingDecision` describing what to do (create article, create cornerstone_spec, trigger localize pipeline, trigger refresh).
2. A **route refactor**: `/generate` and `/automate` load the corresponding TopicBrief, hand it to the policy, execute the decision in a single transaction, mark the brief as `routed`, and return responses that include the new `briefId` field.
3. **`TopicIntakeStep` refactor**: prefer brief-sourced primaryKeyword + satelliteKeywords; if no brief is linked (legacy path), fall back to current matching logic with a warning log.
4. **`/suggest` side-effect removal**: response shape gains `clusterUpdated: false` (always false after this spec); discovered keywords are written to `topic_briefs.secondary_keywords` instead of `clusters.satellite_keywords`.
5. **`detect-content-gaps.ts` filter removal**: the `source='imported'` filter is dropped; all articles (imported + generated) count toward cluster size and intent coverage.
6. **`drizzle-orm` direct imports**: every file touched by 54.3 has its imports normalized to `@marketing-auto/db`.

After this spec lands:
- Phase A is complete. Foundations are in place for Phase B (Trend Discovery)
- TopicRoutingPolicy is the single decision point for "what to generate from this brief"
- API responses include `briefId` so future UI can navigate brief ↔ article
- Gap-detection sees the full content corpus (no source filter)
- `/suggest` is idempotent — calling it twice produces identical state

## What this is NOT

- Not building Trend Discovery sources (54.4)
- Not building Trend scoring or synthesis (54.5)
- Not building UI for the new flow (54.6 — minimal UI; 54.9 — full redesign)
- Not removing `content_gaps` table (dual-write continues; deprecation lives in 54.9+)
- Not adding new automation rules (Phase 2 future)
- Not refactoring Cold-Start cluster creation
- Not implementing the `cluster_action='create_new'` path beyond a stub — Cluster Creator is 54.7. The policy may emit a `RoutingDecision` of type `create_cluster`, but in 54.3 that decision throws "Not implemented in 54.3" if reached. Realistically gap-sourced briefs never request `create_new` (the existing flow only appends to existing clusters), so this path stays cold until 54.7.
- Not breaking existing UI: `GapsPanel.vue` continues to work with `briefId` available as an optional new field
- Not removing `clusters.satellite_keywords` column (other code still reads it for now; cleanup is a future task)

## Architecture

### Why pure functions, not a class

Per user direction (1b): the policy is pure functions, not a class. Rationale matches the project's existing style (`loadActiveConfig`, `resolveIntentTaxonomy`, `mapGapToBrief` are all pure exports). A class would add ceremony for no benefit — there is no shared state across decisions, no injected dependencies that vary at runtime. Pure functions test trivially without mocking.

```typescript
// What we build:
export function route(brief: TopicBrief): RoutingDecision { ... }
export function executeDecision(
  decision: RoutingDecision,
  brief: TopicBrief,
  tx: Transaction,
): Promise<RoutingResult> { ... }

// What we don't build:
class TopicRoutingPolicy {
  constructor(private db: Database, private queue: Queue) {}
  async route(brief: TopicBrief): Promise<RoutingResult> { ... }
}
```

### Decision separated from execution

A `RoutingDecision` is a plain data structure describing **what** to do. `executeDecision` performs it inside a transaction. This separation matters for three reasons:

1. **Testability**: decisions are pure, can be unit-tested per gap-type without DB
2. **Auditability**: a decision can be logged before execution, useful for debugging
3. **Future automation**: Phase 2 rule-based automation can decide, defer, batch, or override decisions before execution

```typescript
type RoutingDecision =
  | { kind: "create_article"; intentType: string; clusterId: string; mode: GenerationMode }
  | { kind: "create_cornerstone_spec"; clusterId: string; mode: "pillar" }
  | { kind: "create_translation"; sourceArticleId: string; targetLocale: "de" | "en" }
  | { kind: "refresh_article"; targetArticleId: string }
  | { kind: "create_cluster"; pillarHint: string | null }  // STUB in 54.3
  | { kind: "skip"; reason: string };                       // safety net
```

### The brief is the Single Source of Truth

Per the (4a) and (5c) decisions:
- `/suggest` writes discovered keywords to `topic_briefs.secondary_keywords` (NOT `clusters.satellite_keywords` anymore)
- `TopicIntakeStep` reads keywords from the brief first, then falls back to cluster lookup for legacy articles

This is the most important behavior change in 54.3. To make it work without breaking existing pipelines:

```typescript
// In TopicIntakeStep, the resolution becomes:
async function resolveKeywords(article: Article): Promise<KeywordContext> {
  // 1. Find the brief linked to this article (via articleId in brief or
  //    via gap_id → article.gap relationship)
  const brief = await findBriefForArticle(article.id);

  if (brief) {
    // PRIMARY PATH (post-54.3): brief is the source
    log.debug({ articleId: article.id, briefId: brief.id }, "intake: brief-sourced");
    return {
      primaryKeyword: brief.primaryKeyword ?? article.cornerstoneKeyword,
      satelliteKeywords: brief.secondaryKeywords ?? [],
      source: "brief",
    };
  }

  // FALLBACK PATH (legacy articles created before 54.3): match against cluster
  log.warn({ articleId: article.id }, "intake: no brief linked, using legacy cluster match");
  const matched = matchCornerstoneKeywordInCluster(
    article.cornerstoneKeyword,
    article.cluster.satelliteKeywords,
  );
  return {
    primaryKeyword: article.cornerstoneKeyword,
    satelliteKeywords: matched?.keywords ?? [],
    source: "cluster_legacy",
  };
}
```

Articles created after 54.3 always have a linked brief (gap-detection creates one; manual article creation will too, see Section "Brief-to-Article Link" below). Legacy articles fall back gracefully.

### Brief-to-Article Link

Currently, the brief↔article relationship is indirect: `topic_briefs.gap_id → content_gaps.id` and the article is found by matching gap metadata. After 54.3, the link becomes direct: when an article is created from a brief, the brief is updated with the new `article_id`.

Two new fields are added to `topic_briefs`:

```sql
ALTER TABLE topic_briefs
  ADD COLUMN routed_article_id UUID REFERENCES articles(id) ON DELETE SET NULL,
  ADD COLUMN routed_cornerstone_spec_id UUID REFERENCES cornerstone_specs(id) ON DELETE SET NULL;

CREATE INDEX topic_briefs_routed_article_idx
  ON topic_briefs(routed_article_id) WHERE routed_article_id IS NOT NULL;
```

When `executeDecision` runs:
- For `create_article`: insert article, then update brief with `routed_article_id` + `approval_status='routed'`
- For `create_cornerstone_spec`: insert spec, then update brief with `routed_cornerstone_spec_id` + `approval_status='routed'`
- For `create_translation`: insert article (the EN/DE sibling), update brief with `routed_article_id` + `approval_status='routed'`

All in one transaction. The unique partial index on `(gap_id)` for non-terminal statuses from 54.1 still holds, because `routed` is in the non-terminal set (see 54.1 Decision 7).

### `/suggest` becomes idempotent

Current behavior (Tech Debt #6): `/suggest` calls DataForSEO, writes results to BOTH `content_gaps.metadata.discoveredKeywords` AND `clusters.satellite_keywords`. The cluster write is the side-effect that breaks idempotency.

After 54.3:
- `/suggest` calls DataForSEO if (and only if) the brief has no `secondary_keywords` yet
- Writes results to `topic_briefs.secondary_keywords`
- Does NOT touch `clusters.satellite_keywords`
- Response includes `clusterUpdated: false` (forever — kept for backward compat shape)
- Calling `/suggest` twice for the same brief is now a no-op on the second call

Existing `clusters.satellite_keywords` data is preserved (no migration needed). New `/suggest` calls just stop adding to it. Over time, the cluster-keyword column becomes a fossil; we'll decide whether to drop it after 54.9 surveys the consumer landscape.

### Gap-Detection sees all articles

Per user direction (3a): the `eq(articles.source, "imported")` filter is removed entirely. Both imported and generated articles count toward:
- Cluster size (`cluster_too_small` if total < 3)
- Intent coverage (`missing_spoke_type` based on intents present across all articles)
- Translation pairing (`missing_translation` based on `translationKey` across all articles)
- Hub presence (`missing_hub` based on `clusterRole='hub'` across all articles)

Side effect: re-running gap-detection on a project that recently generated articles via the pipeline will see those articles. This is the desired correctness fix. Risk: if a generated article was misclassified (wrong `intentType`), it influences gap-detection. That risk pre-exists (the article would be wrong on the site too) and is not a new failure mode.

### Response shape additions

Per user direction (Approach b), routes gain a `briefId` field so UI can navigate brief ↔ article. The additions are non-breaking:

```
POST /api/projects/:slug/content-gaps/:id/suggest
  Before: { suggestedTitle, suggestedSlug, ... }
  After:  { suggestedTitle, suggestedSlug, ..., briefId, clusterUpdated: false }

POST /api/projects/:slug/content-gaps/:id/generate
  Before: { articleId | cornerstoneSpecId, status }
  After:  { articleId | cornerstoneSpecId, status, briefId }

POST /api/projects/:slug/content-gaps/:id/automate
  Before: { chainId, status }
  After:  { chainId, status, briefId }
```

The frontend (`GapsPanel.vue`) currently does not use `briefId`; it can ignore the field. In 54.6 / 54.9 the field becomes the navigation key into the new Trending Topics inbox.

### Routing decisions per gap type

The policy's decision matrix, mapping `TopicBrief` fields (which already encode the gap shape via `mapGapToBrief` from 54.1) to a `RoutingDecision`:

```
brief.source='gap_analysis', brief.gap_metadata.gapType=
  missing_hub             → create_cornerstone_spec (mode='pillar')
  missing_spoke_type      → create_article (mode='spoke', intentType from brief)
  missing_translation     → create_translation (find source article from brief.translationKey)
  cluster_too_small       → create_article (mode='spoke', intentType from brief)

brief.source='trend_discovery'   → 54.5+ (not in 54.3)
brief.source='refresh_detection' → future
brief.source='manual'            → 54.6+ (UI form)
```

For 54.3, only `gap_analysis` briefs reach the policy in practice. The decision function still handles unknown sources gracefully with `kind: 'skip', reason: 'source not yet supported'`.

### Decision function (pure)

`packages/pipelines/src/routing/decide-route.ts`:

```typescript
import type { TopicBrief } from "@marketing-auto/db";
import type { RoutingDecision } from "./types.ts";

/**
 * Decides what to do with a TopicBrief. Pure function — no DB, no I/O.
 *
 * The decision is structural: derived entirely from brief fields. The caller
 * (executeDecision) performs the actual DB writes inside a transaction.
 *
 * For 54.3, only source='gap_analysis' briefs produce meaningful decisions.
 * Other sources return { kind: 'skip', reason: '...' } so upstream callers
 * see explicit non-handling rather than silent failures.
 */
export function decideRoute(brief: TopicBrief): RoutingDecision {
  if (brief.source !== "gap_analysis") {
    return {
      kind: "skip",
      reason: `Source '${brief.source}' not yet supported in 54.3`,
    };
  }

  const meta = brief.gapMetadata;
  if (!meta) {
    return { kind: "skip", reason: "gap_analysis brief missing gap_metadata" };
  }

  switch (meta.gapType) {
    case "missing_hub": {
      if (!brief.clusterId) {
        return { kind: "skip", reason: "missing_hub requires clusterId" };
      }
      return {
        kind: "create_cornerstone_spec",
        clusterId: brief.clusterId,
        mode: "pillar",
      };
    }

    case "missing_spoke_type":
    case "cluster_too_small": {
      if (!brief.clusterId) {
        return { kind: "skip", reason: `${meta.gapType} requires clusterId` };
      }
      const intentType = brief.intentType
        ?? (meta.gapType === "missing_spoke_type" ? null : "use_case");
      if (!intentType) {
        return { kind: "skip", reason: "missing_spoke_type requires intentType" };
      }
      return {
        kind: "create_article",
        clusterId: brief.clusterId,
        intentType,
        mode: brief.generationMode ?? "spoke",
      };
    }

    case "missing_translation": {
      const translationKey = meta.translationKey;
      const targetLocale = brief.locale;
      if (!translationKey || !targetLocale) {
        return {
          kind: "skip",
          reason: "missing_translation requires translationKey and locale",
        };
      }
      return {
        kind: "create_translation",
        sourceTranslationKey: translationKey,
        targetLocale,
        clusterId: brief.clusterId ?? null,
      };
    }

    default:
      return {
        kind: "skip",
        reason: `Unknown gapType: ${(meta as { gapType: string }).gapType}`,
      };
  }
}
```

### Execution function (transactional)

`packages/pipelines/src/routing/execute-decision.ts`:

```typescript
import { eq } from "@marketing-auto/db";
import {
  db, articles, cornerstoneSpecs, topicBriefs,
  type TopicBrief, type Transaction,
} from "@marketing-auto/db";
import type { RoutingDecision, RoutingResult } from "./types.ts";
import { RoutingNotImplementedError } from "./types.ts";

/**
 * Executes a routing decision inside a transaction.
 *
 * Atomicity invariant: the article/spec/translation insert AND the brief update
 * to `approval_status='routed'` happen in the same transaction. If the pipeline
 * chain enqueue (caller's responsibility) fails afterward, the brief is still
 * marked routed — that's acceptable, the chain can be retried manually.
 *
 * The transaction is passed in by the caller (route handler) so this function
 * can join an outer transaction (e.g., when /automate wraps multiple steps).
 */
export async function executeDecision(
  decision: RoutingDecision,
  brief: TopicBrief,
  tx: Transaction,
): Promise<RoutingResult> {
  switch (decision.kind) {
    case "create_article": {
      const [article] = await tx.insert(articles).values({
        projectId: brief.projectId,
        clusterId: decision.clusterId,
        cornerstoneKeyword: brief.primaryKeyword ?? null,
        locale: brief.locale ?? "de",
        translationKey: brief.gapMetadata?.translationKey ?? null,
        intentType: decision.intentType,
        status: "proposed",
        approvalMode: brief.approvalRequired ? "manual" : "auto",
        source: "generated",
        clusterRole: decision.mode === "pillar" ? "hub" : "spoke",
      }).returning();

      await markBriefRouted(tx, brief.id, { routedArticleId: article.id });
      return { kind: "article_created", articleId: article.id, briefId: brief.id };
    }

    case "create_cornerstone_spec": {
      const [spec] = await tx.insert(cornerstoneSpecs).values({
        projectId: brief.projectId,
        clusterId: decision.clusterId,
        locale: brief.locale ?? "de",
        translationKey: brief.gapMetadata?.translationKey ?? `hub-${decision.clusterId}`,
        cornerstoneKeyword: brief.primaryKeyword ?? "",
        proposedTitle: brief.suggestedTitle ?? `Pillar for cluster ${decision.clusterId}`,
        proposedSlug: brief.suggestedSlug ?? "",
        metaDescription: brief.suggestedMeta ?? "",
        estimatedWordCount: 3000,
        h2Outline: [],
        status: "proposed",
      }).returning();

      await markBriefRouted(tx, brief.id, { routedCornerstoneSpecId: spec.id });
      return {
        kind: "cornerstone_spec_created",
        cornerstoneSpecId: spec.id,
        briefId: brief.id,
      };
    }

    case "create_translation": {
      // Locate the source article by translationKey + opposite locale
      const sourceLocale = decision.targetLocale === "de" ? "en" : "de";
      const [sourceArticle] = await tx
        .select()
        .from(articles)
        .where(/* projectId + translationKey + sourceLocale */)
        .limit(1);

      if (!sourceArticle) {
        await markBriefRouted(tx, brief.id, {
          approvalStatus: "superseded",
        });
        return { kind: "skipped", reason: "source article not found", briefId: brief.id };
      }

      const [translation] = await tx.insert(articles).values({
        projectId: brief.projectId,
        clusterId: sourceArticle.clusterId,
        cornerstoneKeyword: sourceArticle.cornerstoneKeyword,
        locale: decision.targetLocale,
        translationKey: decision.sourceTranslationKey,
        intentType: sourceArticle.intentType,
        status: "proposed",
        approvalMode: brief.approvalRequired ? "manual" : "auto",
        source: "generated",
        clusterRole: sourceArticle.clusterRole,
      }).returning();

      await markBriefRouted(tx, brief.id, { routedArticleId: translation.id });
      return { kind: "translation_created", articleId: translation.id, briefId: brief.id };
    }

    case "refresh_article":
      throw new RoutingNotImplementedError(
        "refresh_article",
        "Refresh source is future spec",
      );

    case "create_cluster":
      throw new RoutingNotImplementedError(
        "create_cluster",
        "Cluster Creator is Spec 54.7",
      );

    case "skip":
      // Mark the brief as superseded so it doesn't re-surface
      await tx.update(topicBriefs)
        .set({ approvalStatus: "superseded", updatedAt: new Date() })
        .where(eq(topicBriefs.id, brief.id));
      return { kind: "skipped", reason: decision.reason, briefId: brief.id };
  }
}

async function markBriefRouted(
  tx: Transaction,
  briefId: string,
  patch: Partial<{
    routedArticleId: string;
    routedCornerstoneSpecId: string;
    approvalStatus: "routed" | "superseded";
  }>,
): Promise<void> {
  await tx.update(topicBriefs)
    .set({
      approvalStatus: patch.approvalStatus ?? "routed",
      approvedAt: new Date(),
      routedArticleId: patch.routedArticleId ?? undefined,
      routedCornerstoneSpecId: patch.routedCornerstoneSpecId ?? undefined,
      updatedAt: new Date(),
    })
    .where(eq(topicBriefs.id, briefId));
}
```

Note on the `undefined` vs `null` distinction here: this is exactly the case 54.1 discovered (Zod optional × Drizzle exactOptionalPropertyTypes). Use `Object.fromEntries(...filter v !== undefined...)` pattern if the type checker complains, OR explicitly pass `null` for absent fields.

### Route refactor: /generate

Current shape (simplified):

```typescript
app.post("/api/projects/:slug/content-gaps/:id/generate", async (c) => {
  const gap = await loadGap(...);
  // ... a switch on gap.gapType creates article or cornerstone_spec ...
  return c.json({ articleId, status: "proposed" });
});
```

Target shape:

```typescript
app.post("/api/projects/:slug/content-gaps/:id/generate", async (c) => {
  const gap = await loadGap(...);

  // Load the brief that 54.1 dual-write created for this gap
  const [brief] = await db.select().from(topicBriefs)
    .where(and(
      eq(topicBriefs.gapId, gap.id),
      inArray(topicBriefs.approvalStatus, ["pending", "approved"]),
    ))
    .limit(1);

  if (!brief) {
    return c.json({ error: "No active brief for this gap" }, 404);
  }

  const decision = decideRoute(brief);

  const result = await db.transaction(async (tx) => {
    return executeDecision(decision, brief, tx);
  });

  if (result.kind === "skipped") {
    return c.json({
      status: "skipped",
      reason: result.reason,
      briefId: result.briefId,
    }, 422);
  }

  return c.json({
    articleId: "articleId" in result ? result.articleId : undefined,
    cornerstoneSpecId: "cornerstoneSpecId" in result ? result.cornerstoneSpecId : undefined,
    status: "proposed",
    briefId: result.briefId,
  });
});
```

### Route refactor: /automate

`/automate` chains the routing decision with pipeline-chain creation. The brief is marked `routed` in the same transaction as the article+chain row.

```typescript
app.post("/api/projects/:slug/content-gaps/:id/automate", async (c) => {
  const gap = await loadGap(...);
  const [brief] = await db.select()...; // same brief lookup

  const decision = decideRoute(brief);

  const { chainId, briefId } = await db.transaction(async (tx) => {
    const result = await executeDecision(decision, brief, tx);

    if (result.kind === "skipped") {
      return { chainId: null, briefId: result.briefId };
    }

    // Only create_article and create_translation enter the chain flow.
    // create_cornerstone_spec uses a different downstream path (cornerstone approval).
    if (result.kind === "article_created" || result.kind === "translation_created") {
      const [chain] = await tx.insert(pipelineChains).values({
        projectId: brief.projectId,
        gapId: gap.id,                // backward-compat (existing chain consumers)
        articleId: result.articleId,
        status: "queued",
        currentStep: "outline",
        autoPublish: false,
      }).returning();
      return { chainId: chain.id, briefId: result.briefId };
    }

    return { chainId: null, briefId: result.briefId };
  });

  // Pipeline-chain enqueue happens outside the transaction (BullMQ)
  if (chainId) {
    await chainQueue.add("advance", { chainId });
  }

  return c.json({ chainId, status: "queued", briefId });
});
```

app.post("/api/projects/:slug/content-gaps/:id/suggest", async (c) => {

### TopicIntakeStep refactor

`packages/pipelines/src/article/steps/topic-intake.ts`:

```typescript
import { and, eq } from "@marketing-auto/db";
import { db, articles, topicBriefs, clusters } from "@marketing-auto/db";
import { createLogger } from "@marketing-auto/shared";

const log = createLogger("topic-intake");

async function resolveKeywordsAndCluster(articleId: string): Promise<KeywordContext> {
  const [article] = await db.select().from(articles)
    .where(eq(articles.id, articleId)).limit(1);
  if (!article) throw new Error(`Article ${articleId} not found`);

  // 1. Primary path: find linked brief
  const [brief] = await db.select().from(topicBriefs)
    .where(and(
      eq(topicBriefs.routedArticleId, articleId),
      // No status filter — even superseded briefs are valid context for already-routed articles
    ))
    .limit(1);

  if (brief) {
    log.debug({ articleId, briefId: brief.id }, "topic-intake: brief-sourced");
    return {
      primaryKeyword: brief.primaryKeyword ?? article.cornerstoneKeyword ?? "",
      secondaryKeywords: brief.secondaryKeywords ?? [],
      source: "brief",
      brief,
      article,
    };
  }

  // 2. Fallback path: legacy article without brief (created before 54.1 dual-write)
  log.warn(
    { articleId, cornerstoneKeyword: article.cornerstoneKeyword },
    "topic-intake: no brief linked, using legacy cluster match",
  );

  let satellites: string[] = [];
  if (article.clusterId) {
    const [cluster] = await db.select().from(clusters)
      .where(eq(clusters.id, article.clusterId)).limit(1);
    if (cluster?.satelliteKeywords) {
      // Existing match logic: find the SatelliteKeywordEntry whose
      // cornerstoneKeyword equals article.cornerstoneKeyword
      const matched = (cluster.satelliteKeywords as SatelliteKeywordEntry[]).find(
        (e) => e.cornerstoneKeyword === article.cornerstoneKeyword,
      );
      satellites = matched?.keywords.map((k) => k.keyword) ?? [];
    }
  }

  return {
    primaryKeyword: article.cornerstoneKeyword ?? "",
    secondaryKeywords: satellites,
    source: "cluster_legacy",
    brief: null,
    article,
  };
}
```

## Open Questions / Decisions Made

**Decision 1: Pure functions over class for TopicRoutingPolicy.**
Per user direction (1b). Consistent with existing pattern (`loadActiveConfig`, `resolveIntentTaxonomy`, `mapGapToBrief`). No mocking needed for tests.

**Decision 2: Brief marked `routed` atomically with article/spec insert.**
Per user direction (2a). If pipeline-chain enqueue (post-transaction) fails, the brief is still `routed`, but the article exists and chains can be manually retried. Better than the alternative of leaving the brief `pending` with an orphan article.

**Decision 3: Drop `source='imported'` filter entirely in gap-detection.**
Per user direction (3a). Tech Debt #1 fix. Risk (generated articles influence detection) pre-exists if any article was misclassified; no new failure mode.

**Decision 4: `/suggest` side-effect removed; data lives in brief only.**
Per user direction (4a). Tech Debt #6 fix. `clusters.satellite_keywords` is no longer written by `/suggest`. Existing data preserved. Column becomes a fossil for now; deprecation deferred.

**Decision 5: TopicIntakeStep brief-sourced, with legacy fallback.**
Per user direction (5c). Tech Debt #7 fix. Brief is the single source of truth. Legacy articles (no brief) still work via cluster-match fallback with a warning log.

**Decision 6: Decision separated from execution.**
A `RoutingDecision` is data; `executeDecision` performs it. Enables logging decisions before execution and prepares the model for Phase 2 rule-based automation.

**Decision 7: `create_cluster` is a stub.**
The policy can emit `kind: 'create_cluster'`, but executeDecision throws `RoutingNotImplementedError`. Realistically, gap-sourced briefs never request `create_new` — only Trend Discovery and Manual sources will (Phase B+). Stub keeps the model honest without forcing 54.7 work into 54.3.

**Decision 8: `/suggest` dual-writes to content_gaps.metadata for backward compat.**
The brief is the primary writer, but `content_gaps.metadata` still gets the same fields. Any code outside our touch radius that reads `gap.metadata.suggestedTitle` continues to work. Cleanup deferred.

**Decision 9: 404 if no active brief found.**
Routes return 404 when no brief exists (terminal status only). This forces callers to handle the case explicitly rather than silently re-running. Resolved/dismissed gaps that lost their brief won't generate accidentally.

**Decision 10: `routed_article_id` and `routed_cornerstone_spec_id` as separate columns.**
Could be a single polymorphic `routed_target_id` + `routed_target_kind`. Chose two columns because they FK to different tables (cleaner with `ON DELETE SET NULL`), and queries that need "all routed articles" are simpler. Cost: one extra nullable column.

**Decision 11: Transaction boundary at the route handler, not in executeDecision.**
`executeDecision` accepts a `tx`, doesn't open one itself. This lets the route handler compose multiple actions (e.g., `/automate` adds the chain insert) into one transaction. Standard pattern.

**Decision 12: Existing `clusters.satellite_keywords` column not migrated/dropped in 54.3.**
Other code may still read it. Removing it is a discrete future task once we audit all readers. For now, it stays — `/suggest` just stops writing to it.
