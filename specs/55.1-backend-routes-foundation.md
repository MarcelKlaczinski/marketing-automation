## Goal

Add the backend foundation for Theme 55's new UI:

1. **Missing routes for Dashboard orchestration**: retry, enriched run detail, cluster generation status, search, cost summary, project picker
2. **SSE pipeline events channel**: real-time updates for the live activity feed (avoids polling)
3. **Frontend-driven scoping migration**: only routes the new Dashboard consumes get migrated to `/api/projects/:slug/...` path-param pattern
4. **API consistency cleanup**: pagination patterns documented, error response shapes standardized

After this spec lands, the new UI (55.2 Dashboard MVP) has all the backend it needs. Bulk endpoints (low-priority) are deferred to post-55.2 once UI surfaces real bulk use cases.

## What this is NOT

- Not bulk-approve/bulk-retry endpoints — deferred to post-55.2 (Q5b)
- Not OpenAPI/Swagger generation — Phase E backlog (Q4c)
- Not API versioning (no `/api/v2/...`) — deprecate old routes inline (Q3a)
- Not big-bang scoping migration — only frontend-consumed routes get migrated (Q2c)
- Not WebSocket — SSE only, extends existing `/api/notifications/stream` pattern (Q1a)
- Not changing the existing Cold-Start, Cost, or Brand-Tokens routes — those work as-is
- Not refactoring the existing `/api/pipeline-runs/active` activity feed — it stays, SSE complements it

## Section A: Missing Routes

### A.1 `POST /api/pipeline-runs/:id/retry`

**Priority**: High
**Use case**: User clicks "Retry" on a failed pipeline run in Dashboard. Re-enqueues the same pipeline with the same input.

**Implementation**:

```typescript
// apps/api/src/routes/pipeline-runs.ts (extends existing file)

retryRunRoute = createRoute({
  method: "POST",
  path: "/:id/retry",
  // ...
});

async function handleRetry(c: Context) {
  const { id } = c.req.param();
  const session = c.get("session");
  
  // 1. Load failed run
  const [run] = await db.select().from(pipelineRuns)
    .where(eq(pipelineRuns.id, id))
    .limit(1);
  
  if (!run) return c.json({ ok: false, error: "not_found" }, 404);
  if (run.status !== "failed") {
    return c.json({ 
      ok: false, 
      error: "not_failed", 
      message: `Run is in status "${run.status}", only "failed" runs can be retried` 
    }, 422);
  }
  
  // 2. Check project not paused + cost not exceeded
  const project = await loadProject(run.projectId);
  const triggerCheck = await checkTriggerAllowed({
    projectId: project.id,
    operation: run.pipelineName,
  });
  if (!triggerCheck.allowed) {
    return c.json({ ok: false, ...triggerCheck.errorPayload }, triggerCheck.errorStatus);
  }
  
  // 3. Re-enqueue based on pipeline type
  const pipelineName = run.pipelineName;
  const input = run.input as Record<string, unknown>;
  
  const newRunId = generatePipelineRunId();
  
  // Dispatch by pipeline type
  if (pipelineName === "article:blog") {
    await enqueueBlogGeneration({
      ...input as BlogPipelineInput,
      pipelineRunId: newRunId,
      retriedFromRunId: id,  // audit trail
    });
  } else if (pipelineName === "article:refresh") {
    await enqueueRefreshPipeline({ ...input, pipelineRunId: newRunId, retriedFromRunId: id });
  } else if (pipelineName === "article:translation") {
    await enqueueTranslationPipeline({ ...input, pipelineRunId: newRunId, retriedFromRunId: id });
  } else if (pipelineName === "cluster:plan") {
    // Cluster plan is one-shot, not pipeline
    return c.json({ 
      ok: false, 
      error: "not_retryable", 
      message: "Cluster plan generation is one-shot. Trigger a new plan instead." 
    }, 422);
  } else {
    return c.json({ 
      ok: false, 
      error: "unknown_pipeline", 
      message: `No retry handler for pipeline "${pipelineName}"` 
    }, 422);
  }
  
  return c.json({ 
    ok: true, 
    data: { newRunId, retriedFromRunId: id } 
  }, 202);
}
```

**Audit trail**: every retry creates a new pipeline_run with `input.retriedFromRunId` referencing the failed run. Allows the UI to show "Retried from run pr_abc..." in the detail pane.

**What this is NOT**: not a "resume from failed step" — it's a full re-run. Resume-from-step is a Phase E backlog item.

### A.2 Enriched `GET /api/pipeline-runs/:id`

**Priority**: High
**Use case**: Dashboard detail pane shows pipeline run with step-by-step timeline, costs, errors.

**Current behavior** (from Discovery 3.2): returns only top-level run row.

**New behavior**: returns run + child step rows + cost_logs + linked article/brief.

**Implementation**:

```typescript
// apps/api/src/routes/pipeline-runs.ts

async function handleGetRunDetail(c: Context) {
  const { id } = c.req.param();
  
  // 1. Load parent run
  const [run] = await db.select().from(pipelineRuns)
    .where(eq(pipelineRuns.id, id))
    .limit(1);
  
  if (!run) return c.json({ ok: false, error: "not_found" }, 404);
  
  // 2. Load child step runs (parentRunId = id)
  const stepRuns = await db.select().from(pipelineRuns)
    .where(eq(pipelineRuns.parentRunId, id))
    .orderBy(asc(pipelineRuns.createdAt));
  
  // 3. Load cost_logs for this run (parent + children)
  const allRunIds = [id, ...stepRuns.map(s => s.id)];
  const costs = await db.select().from(costLogs)
    .where(inArray(costLogs.pipelineRunId, allRunIds))
    .orderBy(asc(costLogs.createdAt));
  
  // 4. Load linked article (via input.articleId or pipeline_runs.articleId if column exists)
  // Per 54.9.1 discovery: pipeline_runs.article_id column doesn't exist;
  // articleId is in input JSONB
  const articleId = (run.input as Record<string, unknown>)?.articleId as string | undefined;
  const article = articleId ? await loadArticle(articleId) : null;
  
  // 5. Load linked brief if present in input
  const briefId = (run.input as Record<string, unknown>)?.briefId as string | undefined;
  const brief = briefId ? await loadBrief(briefId) : null;
  
  return c.json({
    ok: true,
    data: {
      run: {
        id: run.id,
        pipelineName: run.pipelineName,
        projectId: run.projectId,
        status: run.status,
        startedAt: run.startedAt,
        completedAt: run.completedAt,
        createdAt: run.createdAt,
        durationMs: run.completedAt && run.startedAt
          ? new Date(run.completedAt).getTime() - new Date(run.startedAt).getTime()
          : null,
        input: run.input,
        output: run.output,
        error: run.error,
        retriedFromRunId: (run.input as Record<string, unknown>)?.retriedFromRunId ?? null,
      },
      steps: stepRuns.map(s => ({
        id: s.id,
        stepName: s.stepName,
        status: s.status,
        startedAt: s.startedAt,
        completedAt: s.completedAt,
        durationMs: s.completedAt && s.startedAt
          ? new Date(s.completedAt).getTime() - new Date(s.startedAt).getTime()
          : null,
        output: s.output,
        error: s.error,
      })),
      costs: costs.map(c => ({
        id: c.id,
        operation: c.operation,
        service: c.service,
        costEur: c.costEur,
        stepRunId: c.pipelineRunId !== id ? c.pipelineRunId : null,  // link to step if child
        createdAt: c.createdAt,
      })),
      totalCostEur: costs.reduce((sum, c) => sum + Number(c.costEur), 0),
      article: article ? {
        id: article.id,
        title: article.title,
        slug: article.slug,
        status: article.status,
        locale: article.locale,
        clusterId: article.clusterId,
      } : null,
      brief: brief ? {
        id: brief.id,
        source: brief.source,
        topicTitle: brief.topicTitle,
      } : null,
    },
  });
}
```

**Backward compatibility**: existing consumers that only read top-level fields continue to work (they're still in `data.run.*`). New fields are additive.

### A.3 `GET /api/projects/:slug/clusters/:id/generation-status`

**Priority**: Medium (post-54.12)
**Use case**: Dashboard Cluster Card shows real-time generation progress with article pills.

**Implementation**:

```typescript
// apps/api/src/routes/projects/clusters.ts

async function handleGetGenerationStatus(c: Context) {
  const { slug, id } = c.req.param();
  
  const project = await loadProjectBySlug(slug);
  if (!project) return c.json({ ok: false, error: "project_not_found" }, 404);
  
  const [cluster] = await db.select().from(clusters)
    .where(and(
      eq(clusters.id, id),
      eq(clusters.projectId, project.id),
    ))
    .limit(1);
  
  if (!cluster) return c.json({ ok: false, error: "cluster_not_found" }, 404);
  
  // Load all articles tied to this cluster generation
  const clusterArticles = await db.select().from(articles)
    .where(or(
      eq(articles.clusterGenerationId, id),
      eq(articles.clusterId, id),  // also include manually-added articles
    ))
    .orderBy(asc(articles.createdAt));
  
  // Separate hub from spokes
  const hubArticle = clusterArticles.find(a => a.role === "hub") ?? null;
  const spokeArticles = clusterArticles.filter(a => a.role === "spoke");
  
  // Load pipeline_runs tied to this cluster
  const pipelineRunsForCluster = await db.select().from(pipelineRuns)
    .where(sql`${pipelineRuns.input}->>'clusterGenerationId' = ${id}`)
    .orderBy(desc(pipelineRuns.createdAt));
  
  // Aggregate cost
  const allRunIds = pipelineRunsForCluster.map(r => r.id);
  const totalCostEur = allRunIds.length > 0
    ? await db.select({ total: sql<number>`SUM(${costLogs.costEur})` })
        .from(costLogs)
        .where(inArray(costLogs.pipelineRunId, allRunIds))
        .then(r => Number(r[0]?.total ?? 0))
    : 0;
  
  // Compute progress
  const expectedDeArticleCount = 1 + (cluster.proposedSpokes?.length ?? 0);  // Hub + Spokes
  const hasTranslation = project.targetLocales?.includes("en-US") 
    && project.translationAutoTrigger !== false;
  const expectedTotalArticleCount = hasTranslation 
    ? expectedDeArticleCount * 2 
    : expectedDeArticleCount;
  
  const completedCount = clusterArticles.filter(a => 
    a.status === "final_review" || a.status === "published"
  ).length;
  
  const progressPercent = expectedTotalArticleCount > 0
    ? Math.round((completedCount / expectedTotalArticleCount) * 100)
    : 0;
  
  return c.json({
    ok: true,
    data: {
      cluster: {
        id: cluster.id,
        name: cluster.name,
        generationStatus: cluster.generationStatus,
        triggerBriefId: cluster.triggerBriefId,
        proposedHub: cluster.proposedHub,
        proposedSpokes: cluster.proposedSpokes,
        pendingSpokeBriefIds: cluster.pendingSpokeBriefIds ?? [],
      },
      hubArticle: hubArticle ? {
        id: hubArticle.id,
        title: hubArticle.title,
        status: hubArticle.status,
        locale: hubArticle.locale,
        role: "hub",
      } : null,
      spokeArticles: spokeArticles.map(a => ({
        id: a.id,
        title: a.title,
        status: a.status,
        locale: a.locale,
        role: "spoke",
      })),
      pipelineRuns: pipelineRunsForCluster.map(r => ({
        id: r.id,
        pipelineName: r.pipelineName,
        status: r.status,
        articleId: (r.input as Record<string, unknown>)?.articleId ?? null,
        createdAt: r.createdAt,
      })),
      cost: {
        spentEur: totalCostEur,
        estimatedEur: 4.20,  // from cost preview, see 54.12 Section F
      },
      progress: {
        completed: completedCount,
        expected: expectedTotalArticleCount,
        percent: progressPercent,
      },
    },
  });
}
```

### A.4 `GET /api/projects/:slug/search?q=`

**Priority**: Medium
**Use case**: Cmd+K search across articles, briefs, clusters within a project.

**Implementation**:

```typescript
// apps/api/src/routes/projects/search.ts (new file)

const searchQuerySchema = z.object({
  q: z.string().min(2).max(100),
  types: z.string().optional(),  // comma-separated: "articles,briefs,clusters"
  limit: z.coerce.number().int().min(1).max(50).default(20),
});

async function handleSearch(c: Context) {
  const { slug } = c.req.param();
  const { q, types, limit } = searchQuerySchema.parse(c.req.query());
  
  const project = await loadProjectBySlug(slug);
  if (!project) return c.json({ ok: false, error: "project_not_found" }, 404);
  
  const wantedTypes = types?.split(",") ?? ["articles", "briefs", "clusters"];
  const ilikePattern = `%${q}%`;
  
  const results: SearchResults = {
    articles: [],
    briefs: [],
    clusters: [],
  };
  
  if (wantedTypes.includes("articles")) {
    results.articles = await db.select({
      id: articles.id,
      title: articles.title,
      slug: articles.slug,
      collection: articles.collection,
      locale: articles.locale,
      status: articles.status,
    })
      .from(articles)
      .where(and(
        eq(articles.projectId, project.id),
        or(
          ilike(articles.title, ilikePattern),
          ilike(articles.cornerstoneKeyword, ilikePattern),
          ilike(articles.slug, ilikePattern),
        ),
      ))
      .limit(limit);
  }
  
  if (wantedTypes.includes("briefs")) {
    results.briefs = await db.select({
      id: topicBriefs.id,
      topicTitle: topicBriefs.topicTitle,
      primaryKeyword: topicBriefs.primaryKeyword,
      source: topicBriefs.source,
      approvalStatus: topicBriefs.approvalStatus,
    })
      .from(topicBriefs)
      .where(and(
        eq(topicBriefs.projectId, project.id),
        or(
          ilike(topicBriefs.topicTitle, ilikePattern),
          ilike(topicBriefs.primaryKeyword, ilikePattern),
        ),
      ))
      .limit(limit);
  }
  
  if (wantedTypes.includes("clusters")) {
    results.clusters = await db.select({
      id: clusters.id,
      name: clusters.name,
      primaryKeyword: clusters.primaryKeyword,
      generationStatus: clusters.generationStatus,
    })
      .from(clusters)
      .where(and(
        eq(clusters.projectId, project.id),
        or(
          ilike(clusters.name, ilikePattern),
          ilike(clusters.primaryKeyword, ilikePattern),
        ),
      ))
      .limit(limit);
  }
  
  return c.json({ ok: true, data: results });
}
```

**Implementation choice**: PostgreSQL `ILIKE` with `%pattern%`. Simple, no full-text index needed at toolwiki scale (272 articles + few hundred briefs/clusters). If performance degrades, future spec can add `tsvector` index.

**Index suggestion** (optional optimization, in migration):
```sql
CREATE INDEX articles_search_idx ON articles 
  USING gin (
    to_tsvector('simple', coalesce(title, '') || ' ' || coalesce(cornerstone_keyword, '') || ' ' || coalesce(slug, ''))
  );
```

Defer to Phase E if `ILIKE` becomes slow.

### A.5 `GET /api/projects/:slug/cost-summary?window=`

**Priority**: Medium
**Use case**: Dashboard stat cards show "Cost today / week / month" with sparklines.

**Implementation**:

```typescript
// apps/api/src/routes/projects/cost-summary.ts (new file)

const costSummaryQuerySchema = z.object({
  window: z.enum(["today", "week", "month", "year"]).default("month"),
});

async function handleCostSummary(c: Context) {
  const { slug } = c.req.param();
  const { window } = costSummaryQuerySchema.parse(c.req.query());
  
  const project = await loadProjectBySlug(slug);
  if (!project) return c.json({ ok: false, error: "project_not_found" }, 404);
  
  const now = new Date();
  const windowStart = getWindowStart(now, window);
  
  // Total cost in window
  const totalResult = await db.select({
    total: sql<number>`COALESCE(SUM(${costLogs.costEur}), 0)`,
  })
    .from(costLogs)
    .where(and(
      eq(costLogs.projectId, project.id),
      gte(costLogs.createdAt, windowStart),
    ));
  const totalEur = Number(totalResult[0]?.total ?? 0);
  
  // Group by service
  const byServiceResult = await db.select({
    service: costLogs.service,
    total: sql<number>`COALESCE(SUM(${costLogs.costEur}), 0)`,
  })
    .from(costLogs)
    .where(and(
      eq(costLogs.projectId, project.id),
      gte(costLogs.createdAt, windowStart),
    ))
    .groupBy(costLogs.service);
  
  const byService = Object.fromEntries(
    byServiceResult.map(r => [r.service, Number(r.total)])
  );
  
  // Group by operation
  const byOperationResult = await db.select({
    operation: costLogs.operation,
    total: sql<number>`COALESCE(SUM(${costLogs.costEur}), 0)`,
  })
    .from(costLogs)
    .where(and(
      eq(costLogs.projectId, project.id),
      gte(costLogs.createdAt, windowStart),
    ))
    .groupBy(costLogs.operation);
  
  const byOperation = Object.fromEntries(
    byOperationResult.map(r => [r.operation, Number(r.total)])
  );
  
  // Trend: daily aggregation across window (for sparkline)
  const trend = await db.select({
    date: sql<string>`DATE(${costLogs.createdAt})`,
    total: sql<number>`COALESCE(SUM(${costLogs.costEur}), 0)`,
  })
    .from(costLogs)
    .where(and(
      eq(costLogs.projectId, project.id),
      gte(costLogs.createdAt, windowStart),
    ))
    .groupBy(sql`DATE(${costLogs.createdAt})`)
    .orderBy(sql`DATE(${costLogs.createdAt})`);
  
  // Article count in window
  const articleCountResult = await db.select({
    count: sql<number>`COUNT(*)`,
  })
    .from(articles)
    .where(and(
      eq(articles.projectId, project.id),
      eq(articles.source, "generated"),
      gte(articles.createdAt, windowStart),
    ));
  
  return c.json({
    ok: true,
    data: {
      window,
      windowStart,
      windowEnd: now,
      totalEur,
      articleCount: Number(articleCountResult[0]?.count ?? 0),
      byService,
      byOperation,
      trend: trend.map(t => ({
        date: t.date,
        costEur: Number(t.total),
      })),
    },
  });
}

function getWindowStart(now: Date, window: "today" | "week" | "month" | "year"): Date {
  const start = new Date(now);
  switch (window) {
    case "today":
      start.setHours(0, 0, 0, 0);
      break;
    case "week":
      start.setDate(start.getDate() - 7);
      start.setHours(0, 0, 0, 0);
      break;
    case "month":
      start.setDate(1);
      start.setHours(0, 0, 0, 0);
      break;
    case "year":
      start.setMonth(0, 1);
      start.setHours(0, 0, 0, 0);
      break;
  }
  return start;
}
```

### A.6 `GET /api/projects/picker`

**Priority**: Medium
**Use case**: Project selector in nav. Lightweight payload with activity indicators.

**Implementation**:

```typescript
// apps/api/src/routes/projects.ts (extends existing)

async function handleProjectPicker(c: Context) {
  const session = c.get("session");
  
  // List all projects (no per-project full stats query)
  const allProjects = await db.select({
    id: projects.id,
    slug: projects.slug,
    name: projects.name,
    industry: projects.industry,
  }).from(projects);
  
  // Single query for running counts per project
  const runningCountsByProject = await db.select({
    projectId: pipelineRuns.projectId,
    count: sql<number>`COUNT(*)`,
  })
    .from(pipelineRuns)
    .where(or(
      eq(pipelineRuns.status, "running"),
      eq(pipelineRuns.status, "queued"),
    ))
    .groupBy(pipelineRuns.projectId);
  
  const runningMap = Object.fromEntries(
    runningCountsByProject.map(r => [r.projectId, Number(r.count)])
  );
  
  // Single query for failed counts (last 24h)
  const dayAgo = new Date(Date.now() - 24 * 60 * 60 * 1000);
  const failedCountsByProject = await db.select({
    projectId: pipelineRuns.projectId,
    count: sql<number>`COUNT(*)`,
  })
    .from(pipelineRuns)
    .where(and(
      eq(pipelineRuns.status, "failed"),
      gte(pipelineRuns.createdAt, dayAgo),
    ))
    .groupBy(pipelineRuns.projectId);
  
  const failedMap = Object.fromEntries(
    failedCountsByProject.map(r => [r.projectId, Number(r.count)])
  );
  
  // Single query for cost-this-month per project
  const monthStart = new Date();
  monthStart.setDate(1);
  monthStart.setHours(0, 0, 0, 0);
  
  const costsByProject = await db.select({
    projectId: costLogs.projectId,
    total: sql<number>`COALESCE(SUM(${costLogs.costEur}), 0)`,
  })
    .from(costLogs)
    .where(gte(costLogs.createdAt, monthStart))
    .groupBy(costLogs.projectId);
  
  const costMap = Object.fromEntries(
    costsByProject.map(r => [r.projectId, Number(r.total)])
  );
  
  // Article count per project (denormalized, fast query)
  const articleCountsByProject = await db.select({
    projectId: articles.projectId,
    count: sql<number>`COUNT(*)`,
  })
    .from(articles)
    .where(eq(articles.source, "generated"))
    .groupBy(articles.projectId);
  
  const articleCountMap = Object.fromEntries(
    articleCountsByProject.map(r => [r.projectId, Number(r.count)])
  );
  
  return c.json({
    ok: true,
    data: allProjects.map(p => ({
      id: p.id,
      slug: p.slug,
      name: p.name,
      industry: p.industry,
      activity: {
        runningCount: runningMap[p.id] ?? 0,
        failedLast24h: failedMap[p.id] ?? 0,
      },
      stats: {
        articleCount: articleCountMap[p.id] ?? 0,
        costThisMonthEur: costMap[p.id] ?? 0,
      },
    })),
  });
}
```

**Performance**: 4 aggregation queries instead of N+1. At scale (10 projects), ~10ms total. Adequate for picker which is loaded once per session.

### B.3 Publishing events from pipelines

Events are published via Redis pub/sub channel keyed by project. The SSE endpoint subscribes per-client.

```typescript
// packages/core/src/events/publisher.ts (new file)

export async function publishPipelineEvent(
  projectId: string,
  event: PipelineEvent,
): Promise<void> {
  const channel = `pipeline:events:project:${projectId}`;
  await redis.publish(channel, JSON.stringify(event));
}
```

**Integration into existing pipelines**:

In Blog Pipeline `runPipeline()`:
```typescript
// On pipeline start
await publishPipelineEvent(projectId, {
```

### B.4 SSE endpoint implementation

```typescript
// apps/api/src/routes/projects/pipeline-events.ts (new file)

import { streamSSE } from "hono/streaming";

async function handlePipelineEvents(c: Context) {
  const { slug } = c.req.param();
  const session = c.get("session");
  
  const project = await loadProjectBySlug(slug);
  if (!project) return c.json({ ok: false, error: "project_not_found" }, 404);
  
  // Authorization: user must have access to this project (existing pattern)
  // ...
  
  return streamSSE(c, async (stream) => {
    const subscriber = redis.duplicate();  // separate connection for subscription
    const channel = `pipeline:events:project:${project.id}`;
    
    let isOpen = true;
    
    // Send initial connection event
    await stream.writeSSE({
      event: "connected",
      data: JSON.stringify({ projectId: project.id, timestamp: new Date().toISOString() }),
    });
    
    // Subscribe to Redis channel
    await subscriber.subscribe(channel, async (message) => {
      if (!isOpen) return;
      try {
        const event = JSON.parse(message) as PipelineEvent;
        await stream.writeSSE({
          event: event.type,
          data: JSON.stringify(event),
        });
      } catch (err) {
        log.error({ err }, "Failed to forward pipeline event to SSE client");
      }
    });
    
    // Heartbeat every 30s to keep connection alive
    const heartbeatInterval = setInterval(async () => {
      if (!isOpen) return;
      try {
        await stream.writeSSE({
          event: "heartbeat",
          data: JSON.stringify({ timestamp: new Date().toISOString() }),
        });
      } catch (err) {
        // Connection closed
        isOpen = false;
      }
    }, 30_000);
    
    // Cleanup on disconnect
    stream.onAbort(async () => {
      isOpen = false;
      clearInterval(heartbeatInterval);
      await subscriber.unsubscribe(channel);
      await subscriber.quit();
    });
    
    // Keep stream open
    await new Promise((resolve) => {
      const checkInterval = setInterval(() => {
        if (!isOpen) {
          clearInterval(checkInterval);
          resolve(null);
        }
      }, 1000);
    });
  });
}
```

**Notes**:
- Uses Hono's `streamSSE` helper for proper SSE formatting
- Each client gets its own Redis subscription (slight overhead but isolates failures)
- 30s heartbeat prevents proxy timeouts (default 60s on most setups)
- `onAbort` cleanup is critical — without it, Redis connections leak

## Decisions Made

**Decision 1: SSE over WebSocket (Q1a).**
Pipeline state is server→client only. SSE extends existing notifications pattern. WebSocket overhead not justified.

**Decision 2: Frontend-driven scoping migration (Q2c).**
Only Dashboard-consumed routes get migrated. Avoids touching 100+ routes for big-bang refactor. Future sub-specs migrate as UI needs.

**Decision 3: No API versioning (Q3a).**
Deprecation header per-route. Single backend, single frontend, no external clients. Versioning adds complexity without benefit.

**Decision 4: No OpenAPI generation (Q4bc).**
Solo-dev shared types via tsconfig path mapping suffice. Phase E backlog if external integration emerges.

**Decision 5: Bulk endpoints deferred (Q5b).**
Implement after 55.2 Dashboard MVP reveals real bulk use cases. Don't over-build.

**Decision 6: ILIKE for search, not tsvector.**
At toolwiki scale (272 articles + ~50 briefs + ~32 clusters), ILIKE on indexed columns is fast enough. tsvector index upgrade in Phase E if performance degrades.

**Decision 7: Redis pub/sub for SSE event delivery.**
Already using Redis for BullMQ. Pub/sub is built-in. Per-client subscriber connection isolates failures.

**Decision 8: Heartbeat at 30s.**
Most proxies timeout at 60s. 30s is safe margin. Cost: ~120 bytes per project per minute.

**Decision 9: Deprecation header pattern instead of route removal.**
Old routes keep working. Frontend migration happens at consumer pace. Logs identify stragglers.

**Decision 10: Retry creates new pipeline_run, doesn't modify failed one.**
Audit trail preserved. Old run shows it was retried via reverse lookup. Status of old run remains 'failed' historically.

**Decision 11: Cluster:plan not retryable via this endpoint.**
Cluster plan generation is one-shot LLM call, not a pipeline. Use `POST /clusters/:id/plan/regenerate` from 54.12 Section B for that.

## Discovered During Implementation

- **Retry uses `enqueuePipeline` directly, NOT pipeline-specific wrappers.** `enqueueBlogGeneration` creates a new article from a brief — wrong for retry where the article already exists. Correct pattern: call `enqueuePipeline({ pipelineName, projectId, input: { ...originalInput, retriedFromRunId: id } })` directly. Only `cluster:plan` and `cold-start:*` pipelines are blocked (422 not-retryable); all article pipelines use the direct path.
- **JSONB `input` null safety pattern.** `(run.input as Record<string, unknown>)?.articleId` silently returns `undefined` when `run.input` is `null` (stored as SQL NULL). Correct pattern: `const input = run.input ?? {}; const articleId = typeof input.articleId === "string" ? input.articleId : undefined;` — the `?? {}` guard must come first.
- **Hub/spoke split via `articles.role` column.** `GET /clusters/:id/generation-status` separates hub from spokes using `a.role === "hub"` filter on the loaded article set — not via a separate query. The `role` column (added in Spec 54.12) is the canonical discriminator.
- **`ilike` and `or` were missing from `@marketing-auto/db` re-exports** before sessions 1+2. Both were added to `packages/db/src/index.ts` so search queries could use them via the workspace-canonical import.
- **`GET /api/projects/picker` must be registered BEFORE `/:slug`** in `apps/api/src/routes/projects.ts`. Hono matches in registration order; registering `/picker` after `/:slug` causes Hono to capture it as `slug = "picker"` silently.

## Deviations

- **A.1 retry dispatch simplified**: spec's implementation blueprint showed separate `if/else if` branches per pipeline name calling pipeline-specific enqueue wrappers (e.g. `enqueueBlogGeneration`, `enqueueRefreshPipeline`). Actual implementation uses `enqueuePipeline` directly for all retryable pipelines — avoids side effects (new article creation, brief validation) that wrappers perform on first-run. Only the block-list logic (cluster:plan, cold-start:*) matches the spec.
- **Section B (SSE) and C (scoping migration) deferred**: sessions 1+2 cover only Section A (all 6 missing routes). SSE (Section B) and scoping migration (Section C) are targeted for sessions 3+4 as originally planned.
