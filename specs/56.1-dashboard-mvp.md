# Spec 56.1: Dashboard MVP

**Theme:** 56 / UI Refactoring — Sub-spec 1 of 4
**Phase:** Frontend Foundation + Dashboard
**Estimated Effort:** ~5-6 days (~36 focused hours across 8 sessions)
**Dependencies:**
- Spec 55.1 (Backend Routes Foundation — provides retry, enriched run detail, generation status, search, cost summary, picker, SSE)
- Spec 54.12 (Full Cluster Generation — provides cluster generation state)
- Spec 54.10 (Translation Pipeline)
- Dashboard Mockup (visual anchor: `dashboard-mockup.html`)

**Status:** Ready for implementation
**Recommended Model:** Sonnet 4.6 for implementation work.

---

## Goal

Replace the existing Marketing-Auto frontend with a new glassmorphism dark-mode dashboard focused on pipeline orchestration. This sub-spec establishes:

1. **Component Library Foundation**: design-tokens, layout primitives (AppShell, Sidebar, Topbar), atomic components (Button, Card, Pill, Badge, etc.)
2. **State Management Architecture**: TanStack Query (Vue Query) for API data + Pinia for UI state + SSE event integration
3. **The Dashboard itself**: Hybrid view with Stats + Kanban Lanes + Cluster Cards + Detail Pane (matching the approved mockup)

After this spec lands, Marcel has a working dashboard that shows real-time pipeline state. Other views (Articles, Briefs, Clusters, Settings) are still missing — those come in 56.2 and 56.3. The app is **intentionally incomplete** between 56.1-56.4 (per big-bang strategy).

## What this is NOT

- Not migrating articles/briefs/clusters views — that's 56.2
- Not redesigning settings/costs — that's 56.3
- Not migrating cold-start — that's 56.4
- Not adding quick-actions to Cmd+K — search only (per Q9a)
- Not implementing bulk operations — backlog after 56.x complete
- Not migrating any UI logic to keep the legacy app functional in parallel
- Not preserving Quasar Material design — keeping Quasar layout primitives only

## Sections

- **Section A**: File structure + cleanup of legacy code

- **Section F**: Dashboard page (Stats + Kanban + Clusters + Detail Pane)

### C.4 ProjectSelector.vue

In Topbar. Dropdown menu with all projects + current one highlighted.

```vue
<template>
  <q-btn-dropdown flat dense no-icon-animation>
    <template #label>
      <div class="project-selector-label">
        <div class="project-dot" />
        <div class="project-name">{{ currentProject?.name }}</div>
        <div class="project-meta">{{ currentProject?.industry }} · {{ articleCount }}</div>
      </div>
    </template>
    
    <q-list>
      <q-item
        v-for="project in projects"
        :key="project.id"
        clickable
        :active="project.slug === currentProjectSlug"
        @click="switchProject(project.slug)"
      >
        <div class="project-row">
          <div>
            <div class="project-name">{{ project.name }}</div>
            <div class="project-meta">{{ project.industry }}</div>
          </div>
          <div class="project-activity">
            <span v-if="project.activity.runningCount > 0" class="badge-live">
              {{ project.activity.runningCount }}
            </span>
            <span v-if="project.activity.failedLast24h > 0" class="badge-urgent">
              {{ project.activity.failedLast24h }}
            </span>
            <span class="cost-mini mono">€{{ project.stats.costThisMonthEur.toFixed(2) }}</span>
          </div>
        </div>
      </q-item>
    </q-list>
  </q-btn-dropdown>
</template>

<script lang="ts">
import { defineComponent } from "vue";
import { useQuery } from "@tanstack/vue-query";
import { useProjectStore } from "@/stores/project";

export default defineComponent({
  name: "ProjectSelector",
  setup() {
    const projectStore = useProjectStore();
    
    // Fetch projects via TanStack Query, refetches every 30s for activity counts
    const { data: projects } = useQuery({
      queryKey: ["projects", "picker"],
      queryFn: () => apiClient.projects.getPicker(),
      refetchInterval: 30_000,
    });
    
    return { projectStore, projects };
  },
  computed: {
    currentProjectSlug(): string {
      return this.projectStore.currentSlug;
    },
    currentProject(): Project | null {
      return this.projects?.find(p => p.slug === this.currentProjectSlug) ?? null;
    },
    articleCount(): number {
      return this.currentProject?.stats?.articleCount ?? 0;
    },
  },
  methods: {
    switchProject(slug: string): void {
      this.projectStore.setCurrentSlug(slug);
      this.$router.push(`/projects/${slug}/dashboard`);
    },
  },
});
</script>
```

Uses `useQuery` from `@tanstack/vue-query` — fetched once + auto-refetched every 30s for fresh activity counts.

### E.4 Pipeline Events Store (`stores/pipeline-events.ts`)

Holds the SSE-event stream + derived state. The composable `usePipelineEvents` (next section) populates this store.

```typescript
import { defineStore } from "pinia";
import type { PipelineEvent } from "@/types/ui";

interface PipelineEventsState {
  events: PipelineEvent[];        // newest first, capped at 100
  connectionStatus: "disconnected" | "connecting" | "connected" | "error";
  lastEventAt: string | null;
}

/**
 * Buffers SSE pipeline events for the active project.
 * UI components query this store to render real-time updates.
 * Events older than 100 are pruned.
 */
export const usePipelineEventsStore = defineStore("pipeline-events", {
  state: (): PipelineEventsState => ({
    events: [],
    connectionStatus: "disconnected",
    lastEventAt: null,
  }),
  actions: {
    addEvent(event: PipelineEvent): void {
      this.events.unshift(event);
      if (this.events.length > 100) {
        this.events.length = 100;
      }
      this.lastEventAt = event.timestamp;
    },
    setConnectionStatus(status: PipelineEventsState["connectionStatus"]): void {
      this.connectionStatus = status;
    },
    clearEvents(): void {
      this.events = [];
    },
  },
});
```

### E.5 usePipelineEvents composable

Connects to SSE, pushes events into store. Auto-reconnects on failure.

```typescript
// apps/web/src/composables/usePipelineEvents.ts
import { ref, watch, onMounted, onUnmounted } from "vue";
import { usePipelineEventsStore } from "@/stores/pipeline-events";
import { useProjectStore } from "@/stores/project";
import { useQueryClient } from "@tanstack/vue-query";
import type { PipelineEvent } from "@/types/ui";

/**
 * SSE subscription to pipeline events for the currently selected project.
 * Pushes events into the pipeline-events store and invalidates relevant
 * TanStack Query caches so dependent UI re-fetches.
 */
export function usePipelineEvents() {
  const eventsStore = usePipelineEventsStore();
  const projectStore = useProjectStore();
  const queryClient = useQueryClient();
  
  let eventSource: EventSource | null = null;
  let reconnectTimer: ReturnType<typeof setTimeout> | null = null;
  
  const connect = () => {
    cleanup();
    
    if (!projectStore.currentSlug) return;
    
    eventsStore.setConnectionStatus("connecting");
    
    const url = `/api/projects/${projectStore.currentSlug}/pipeline-events`;
    eventSource = new EventSource(url, { withCredentials: true });
    
    eventSource.addEventListener("connected", () => {
      eventsStore.setConnectionStatus("connected");
    });
    
    const handlers: Record<string, (e: MessageEvent) => void> = {
      "pipeline.started": handleEvent,
      "pipeline.step.started": handleEvent,
      "pipeline.step.completed": handleEvent,
      "pipeline.completed": handleEvent,
      "pipeline.failed": handleEvent,
      "pipeline.cancelled": handleEvent,
      "cluster.status.changed": handleClusterEvent,
    };
    
    for (const [eventType, handler] of Object.entries(handlers)) {
      eventSource.addEventListener(eventType, handler);
    }
    
    eventSource.onerror = () => {
      eventsStore.setConnectionStatus("error");
      // Reconnect after 5s
      reconnectTimer = setTimeout(connect, 5000);
    };
  };
  
  const handleEvent = (e: MessageEvent) => {
    const event = JSON.parse(e.data) as PipelineEvent;
    eventsStore.addEvent(event);
    
    // Invalidate caches that depend on pipeline state
    queryClient.invalidateQueries({ queryKey: ["pipeline-runs"] });
    queryClient.invalidateQueries({ queryKey: ["cost-summary"] });
    
    // If this event is about a specific run, invalidate its detail
    if ("runId" in event) {
      queryClient.invalidateQueries({ queryKey: ["pipeline-run-detail", event.runId] });
    }
  };
  
  const handleClusterEvent = (e: MessageEvent) => {
    const event = JSON.parse(e.data);
    eventsStore.addEvent(event);
    queryClient.invalidateQueries({ queryKey: ["cluster-generation-status", event.clusterId] });
  };
  
  const cleanup = () => {
    if (eventSource) {
      eventSource.close();
      eventSource = null;
    }
    if (reconnectTimer) {
      clearTimeout(reconnectTimer);
      reconnectTimer = null;
    }
    eventsStore.setConnectionStatus("disconnected");
  };
  
  onMounted(connect);
  onUnmounted(cleanup);
  
  // Reconnect when project changes
  watch(() => projectStore.currentSlug, () => {
    eventsStore.clearEvents();
    connect();
  });
  
  return {
    connectionStatus: () => eventsStore.connectionStatus,
    reconnect: connect,
  };
}
```

**Key behaviors**:
- One SSE connection per session (instantiated in DashboardPage, persists across views via shared composable)
- Auto-reconnect on error after 5s
- Project switch → close + reconnect
- Each event invalidates relevant TanStack Query caches → triggers refetch → UI updates

## Decisions Made

**Decision 1: Big-bang replace, no legacy/v2 coexistence.**
Solo-dev, no external users, no parallel maintenance overhead. Per user direction: "wir können lieber nach effizienz optimieren".

**Decision 2: Quasar layout primitives only, custom glassmorphism components.**
Quasar's q-dialog, q-list, q-item are reused. All UI styling done via custom components matching mockup.

**Decision 3: TanStack Query for API data, Pinia for UI state, SSE for real-time.**
Clean separation. TanStack handles cache, dedup, invalidation. Pinia for cross-component state (selected run, filters). SSE triggers query invalidations.

**Decision 4: Vue Options API per user memory edit #1.**
All components use Options API. Composables use Composition API (Vue convention).

**Decision 5: Inter for body, JetBrains Mono for code/IDs/timestamps.**
Inter chosen by user. JetBrains Mono adds tech personality where mono is semantically appropriate.

**Decision 6: One SSE connection per session, instantiated in DashboardPage.**
Connection persists when navigating away/back to dashboard. Project switch closes + reconnects.

**Decision 7: 100-event buffer cap.**
Prevents memory issues on long sessions. Older events pruned from store but the underlying data is queryable via API if needed.

**Decision 8: Auto-reconnect SSE after 5s on failure.**
Balances UX (recovery) with server load (not hammering).

**Decision 9: 60s polling backup for activity feed.**
Belt-and-suspenders pattern. If SSE fails silently, polling keeps UI fresh.

**Decision 10: Cmd+K search only, no quick-actions (Q9a).**
MVP scope. Quick-actions added when use cases clear.

**Decision 11: Mobile: master-detail slide pattern (Q6a).**
iOS-native pattern. Familiar to users. Better than stacked-pane on small screens.

**Decision 12: Magic-link auth unchanged (Q7a).**
Theme 56 not scope for auth changes.

**Decision 13: No bundle-size limit enforced in 56.1.**
Document baseline after implementation. Tighten in Phase E if needed.

**Decision 14: Accessibility ≥ 90 Lighthouse, no separate WCAG audit.**
Pragmatic threshold. Solo-dev usage. WCAG full audit if Marcel onboards external users.

**Decision 15: All component files use `defineComponent` + Options API per memory #1.**
Memory rules: Options API, TypeScript strict, English JSDoc, arrow-function data shorthand.
