## 3. Schema Location Decision

Marcel: "Discovery soll evaluieren".

### 3.1 Options

**Option A — Single file `packages/shared/format-types/registry.ts`:**

```typescript
// All 5 format-types in one file
import { z } from 'zod';

export const FORMAT_TYPES = {
  top_n_comparison: {
    family: 'A',
    configSchema: z.object({
      categorySlug: z.string(),
      topN: z.number().int().min(3).max(10),
      rankingSource: z.enum(['manual', 'auto-by-stars', 'llm-curated']),
    }),
    briefGenerator: 'top-n-comparison-brief-generator',
    eligibleTemplates: ['comparison-grid-3', 'comparison-grid-5', 'comparison-grid-10'],
  },
  head_to_head: { ... },
  // ... etc
};
```

**Pros:** Single file, easy to grep, low overhead V1 size
**Cons:** File grows linearly with format-types (5 → 14 → 30?), per-format-type config-schemas can be 30-60 lines each → file → 500+ lines fast

**Option B — One file per format-type:**

```
packages/shared/src/format-types/
├── top-n-comparison.ts        # exports schema, eligibleTemplates, etc.
├── head-to-head.ts
├── story-arc-clickbait.ts
├── lifestyle-listicle.ts
├── opinion-recommendation.ts
├── types.ts                    # shared FormatTypeDefinition interface
└── registry.ts                 # imports all, builds FORMAT_TYPES map
```

**Pros:** Scales linearly, each format-type owned in isolated file, easy to add v1.5/v2 types
**Cons:** More import-overhead (`registry.ts` imports all 5), some duplication if schemas share common fields

**Option C — Hybrid: shared types + per-format-type schemas + auto-discovery:**

```
packages/shared/src/format-types/
├── types.ts                    # FormatTypeDefinition + shared schema fragments
├── schemas/
│   ├── top-n-comparison.ts
│   ├── head-to-head.ts
│   └── ...
└── registry.ts                 # exports getFormatType(type) + lazy-loads from schemas/
```

**Pros:** Cleanest separation, lazy-load possible, future-proof
**Cons:** Over-engineered V1, lazy-loading not really needed in non-edge-runtime

### 3.2 Recommendation: **Option B — One file per format-type**

Reasoning:

1. **Scales linearly mit format-type-additions** — wenn v1.5 + v2 alle 14 types adden, jeder file bleibt klein
2. **65.5+65.6 import per-format-type** — brief-generators und template-eligibility können specifisches schema importieren ohne whole registry
3. **Settings-UI Form-Engine (65.11)** kann per-format-type schemas lazy-laden für form-rendering
4. **Matches existing pattern** — Engine Day 4 hat `RENDER_FN_MAP` pattern, ist aber für 5 templates noch one file; bei 14 wäre das fragmentation-würdig

**Trade-off accepted:** Slight import-overhead in `registry.ts` (5 imports), is fine for V1.

## 6. Hook-Picker Implementation

### 6.1 Architecture

**File:** `apps/api/src/lib/hook-library/pick-hook.ts`

```typescript
import { listLruEligibleHooks, markHookUsed } from '@marketing-auto/db/helpers/hook-templates-read';
import { callLlmWithSchema } from '@marketing-auto/api/lib/llm';
import { z } from 'zod';

export interface PickHookInput {
  projectId: string;
  formatType: string;
  language: 'de' | 'en';
  contentContext: {
    toolIds?: string[];
    professionPool?: string[];
    lifeArea?: string;
    narrative_intent?: string;
  };
}

export interface PickedHook {
  hookId: string;
  pattern: string;
  variables: string[];
  reasoning: string;
}

const HOOK_PICKER_OUTPUT_SCHEMA = z.object({
  pickedHookId: z.string().uuid(),
  reasoning: z.string().min(10).max(500),
});

export async function pickHook(input: PickHookInput): Promise<PickedHook | null> {
  // 1. List 10 LRU-eligible hooks for this format-type + language
  const candidates = await listLruEligibleHooks({
    projectId: input.projectId,
    formatType: input.formatType,
    language: input.language,
    limit: 10,
  });
  
  if (candidates.length === 0) return null;
  
  // 2. LLM-call: pick top-1 with reasoning
  const result = await callLlmWithSchema({
    prompt: buildHookPickerPrompt(candidates, input.contentContext),
    schema: HOOK_PICKER_OUTPUT_SCHEMA,
    purpose: 'hook-picker',  // for cost-tracking per Memory D17
  });
  
  const picked = candidates.find(c => c.id === result.pickedHookId);
  if (!picked) {
    // LLM hallucinated an ID — fallback to first candidate
    return {
      hookId: candidates[0].id,
      pattern: candidates[0].pattern,
      variables: candidates[0].variables,
      reasoning: 'LLM-hallucination fallback to first LRU candidate',
    };
  }
  
  // 3. Mark hook used
  await markHookUsed(picked.id);
  
  return {
    hookId: picked.id,
    pattern: picked.pattern,
    variables: picked.variables,
    reasoning: result.reasoning,
  };
}
```

### 6.2 LLM-Picker Prompt Pattern

```typescript
function buildHookPickerPrompt(candidates: HookTemplate[], context: ContentContext): string {
  return `
You are picking the best narrative hook for a social-media carousel.

Content context:
- Tools featured: ${context.toolIds?.join(', ') ?? 'none'}
- Profession pool: ${context.professionPool?.join(', ') ?? 'n/a'}
- Life area: ${context.lifeArea ?? 'n/a'}
- Narrative intent: ${context.narrative_intent ?? 'engagement-driven'}

Eligible hooks (pick best fit):
${candidates.map((c, i) => `${i + 1}. [${c.id}] "${c.pattern}" (last used: ${c.last_used_at ?? 'never'}, count: ${c.usage_count})`).join('\n')}

Pick the hook that:
1. Best matches the content context
2. Hasn't been used recently (LRU-preferential)
3. Feels least AI-generic — prefer fresh-sounding patterns

Return JSON:
{
  "pickedHookId": "<uuid>",
  "reasoning": "<why this hook fits>"
}
`;
}
```

### 6.3 Hook-Render (Variable Substitution)

**File:** `apps/api/src/lib/hook-library/render-hook.ts`

```typescript
export function renderHook(pattern: string, variables: Record<string, string>): string {
  return pattern.replace(/\{(\w+)\}/g, (match, key) => {
    if (variables[key] === undefined) {
      throw new Error(`Missing variable '${key}' for hook pattern: ${pattern}`);
    }
    return variables[key];
  });
}

// Example:
// pattern: "Ich habe meinen {profession}-Job verloren — wegen {tool}"
// variables: { profession: "Texter", tool: "Claude" }
// result: "Ich habe meinen Texter-Job verloren — wegen Claude"
```

## 9. Multi-Domain Considerations

`hook_templates` ist project-scoped per 65.1. BK kommt später mit eigenen hooks:
- BK Solar-context: "Ich habe meine Energiekosten halbiert — mit {balconyPower}"
- Toolwiki AI-context: "Ich habe meinen Texter-Job verloren — wegen {tool}"

**Format-types-registry ist global (lebt in packages/shared)** — alle Projekte teilen dieselben format-types. BK könnte später eigene format-types adden (z.B. `installation_guide` für Solar-DIY), aber das ist eigene Sub-Spec.

**Hook-Picker ist project-scoped via `pickHook({projectId})`** — Toolwiki's hooks unsichtbar für BK und vice versa.

## 10. Risk Analysis

| Risk | Severity | Mitigation |
|---|---|---|
| LLM hallucinates non-existent hook-id | Medium | Fallback to first LRU candidate (Section 6.1) |
| Hooks zu repetitiv (V1 nur 10 pro type/lang) | High | Marcel-curation Disziplin im Seed-Migration + V1.1 Settings-UI für expansion |
| Hook-Picker LLM-cost adds up bei high volume | Low | ~14 posts/month × $0.005 per call = $0.07/month — vernachlässigbar |
| Variable substitution failt bei missing var | Low | Throws explicit error mit pattern + missing-var name |
| Family A format-types accidentally call hook-picker | Low | `definition.needsHooks` gate at brief-generator (65.5) |
| Format-type schemas drift from briefs' actual content-shape | Medium | Schema-tests + 65.5 brief-generator-tests catch mismatches |
| Family B "AI-generic" feel | High | Style-variants in 65.8 + curated hooks + persona-anchoring; Master-Spec Risk #1 |

## 14. Deviations from Discovery

Recorded for the implementation record — none changed user-visible behaviour.

1. **Migration number**: spec said `0117`, actual = **`0116`** (last applied at start of 65.4 was 0115; 65.2 + 65.3 haven't migrated yet).
2. **LLM provider (Q1)**: spec hypothesised "same as existing brief-pipeline" (Opus 4.7); resolved as **Haiku 4.5 + `jsonMode: true`**. Haiku supports assistant prefill (Sonnet 4.6 / Opus 4.7 reject it), classification-style "pick 1 of 10" task is well within Haiku's 4096-token cap, and cost is ~10× cheaper.
3. **`callLlmWithSchema` helper does not exist** in the codebase. The spec's §6.1 sketch referenced it; `pickHook` uses `anthropic.messages()` directly + `HOOK_PICKER_SCHEMA.safeParse(result.json)` for structured output. This matches the convention in `cluster-creator/propose.ts`, `schema-extension/steps/detect-rich-types.ts`, `topic-sources/trend-discovery/synthesize.ts`.
4. **Test layout**: spec §8 sketched 5 separate `<format-type>.test.ts` files. Actual = single combined [`packages/shared/test/format-types/v1-definitions.test.ts`](../packages/shared/test/format-types/v1-definitions.test.ts) (22 cases). Each per-format-type schema test is short; splitting was unnecessary fragmentation.
5. **Seed authoring**: spec §5.1 showed 10 sample story_arc_clickbait DE hooks + placeholder `// 8 more` markers for the other 5 buckets. Actual = full 60-hook seed authored inline in [migration 0116](../packages/db/drizzle/0116_hook_templates_seed.sql). Marcel can edit the SQL before merge.
6. **`defaultEndSlides: string[]`** added to `FormatTypeDefinition` interface alongside `needsHooks: boolean`. The discovery's §4 examples had the field on each definition but didn't formally extend the 65.1 skeleton interface — now both are first-class members.
7. **Per-format-type schemas re-exported via the barrel** `index.ts` so test files + 65.5 brief-generators can `import { topNComparisonConfigSchema }` directly from `@marketing-auto/shared/format-types`. Discovery sketched the registry-only barrel.
8. **`HookRenderError` named class** instead of a bare `throw new Error(...)` — surfaces the offending `pattern` + `missingVariable` for telemetry/UI.

### Non-deviations worth noting
- The `Object.assign(FORMAT_TYPES, {...})` registration was hinted at in 65.1's `registry.ts` JSDoc; preserved verbatim.
- The HTTP boundary validator `validateFormatConfig` from 65.1 unchanged — the registry being populated is enough; no API edit needed.

### Out-of-scope discovery
- [`packages/pipelines/src/cluster-creator/propose.ts:53`](../packages/pipelines/src/cluster-creator/propose.ts:53) calls `claude-opus-4-7` with `jsonMode: true`, which violates the root CLAUDE.md DO-NOT rule (Opus rejects assistant-prefill). Not touched in 65.4; either the model behaviour changed, the rule is stale, or it's an in-flight bug. Flag for a separate audit.
