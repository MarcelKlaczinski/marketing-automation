### 3.4 React-in-Vue End-Slide Preview (Marcel-Decision)

**Architectural Pattern: Option β — Manual React mount via Vue ref + lazy import**

Reasoning (vs other options):
- **Option α (@vue/vue3-react bridge):** Library overhead + maintenance burden für 1 component
- **Option γ (iframe):** Style-isolation good, communication awkward, slow
- **Option β (manual mount):** Minimal overhead, direct control, lazy-loadable

**Implementation:**

```vue
<!-- apps/web/src/components/settings/end-slides/EndSlideLivePreview.vue -->
<template>
  <div class="end-slide-preview-container">
    <div ref="reactMountPoint" class="end-slide-preview-mount" />
    <div v-if="loading" class="preview-loading">Loading preview...</div>
    <div v-if="error" class="preview-error">{{ error }}</div>
  </div>
</template>

<script lang="ts">
import type { EndSlideData } from '@marketing-auto/social/end-slide-components/types';
import type { Root } from 'react-dom/client';

export default {
  props: {
    endSlideData: { type: Object as PropType<EndSlideData>, required: true },
    theme: { type: String as PropType<'light' | 'dark'>, default: 'light' },
  },
  data: () => ({
    reactRoot: null as Root | null,
    loading: true,
    error: null as string | null,
  }),
  async mounted() {
    try {
      // Lazy-load React + RenderEndSlide bundle
      const [{ createRoot }, { RenderEndSlide }] = await Promise.all([
        import('react-dom/client'),
        import('@marketing-auto/social/end-slide-components/RenderEndSlide'),
      ]);
      
      const React = await import('react');
      
      this.reactRoot = createRoot(this.$refs.reactMountPoint as HTMLElement);
      this.reactRoot.render(
        React.createElement(RenderEndSlide, {
          data: this.endSlideData,
          theme: this.theme,
        }),
      );
      
      this.loading = false;
    } catch (err) {
      this.error = `Failed to load preview: ${err.message}`;
      this.loading = false;
    }
  },
  watch: {
    endSlideData: {
      handler() { this.rerenderReact(); },
      deep: true,
    },
    theme() { this.rerenderReact(); },
  },
  beforeUnmount() {
    this.reactRoot?.unmount();
  },
  methods: {
    async rerenderReact() {
      if (!this.reactRoot) return;
      const React = await import('react');
      const { RenderEndSlide } = await import('@marketing-auto/social/end-slide-components/RenderEndSlide');
      
      this.reactRoot.render(
        React.createElement(RenderEndSlide, {
          data: this.endSlideData,
          theme: this.theme,
        }),
      );
    },
  },
};
</script>
```

**Bundle-strategy:**

- Vite-config: dynamic-import chunks für React + Remotion → separate bundle
- Bundle-size estimate: ~200KB gzipped (React 18 + Remotion-core + RenderEndSlide subset)
- Lazy-load only when EndSlideEditModal opens
- Cache after first load (browser cache)

**dependencies adds:**

```json
{
  "dependencies": {
    "react": "^18.0.0",
    "react-dom": "^18.0.0"
  }
}
```

(Plus remotion already in monorepo via packages/social.)

**TypeScript boundary:**

`@marketing-auto/social/end-slide-components/RenderEndSlide` exports React component + types. Web app imports types via `/types` subpath (no JSX, no runtime React-dependency for type-checking). Lazy-import does the runtime-React-loading.

```typescript
// apps/api/src/lib/recurring-content/budget-check.ts

export async function checkBudgetAvailable(input: {
  projectId: string;
  budgetType: 'dry_run' | 'recurring_content_total';
  expectedCostCents: number;
}): Promise<{ allowed: boolean; consumed: number; limit: number }> {
  const now = new Date();
  const yyyymm = parseInt(`${now.getFullYear()}${(now.getMonth() + 1).toString().padStart(2, '0')}`);
  
  const budget = await getBudget(input.projectId, input.budgetType);
  
  // Reset if new month
  if (budget.current_month !== yyyymm) {
    await resetBudgetForNewMonth(input.projectId, input.budgetType, yyyymm);
    budget.current_month_consumed_cents = 0;
  }
  
  const projectedConsumption = budget.current_month_consumed_cents + input.expectedCostCents;
  
  return {
    allowed: projectedConsumption <= budget.monthly_limit_cents,
    consumed: budget.current_month_consumed_cents,
    limit: budget.monthly_limit_cents,
  };
}
```

```typescript
// POST /api/projects/:slug/recurring-content/definitions/:id/dry-run
export async function dryRunDefinition(req, res) {
  const { id } = req.params;
  const project = await getProjectFromSlug(req.params.slug);
  
  // Pre-check budget
  const expectedCost = await estimateDryRunCost(id); // ~20-30 cents (~0.20-0.30 €)
  const budgetCheck = await checkBudgetAvailable({
    projectId: project.id,
    budgetType: 'dry_run',
    expectedCostCents: expectedCost,
  });
  
  if (!budgetCheck.allowed) {
    return res.status(429).json({
      error: 'dry-run-budget-exceeded',
      consumed: budgetCheck.consumed,
      limit: budgetCheck.limit,
      message: `Monthly dry-run budget €${budgetCheck.limit / 100} consumed. Wait until next month.`,
    });
  }
  
  // Execute dry-run
  const result = await generateBriefForRecurringDefinition({ ..., dryRun: true });
  
  // Record actual cost post-execution
  await recordBudgetConsumption({
    projectId: project.id,
    budgetType: 'dry_run',
    actualCostCents: result.llmCostCents,
  });
  
  return res.json(result);
}
```

**Cooldown Gate:**

```typescript
// In brief-generator's skip-handler:
async function handleBriefSkip(definition: RecurringContentDefinition, skipReason: string) {
  const now = new Date();
  const cooldownMs = 24 * 60 * 60 * 1000; // 24h
  
  if (definition.lastSkipNotifiedAt) {
    const elapsedMs = now.getTime() - definition.lastSkipNotifiedAt.getTime();
    if (elapsedMs < cooldownMs) {
      // Within cooldown, skip notification
      logger.debug('Skip notification suppressed (cooldown)', { definitionId: definition.id });
      return;
    }
  }
  
  // Notify + update timestamp
  await notifyMarcelOfSkip({ definitionId: definition.id, reason: skipReason });
  await updateDefinition(definition.id, { lastSkipNotifiedAt: now });
}
```

### Discovered during V1.5c implementation

- **`paths` doesn't merge across tsconfig inheritance** — when apps/web/tsconfig.json adds a `paths` map, it COMPLETELY OVERRIDES the inherited `.quasar/tsconfig.json` paths instead of merging. The Quasar-generated `#q-app/wrappers` + `pages/*` + 12 other auto-paths broke immediately. Workaround: keep `paths` out of `apps/web/tsconfig.json` entirely; use Vite alias for runtime resolution + `@ts-expect-error` for typecheck. Documented as new `apps/web/CLAUDE.md` DO-NOT.
- **lightningcss is stricter than esbuild** — Vite 8 defaults to lightningcss for CSS minification, which rejects q-calendar's chained `:before.X:before` pseudo-elements (the `.q-range-hover:before.q-range-first:before` selector). The pre-Vite-8 default (esbuild) tolerates this. Workaround: explicit `build.cssMinify = "esbuild"` in quasar.config.ts `extendViteConf`. Inline rationale comment added.
- **`@quasar/quasar-ui-qcalendar` is NOT installed by default** — Spec 65.11 V1 implementor noted "q-calendar is NOT installed" but V1.5b deferred without re-checking. Confirmed during V1.5c install: had to `bun add @quasar/quasar-ui-qcalendar --cwd apps/web`. Package version: 4.1.2.
- **Cross-package `.tsx` imports work via Vite alias + esbuild JIT** — the path `apps/web → packages/social/src/end-slide-components/*.tsx → ../../brand-tokens/derive.ts → packages/shared/...` chain compiles cleanly at Vite build time despite the cross-package boundary. esbuild handles `.ts`/`.tsx` extensions in import specifiers natively. No `allowImportingTsExtensions` config needed on apps/web side.
- **Vue Options API + lazy-imported React component** — assigning a React component to `data` requires marking it non-reactive (`_reactRoot: null as ReactRootLike | null` underscore-prefix convention from apps/web/CLAUDE.md). Don't store the entire React `Root` object in reactive state — narrow to `{render, unmount}` via `as unknown as ReactRootLike` cast.

### Reusable patterns surfaced

- **Vite-alias + ts-expect-error single-component cross-package exception** — when one component needs a `@marketing-auto/*` import for runtime but apps/web shouldn't carry a `paths` map (breaks inherited Quasar paths), the canonical pattern is: (1) Vite alias in `quasar.config.ts` `extendViteConf` for runtime resolution, (2) `@ts-expect-error` + inline justification on the dynamic import call site, (3) narrow the lazy-imported module surface via `as unknown as { … }` to the specific exports used. Documented as new DO-NOT in apps/web/CLAUDE.md.
- **Heavy SDK browser shim pattern** — when a JS package has a big browser bundle but only a tiny API surface is actually used (Remotion's `AbsoluteFill` = 50 lines vs. 5MB Remotion runtime), write a 50-line shim in `apps/web/src/lib/<sdk-name>-shim/` and alias the SDK name in Vite. Reusable for any future heavy SDK we only use a small piece of (Chart.js full vs. just bar, Markdown-it vs. just inline parser, etc.).
- **`<component :is="formComponent">` registry dispatch** — when N variant forms share a slot but each has its own per-format Zod-validated payload, register them in a `Record<string, Component>` map keyed by the discriminator field; the `<component :is>` switches at runtime; unregistered keys fall back to a generic JSON editor (forward-compat for new variants that ship before their form does). Pattern reusable for: cluster-creator form variants, future content-pillar editors, batch-action confirmation forms.
- **Pinia draft store + `<router-view>` wizard child routes** — multi-step wizards with URL-state + draft auto-save share the same pattern: Pinia store with `LocalStorage` plugin (TTL via `lastSavedAt` stamp), `loadDraft(slug)` idempotent hydrate, `patchDraft` synchronous-persist, `markStepReached` for forward-nav gating. The wizard layout owns the progress bar + restore-banner; children are pure step pages. Forward-nav permission via `furthestStep` integer in the store.
- **q-calendar `#day` slot per-day rendering** — when a calendar surface needs per-day chips/markers (run schedules, deadlines, deploys, etc.), the canonical pattern is: pre-compute `Record<YYYY-MM-DD, Entry[]>` map in a computed property; render via `<template #day="{ scope }">` + slot lookup. Always custom-format weekday labels via `weekdayFormat` prop (q-calendar's default is 3-letter EN).
