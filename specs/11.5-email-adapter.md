# Spec 11.5: Email Adapter (Nodemailer + Gmail SMTP)

**Phase:** 2 (Cold-Start for KI-Wissensraum) — small refactor spec
**Estimated Effort:** ½ day
**Dependencies:** Spec 00, Spec 01, Spec 03 (cost tracker), Spec 04 (magic link auth — we replace its email.ts), Spec 11 (anthropic adapter — pattern reference)
**Status:** Ready for implementation
**Recommended Model:** Sonnet 4.6

---

## Goal

Refactor the raw `fetch()` call to Resend's API in `apps/api/src/lib/email.ts` (a documented Phase-1 deviation) into a proper typed adapter at `packages/adapters/email/`. The adapter:

1. Uses **Nodemailer + Gmail SMTP** as the transport — no third-party email service, no Resend account, no extra API key to manage. Only requires a Gmail account with 2FA + an App Password.
2. Follows the Spec 11 pattern: typed entry points, cost-tracker integration, project-scoped operations
3. Handles the dev-fallback case (no SMTP credentials set → log to console) cleanly
4. Tracks email sending in `cost_logs` (zero-cost entries — Gmail SMTP is free)
5. Exposes a typed `sendEmail()` and a specialized `sendMagicLinkEmail()` that consumes the generic API

This is a **small refactor**, but it's the right time to do it: before Phase 2 grows more raw-fetch debt.

**Why Nodemailer + Gmail and not Resend?** Marcel chose to avoid yet another third-party account dependency. Gmail SMTP works fine for the actual use case (1-3 magic-link logins per day, plus future cost alerts), is free, and the per-day-cap of 500 emails is far above our needs. The primary trade-off — Gmail's deliverability is not as battle-hardened as a dedicated provider — is acceptable for a small internal tool. **Production migration path is built in**: the adapter abstracts SMTP, so swapping to a different provider (SES, Mailgun, Resend) later is a config change, not a code change.

## Non-Goals

- No React Email integration (HTML strings are sufficient for our 1-2 templates)
- No bounce/complaint webhook handling
- No batch sending — one email at a time
- No multi-recipient broadcast — magic links go to one person at a time
- No tenant-scoped sender domains (one configured Gmail account for all platform emails)
- No OAuth 2.0 flow for Gmail — App Password is simpler and sufficient for our scale (OAuth would require a Google Cloud project + refresh-token handling)
- No newsletter/marketing emails — those go through Kit (ConvertKit) directly from the Astro frontend, not through this adapter

## Detailed Implementation

### Setup: Gmail App Password

Marcel needs to do this **once**:

1. Go to https://myaccount.google.com/security
2. Enable **2-Step Verification** if not already on
3. After 2FA is on, scroll back to Security → search "**App passwords**" (or visit https://myaccount.google.com/apppasswords directly)
4. Create a new App Password:
  - App: "Mail"
  - Device: "Marketing Automation Platform" (or any name — for your own bookkeeping)
5. Google shows a 16-character password (with spaces, e.g. `abcd efgh ijkl mnop`). Copy it **without spaces**: `abcdefghijklmnop`. You will not see it again.
6. Add to `.env`:
   ```
   SMTP_USER=marcel@gmail.com
   SMTP_APP_PASSWORD=abcdefghijklmnop
   SMTP_FROM_NAME=Marketing Automation
   ```

**Important caveat**: Gmail will **always** rewrite the `From:` header to match the authenticated user. If you put `from: "noreply@example.com"` in code, Gmail silently overrides it to `marcel@gmail.com`. The `SMTP_FROM_NAME` is the *display* name only (`"Marketing Automation" <marcel@gmail.com>`).

If you ever want a custom from-address, you'd need Google Workspace + the `GmailWorkspace` Nodemailer service, or switch to AWS SES / Mailgun.

```typescript
  html: string;

  text?: string;

  replyTo?: string;

export type SendEmailResult = {
  /** Nodemailer's messageId (the SMTP server's accepted ID). */
  messageId: string;
  /** Whether the call actually went through SMTP (false in dev-fallback mode). */

  to: string;
  verifyUrl: string;
  expiresInMinutes: number;
  /** Optional: attribute to a project. Defaults to platform-wide. */
  projectId?: string;
};

export class EmailError extends Error {
  constructor(message: string, public readonly cause?: unknown) {
    super(message);
    this.name = "EmailError";
  }
```

### The Adapter

`packages/adapters/email/src/client.ts`:

```typescript
import nodemailer, { type Transporter } from "nodemailer";
import { getEnv, createLogger } from "@marketing-auto/shared";
import { track } from "@marketing-auto/cost-tracker";
import {
  type SendEmailInput,
  type SendEmailResult,
  type SendMagicLinkInput,
  EmailError,
} from "./types.ts";

const log = createLogger("email");

let _transporter: Transporter | null = null;

function getTransporter(): Transporter | null {
  if (_transporter) return _transporter;
  const env = getEnv();
  if (!env.SMTP_USER || !env.SMTP_APP_PASSWORD) {
    return null;  // dev fallback mode
  }
  _transporter = nodemailer.createTransport({
    host: env.SMTP_HOST,
    port: env.SMTP_PORT,
    secure: env.SMTP_PORT === 465,  // true for 465 (SSL), false for 587 (STARTTLS)
    auth: {
      user: env.SMTP_USER,
      pass: env.SMTP_APP_PASSWORD,
    },
  });
  return _transporter;
}

/**
 * Synthetic project ID for platform-wide emails (auth, system alerts).
 * One-time seeded by `bun --filter @marketing-auto/db seed-platform`.
 */
export const PLATFORM_PROJECT_ID = "00000000-0000-0000-0000-000000000001";

/**
 * Generic transactional send. All emails go through here.
 *
 * Cost tracking: Gmail SMTP is free, so cost_eur = 0. We still write a cost_logs
 * row for visibility ("how many auth emails did we send this week?").
 */
export async function sendEmail(input: SendEmailInput): Promise<SendEmailResult> {
  const env = getEnv();
  const transporter = getTransporter();

  // Dev-fallback: no SMTP creds → log and return synthetic result. NO cost row written.
  if (!transporter) {
    log.warn(
      { to: input.to, subject: input.subject, operation: input.operation },
      "SMTP not configured — email logged to console (dev fallback)",
    );
    console.log(
      `\n📧 Email (would-be-sent) — ${input.subject}\n` +
      `   To: ${input.to}\n` +
      `   ${input.html.slice(0, 200)}${input.html.length > 200 ? "…" : ""}\n`,
    );
    return { messageId: "dev-fallback", delivered: false };
  }

  const projectId = input.projectId ?? PLATFORM_PROJECT_ID;
  // Gmail rewrites the From header anyway, so we just always use SMTP_USER.
  const fromAddress = `"${env.SMTP_FROM_NAME}" <${env.SMTP_USER}>`;

  log.debug({
    projectId,
    operation: input.operation,
    to: input.to,
    subjectLen: input.subject.length,
    htmlLen: input.html.length,
  }, "Sending email via SMTP");

  const result = await track({
    projectId,
    service: "smtp",
    operation: input.operation,
    estimatedCostEur: 0,  // Gmail SMTP is free
    fn: async () => {
      try {
        const info = await transporter.sendMail({
          from: fromAddress,
          to: input.to,
          subject: input.subject,
          html: input.html,
          ...(input.text && { text: input.text }),
          ...(input.replyTo && { replyTo: input.replyTo }),
        });
        return info;
      } catch (e) {
        const errMsg = e instanceof Error ? e.message : String(e);
        log.error({ err: e, to: input.to, operation: input.operation }, "SMTP send failed");
        throw new EmailError(`SMTP send failed: ${errMsg}`, e);
      }
    },
    computeCostEur: () => 0,  // Gmail SMTP is free; we still log a row for observability
    metadata: (info) => ({
      messageId: info.messageId,
      to: input.to,
      subject: input.subject,
      smtpResponse: info.response,  // Gmail's accept response, e.g., "250 2.0.0 OK"
      accepted: info.accepted,
      rejected: info.rejected,
    }),
  });

  log.info(
    { projectId, operation: input.operation, messageId: result.messageId, to: input.to },
    "Email sent",
  );

  return { messageId: result.messageId, delivered: true };
}

/**
 * Magic-link login email. Wraps sendEmail with auth-specific copy.
 * Replaces the raw fetch() implementation in apps/api/src/lib/email.ts.
 */
export async function sendMagicLinkEmail(input: SendMagicLinkInput): Promise<SendEmailResult> {
  const html = `
    <div style="font-family:-apple-system,sans-serif;max-width:480px;margin:24px auto;color:#1a1a1a;">
      <h1 style="font-size:18px;margin:0 0 16px;">Sign in to Marketing Automation</h1>
      <p style="font-size:14px;line-height:1.5;margin:0 0 24px;">
        Click the button below to sign in. This link expires in ${input.expiresInMinutes} minutes
        and can only be used once.
      </p>
      <a href="${input.verifyUrl}"
         style="display:inline-block;background:#0066ff;color:#fff;padding:12px 24px;
                border-radius:6px;text-decoration:none;font-weight:500;">
        Sign in
      </a>
      <p style="font-size:12px;color:#666;margin:24px 0 0;line-height:1.5;">
        If you didn't request this, you can safely ignore this email.<br>
        Or copy this link: <span style="word-break:break-all;">${input.verifyUrl}</span>
      </p>
    </div>
  `.trim();

  const text = [
    "Sign in to Marketing Automation",
    "",
    input.verifyUrl,
    "",
    `This link expires in ${input.expiresInMinutes} minutes.`,
  ].join("\n");

  return sendEmail({
    projectId: input.projectId ?? null,
    operation: "magic-link",
    to: input.to,
    subject: "Sign in to Marketing Automation",
    html,
    text,
  });
}
```

### CLAUDE.md

`packages/adapters/email/CLAUDE.md`:

```markdown
# Email Adapter (Nodemailer + Gmail SMTP)

Transactional email via Gmail SMTP. Replaces the raw fetch() implementation that lived in
apps/api/src/lib/email.ts during Phase 1. Used for magic-link auth and (later) cost alerts.

## Hard Rules

- ALL email sending goes through this adapter — never `nodemailer` directly
- ALL calls require `operation` for cost-log attribution
- For platform-wide emails (auth, system notifications), pass `projectId: null` — the adapter
  attributes to PLATFORM_PROJECT_ID synthetic project
- Dev mode (no `SMTP_USER` or `SMTP_APP_PASSWORD`): adapter logs the email content to console
  and returns `delivered: false` — NO cost tracked, NO error thrown
- Cost is always 0 for Gmail SMTP — entries exist for visibility, not billing

## Production Considerations

- **500 recipients/day cap** on personal Gmail accounts. We send 1-5/day. If we ever blast
  more, we'll exceed it and Gmail will start rejecting.
- **Deliverability**: Gmail's reputation for transactional emails is "good enough for tools".
  If magic links land in spam, the user can find them in their Spam folder. For an internal
  tool with 1-2 users, this is acceptable. For external users at scale, switch to
  Resend/SES/Mailgun.
- **From-address rewrite**: Gmail always rewrites `From:` to the authenticated user. Don't
  bother passing custom `from` — it's silently ignored. Display name (`SMTP_FROM_NAME`) IS
  honored.

## Migration Path

If we ever outgrow Gmail (volume, deliverability, or branded sender domain):

1. Sign up with new provider (Resend, SES, Mailgun)
2. Update `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_APP_PASSWORD` in `.env`
3. Done — adapter code doesn't change. SMTP is the universal interface.

If switching to a non-SMTP provider (e.g., Resend's HTTP API), refactor `client.ts`'s
`sendEmail()` internals only. Public API stays the same.

## Common Mistakes

- DO NOT pass `to: string[]` — multi-recipient is not supported
- DO NOT skip the `text` fallback — Gmail's deliverability scoring penalizes HTML-only
- DO NOT use `from: "..."` per-call — Gmail rewrites it anyway
- DO NOT call sendEmail() in tight loops — Gmail rate-limits aggressive senders to ~20/sec
- DO NOT use a personal Gmail you also use for important conversations — bot-like behavior
  could trigger Google's security flags. Consider a dedicated `marcel-bot@gmail.com`.
```

```typescript
#!/usr/bin/env bun
/**
 * One-time seed: creates the synthetic "platform" project that owns
 * cost_logs from non-tenant operations (auth emails, system alerts).
 *
 * Idempotent — safe to run multiple times.
 */
import { eq } from "drizzle-orm";
import { db, projects } from "../index.ts";

const PLATFORM_PROJECT_ID = "00000000-0000-0000-0000-000000000001";

const [existing] = await db
  .select({ id: projects.id })
  .from(projects)
  .where(eq(projects.id, PLATFORM_PROJECT_ID))
  .limit(1);

if (existing) {
  console.log("ℹ️  Platform project already exists");
  process.exit(0);
}

await db.insert(projects).values({
  id: PLATFORM_PROJECT_ID,
  slug: "_platform",
  name: "Platform (synthetic — not a real tenant)",
  industry: "other",
  pipelineTemplate: "educational",  // value doesn't matter — never runs pipelines
  costLimits: { daily: { smtp: 0 }, monthly: { smtp: 0 } },
});

console.log(`✅ Platform project created (id: ${PLATFORM_PROJECT_ID})`);
process.exit(0);

```

## Open Questions / Decisions Made

**Decision 1: Nodemailer 6.9.x.**
Latest stable, well-maintained, native Bun-compatible. Comes with `@types/nodemailer` for full TypeScript support.

**Decision 2: Gmail App Password, not OAuth 2.0.**
OAuth requires a Google Cloud project, refresh-token storage, periodic token refresh logic. App Password is one credential, no rotation needed (until you change your Google password). For a 1-2 user internal tool, OAuth is over-engineering.

**Decision 3: Port 465 (implicit SSL) over 587 (STARTTLS).**
Gmail supports both. 465 is simpler — TLS is on from the first byte; no STARTTLS handshake. Functionally equivalent; we pick 465 as default in env.

**Decision 4: `service: "smtp"` in cost_logs, not `"gmail"` or `"nodemailer"`.**
Generic enough that swapping to SES/Mailgun later doesn't require changing the enum. The actual SMTP host is in metadata if you need to filter.

**Decision 5: Cost = 0, but we still write a cost_logs row.**
Lets you query "how many auth emails went out this week?" without a separate audit table. Storage cost negligible.

**Decision 6: Dev-fallback prints the magic link to console.**
Same UX as Spec 04 — you copy-paste the link in the browser. Works without ANY email setup. Marcel can develop without configuring SMTP at all.

**Decision 7: PLATFORM_PROJECT_ID synthetic project.**
Same approach as the original Resend-based draft. Cost-logs has `project_id` as non-nullable FK; auth emails are platform-wide. Synthetic project keeps the schema invariant clean.

**Decision 8: `apps/api/src/lib/email.ts` becomes a 2-line shim, not removed.**
Preserves the existing import path in `auth.ts`, makes rollback trivial.

**Decision 9: `SMTP_HOST` and `SMTP_PORT` are env-configurable with Gmail defaults.**
Future migration to SES/Mailgun is a pure config change. The `secure` flag is computed from `SMTP_PORT === 465`, which works for the standard providers.

**Decision 10: No retry logic in the adapter.**
Nodemailer doesn't auto-retry. If a transient SMTP error happens, the call to `sendEmail()` throws, and BullMQ's retry policy (3 attempts with backoff, set up in Spec 05) handles it for queued sends. For magic-link (synchronous in the auth route), the user sees an error and clicks "Try again" — acceptable for the rare failure case.

## Discovered During Implementation

**escapeHtml omitted from spec's client.ts snippet.**
The spec's `sendMagicLinkEmail` code sample interpolated `input.verifyUrl` raw into the HTML template,
but the original `apps/api/src/lib/email.ts` (pre-refactor) had an `escapeHtml()` helper that escaped
`&`, `<`, `>`, `"`. The helper was silently dropped when copying the pattern. Caught in `/review-task`
and restored. `verifyUrl` is server-generated so XSS risk is low in practice, but defence-in-depth
requires escaping user-reachable values that land in HTML context.

**`EmailError.cause` → `originalCause` (types.ts).**
The spec's `types.ts` sample used `public readonly cause?: unknown` on the `EmailError` class.
`Error.cause` is a reserved built-in property in ESNext (already documented in root CLAUDE.md).
Renamed to `originalCause` before implementation; the spec sample was not updated. Future spec
authors: check `Error` built-in properties before naming constructor params on subclasses.

## Deviations

None. Implementation matches the spec exactly (modulo the two items above, both of which are
corrections to spec samples, not intentional deviations from the design).
