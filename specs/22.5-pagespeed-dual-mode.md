# Spec 22.5: PageSpeed Dual-Mode Validation

**Phase:** Marketing-Tool feature add — PageSpeed validation extension
**Estimated Effort:** 3-4 hours (1 session, structured into 5 sections)
**Dependencies:** Spec 22 (existing PageSpeed pipeline with Lighthouse-CLI), Spec 44+45 (imported articles)
**Status:** Ready for implementation
**Recommended Model:** Sonnet 4.6 (focused refactor + new adapter step)
**Repos affected:** marketing-tool (db + adapter-pagespeed + api + web)

---

## Context

Currently the PageSpeed pipeline (Spec 22) only supports **local Lighthouse-CLI mode**:
- Clones the Astro repo, runs local Astro build, serves it, runs Lighthouse against the local URL
- Strict status-gate: only triggerable for articles in `ready_to_publish` or `blocked_by_pagespeed`
- Pro: free, deterministic, fast, no external dependencies
- Con: doesn't measure real-world CDN performance, can't validate published articles

For **toolwiki** and similar projects after Spec 44+45 (where 268 imported articles arrive in `published` status from the very start), Marcel needs:
1. **Dual-mode**: choose `local` (existing CLI) or `api` (Google PageSpeed Insights API) per validation run
2. **No status gate**: validate any article anytime (imported, published, generated, ready_to_publish)
3. **DB tracking**: each `pagespeedRuns` row records its mode, so historical runs are distinguishable

API mode is also free at scale — Google PSI API has 25,000 requests/day free quota with API key (400/day without). For a 268-article toolwiki, this is trivial.

## Goal

After this spec:
- New env-var: `PAGESPEED_INSIGHTS_API_KEY` (optional — without key, still works at 400/day)
- `pagespeedRuns.mode: 'local' | 'api'` column distinguishes runs
- Article-status gate **removed** in trigger; both modes work for any article status
- New PSI-API step: HTTP-call to Google PSI API on a public URL, parses identical scores schema
- New `PageSpeedApiValidationPipeline`: 3-step pipeline (load-article → psi-api → evaluate-and-persist), no Astro build needed
- Trigger function accepts `mode: 'local' | 'api'` parameter
- API endpoint accepts mode query param
- UI: Article-Detail-Page shows two buttons "Validate (local)" and "Validate (API)"
- API mode requires `projects.domain` to be set (for URL derivation), or accepts manual `urlOverride` param

## Non-Goals

- **No mobile-emulation toggle** for API mode (uses PSI default — desktop)
- **No bulk-validate UI** (per-article only — bulk can come later)
- **No automatic CrUX-data fetching** beyond what PSI returns by default
- **No caching** of PSI results (each call is fresh — but PSI itself caches ~1 minute server-side)
- **No retry-on-PSI-rate-limit** beyond standard BullMQ retry

## Architecture Overview

```
┌──────────────────────────────────────────────────────────────────┐
│  Trigger: enqueueArticleValidation({ articleId, mode })          │
│  - mode='local' → local pipeline (existing, 6 steps)             │
│  - mode='api'   → api pipeline (new, 3 steps)                    │
│  Both create a pagespeedRuns row with mode column set            │
└──────────────────────────────────────────────────────────────────┘

LOCAL pipeline (existing, unchanged):
  load-article → clone-or-update → astro-build → preview-server → lighthouse → evaluate-and-persist

API pipeline (new):
  load-article → psi-api → evaluate-and-persist
                  │
                  └─ HTTP GET https://pagespeedonline.googleapis.com/pagespeedonline/v5/runPagespeed
                       ?url=<production-url-or-override>&key=<api-key>&category=performance,...
                  └─ parses same PagespeedScoresSchema + CoreWebVitals shape
```

### B.2 PSI-API step

```typescript
// packages/adapters/pagespeed/src/steps/psi-api.ts
import { BaseStep, type StepContext } from "@marketing-auto/pipelines/engine";
import { COST_OPS } from "@marketing-auto/core/cost";
import { createLogger, getEnv } from "@marketing-auto/shared";
import { z } from "zod";
import { CoreWebVitalsSchema, PagespeedError, PagespeedScoresSchema } from "../types.ts";

const log = createLogger("pagespeed:psi-api");

const InputSchema = z.object({
  url: z.string().url(),  // public URL — derived in trigger or override
  articleId: z.string().uuid(),
});

const OutputSchema = z.object({
  scores: PagespeedScoresSchema,
  coreWebVitals: CoreWebVitalsSchema,
  testedUrl: z.string().url(),
  reportPath: z.string().nullable(),  // PSI doesn't produce a saved HTML report; nullable
});

const PSI_BASE_URL = "https://pagespeedonline.googleapis.com/pagespeedonline/v5/runPagespeed";
const CATEGORIES = ["performance", "accessibility", "best-practices", "seo"] as const;

export class PsiApiStep extends BaseStep<
  z.infer<typeof InputSchema>,
  z.infer<typeof OutputSchema>
> {
  readonly name = "psi-api";
  readonly inputSchema = InputSchema;
  readonly outputSchema = OutputSchema;

  override estimatedCostEur(): number {
    return 0;  // PSI API is free up to 25k/day with key, 400/day without
  }

  async execute(
    input: z.infer<typeof InputSchema>,
    ctx: StepContext
  ): Promise<z.infer<typeof OutputSchema>> {
    const env = getEnv();
    const apiKey = env.PAGESPEED_INSIGHTS_API_KEY ?? "";

    // Build URL with all 4 categories
    const params = new URLSearchParams();
    params.set("url", input.url);
    if (apiKey) params.set("key", apiKey);
    for (const cat of CATEGORIES) {
      params.append("category", cat);
    }
    params.set("strategy", "desktop");  // matches local-mode default

    const requestUrl = `${PSI_BASE_URL}?${params.toString()}`;
    log.debug({ articleId: input.articleId, url: input.url }, "Calling PSI API");

    let response: Response;
    try {
      response = await fetch(requestUrl, { method: "GET" });
    } catch (e) {
      throw new PagespeedError(
        `PSI API fetch failed: ${e instanceof Error ? e.message : String(e)}`,
        "lighthouse"
      );
    }

    if (!response.ok) {
      const body = await response.text().catch(() => "");
      throw new PagespeedError(
        `PSI API returned ${response.status}: ${body.slice(0, 500)}`,
        "lighthouse"
      );
    }

    const json = (await response.json()) as PsiApiResponse;
    const lhr = json.lighthouseResult;
    if (!lhr) {
      throw new PagespeedError("PSI API response missing lighthouseResult", "lighthouse");
    }

    // Track cost (free, but record op for audit)
    await ctx.recordCost(COST_OPS.pagespeed_psi_api, 1);

    // Extract scores (0-100, multiplied from 0-1)
    const scores = {
      performance: Math.round((lhr.categories?.performance?.score ?? 0) * 100),
      accessibility: Math.round((lhr.categories?.accessibility?.score ?? 0) * 100),
      bestPractices: Math.round((lhr.categories?.["best-practices"]?.score ?? 0) * 100),
      seo: Math.round((lhr.categories?.seo?.score ?? 0) * 100),
    };

    // Extract Core Web Vitals from audits
    const audits = lhr.audits ?? {};
    const coreWebVitals = {
      lcp: audits["largest-contentful-paint"]?.numericValue ?? null,
      fid: audits["max-potential-fid"]?.numericValue ?? null,
      cls: audits["cumulative-layout-shift"]?.numericValue ?? null,
      fcp: audits["first-contentful-paint"]?.numericValue ?? null,
      tbt: audits["total-blocking-time"]?.numericValue ?? null,
    };

    return {
      scores: PagespeedScoresSchema.parse(scores),
      coreWebVitals: CoreWebVitalsSchema.parse(coreWebVitals),
      testedUrl: input.url,
      reportPath: null,  // PSI doesn't produce a local HTML report
    };
  }
}

// Minimal type for PSI response (only fields we use)
type PsiApiResponse = {
  lighthouseResult?: {
    categories?: {
      performance?: { score: number | null };
      accessibility?: { score: number | null };
      "best-practices"?: { score: number | null };
      seo?: { score: number | null };
    };
    audits?: Record<string, { numericValue?: number }>;
  };
};
```

### B.3 New API pipeline class

```typescript
// packages/adapters/pagespeed/src/pipeline.ts
// Existing PageSpeedValidationPipeline stays unchanged.
// Add new pipeline class at end of file:

import { LoadArticleStep } from "./steps/load-article.ts";
import { PsiApiStep } from "./steps/psi-api.ts";
import { EvaluateAndPersistStep } from "./steps/evaluate-and-persist.ts";

const ApiInputSchema = z.object({
  articleId: z.string().uuid(),
  projectId: z.string().uuid(),
  url: z.string().url(),  // production URL (derived) or override
});

const ApiOutputSchema = z.object({
  outcome: z.enum(["pass", "fail"]),
  failedThresholds: z.array(z.string()),
  pagespeedRunId: z.string().uuid(),
});

type ApiPipelineInput = z.infer<typeof ApiInputSchema>;
type ApiPipelineOutput = z.infer<typeof ApiOutputSchema>;

export class PageSpeedApiValidationPipeline extends Pipeline<
  ApiPipelineInput,
  ApiPipelineOutput
> {
  readonly name = "article:pagespeed-validation-api";
  readonly inputSchema = ApiInputSchema;
  readonly outputSchema = ApiOutputSchema;
  readonly steps = [
    new LoadArticleStep(),
    new PsiApiStep(),
    new EvaluateAndPersistStep(),
  ] as const;

  override bridge(
    fromStep: BaseStep<unknown, unknown>,
    toStep: BaseStep<unknown, unknown>,
    output: unknown,
    pipelineInput: ApiPipelineInput,
    getStepOutput: <T = unknown>(stepName: string) => T | undefined
  ): unknown {
    if (fromStep.name === "load-article" && toStep.name === "psi-api") {
      return {
        url: pipelineInput.url,
        articleId: pipelineInput.articleId,
      };
    }

    if (fromStep.name === "psi-api" && toStep.name === "evaluate-and-persist") {
      const psiOutput = output as {
        scores: Record<string, number>;
        coreWebVitals: Record<string, number | null>;
        testedUrl: string;
        reportPath: string | null;
      };
      const loadArticleOutput = getStepOutput<{
        article: { id: string; projectId: string };
        thresholds: Record<string, number>;
      }>("load-article")!;

      return {
        articleId: pipelineInput.articleId,
        projectId: pipelineInput.projectId,
        scores: psiOutput.scores,
        coreWebVitals: psiOutput.coreWebVitals,
        thresholds: loadArticleOutput.thresholds,
        testedUrl: psiOutput.testedUrl,
        reportPath: psiOutput.reportPath,
        astroCommitSha: null,  // not relevant for API mode
      };
    }

    return output;
  }
}
```

### C.2 Updated trigger

```typescript
// packages/adapters/pagespeed/src/trigger.ts
import { articles, db, pagespeedRuns, projects } from "@marketing-auto/db";
import { enqueuePipeline } from "@marketing-auto/pipelines/engine";
import { createLogger } from "@marketing-auto/shared";
import { eq } from "drizzle-orm";

const log = createLogger("pagespeed:trigger");

export type ValidationMode = "local" | "api";

export interface EnqueueArticleValidationInput {
  articleId: string;
  projectId: string;
  mode?: ValidationMode;  // default 'local'
  /** For API mode: optional override of derived URL */
  urlOverride?: string;
}

export async function enqueueArticleValidation(
  input: EnqueueArticleValidationInput
): Promise<{ pagespeedRunId: string; jobId: string; mode: ValidationMode }> {
  const mode = input.mode ?? "local";

  const [article] = await db
    .select()
    .from(articles)
    .where(eq(articles.id, input.articleId))
    .limit(1);
  if (!article) throw new Error(`Article ${input.articleId} not found`);

  // Status gate REMOVED — both modes work for any status.

  // For API mode: resolve URL (override > derived from project.domain)
  let urlForApi: string | null = null;
  if (mode === "api") {
    if (input.urlOverride) {
      urlForApi = input.urlOverride;
    } else {
      const [project] = await db
        .select({ domain: projects.domain })
        .from(projects)
        .where(eq(projects.id, input.projectId))
        .limit(1);

      if (!project?.domain) {
        throw new Error(
          "API mode requires either urlOverride parameter or projects.domain to be set."
        );
      }

      // Derive: https://<domain>/<locale>/<collection>/<slug>/
      // Fallback for older articles without locale/collection: https://<domain>/<slug>/
      urlForApi = buildPublicUrl(project.domain, {
        locale: article.locale,
        collection: article.collection,
        slug: article.slug,
      });
    }
  }

  const [run] = await db
    .insert(pagespeedRuns)
    .values({
      projectId: input.projectId,
      articleId: input.articleId,
      status: "pending",
      mode,
      testedUrl: urlForApi,
    })
    .returning();

  // Set article status to 'validating' only for local mode (where it's a quality gate)
  // For API mode, article keeps its current status (could be 'published')
  if (mode === "local") {
    await db
      .update(articles)
      .set({ status: "validating", updatedAt: new Date() })
      .where(eq(articles.id, input.articleId));
  }

  const pipelineName =
    mode === "local"
      ? "article:pagespeed-validation"
      : "article:pagespeed-validation-api";

  const pipelineInput =
    mode === "local"
      ? { articleId: input.articleId, projectId: input.projectId }
      : { articleId: input.articleId, projectId: input.projectId, url: urlForApi! };

  const { jobId } = await enqueuePipeline({
    pipelineName,
    projectId: input.projectId,
    input: pipelineInput,
    jobOptions: { jobId: `pagespeed-${mode}-${run!.id}` },
  });

  log.info(
    { articleId: input.articleId, runId: run!.id, jobId, mode },
    "PageSpeed validation enqueued"
  );

  return { pagespeedRunId: run!.id, jobId, mode };
}

/**
 * Build the public URL for an article based on project domain + article path components.
 * Pattern: https://<domain>/<locale>/<collection>/<slug>/
 *
 * Falls back gracefully for articles missing locale or collection (older generated articles).
 */
function buildPublicUrl(
  domain: string,
  parts: { locale: string | null; collection: string | null; slug: string }
): string {
  const cleanDomain = domain.replace(/^https?:\/\//, "").replace(/\/$/, "");
  const segments = ["https:/", cleanDomain];

  if (parts.locale) segments.push(parts.locale);
  if (parts.collection) segments.push(parts.collection);
  segments.push(parts.slug);

  return segments.join("/") + "/";
}
```

import { api } from "src/lib/api-client";

export default defineComponent({

    async triggerValidation(mode: Mode): Promise<void> {
      this.validating = true;
      try {
        const res = await api.post(`/articles/${this.articleId}/validate-pagespeed`, {
          mode,
        });
        Notify.create({
          type: "positive",
          message: this.$t("articles.validate.enqueued", { mode }),
          timeout: 3000,
        });
        this.$emit("validation-enqueued", res.data.data);
      } catch (e) {
        const msg = (e as Error).message ?? "Unknown error";
        Notify.create({
          type: "negative",
          message: msg,
          timeout: 6000,
        });
      } finally {
        this.validating = false;
      }
    },
  },
});

## Discovered During Implementation

- **Status gate belongs in the pipeline bridge, not the step.** `LoadArticleStep` originally enforced the status gate and astroCommitSha/astroRepo checks. To make the step dual-mode compatible those were removed from the step. The checks couldn't simply disappear — they moved to `PageSpeedValidationPipeline.bridge()` (local pipeline's `load-article → clone-or-update` transition), where they throw `PagespeedError` with the same helpful messages. This is the correct pattern: steps stay generic, pipelines enforce mode-specific preconditions in bridge().

- **`CoreWebVitalsSchema` shape is `lcp/inp/cls`**, not `fid/fcp/tbt` as sketched in the spec. The schema was already defined in `types.ts` before Spec 22.5. PSI audit keys mapped: `largest-contentful-paint → lcp`, `interaction-to-next-paint → inp`, `cumulative-layout-shift → cls`.

- **`enqueuePagespeedValidationPipeline` lives in `packages/pipelines/src/article/trigger.ts`**, not in the adapter's `trigger.ts`. The adapter's `trigger.ts` (and its `enqueueArticleValidation`) is a legacy wrapper; the active trigger pattern uses `packages/pipelines` + `triggerWithPreRunId`. New `enqueuePagespeedApiValidationPipeline` was added to the same pipelines trigger file.

- **`COST_ESTIMATES_EUR` with value `0` still generates a "No cost estimate found" warning** on every PSI call. The `estimateCostEur` function warns whenever `baseEur === 0`, whether or not the entry exists. This is expected noise for free APIs — no action needed, but log monitoring should filter it.

- **URL derivation placed in the API route handler** (not the trigger function) for fail-fast 400 response before job enqueue. Spec proposed URL derivation inside the trigger; route is better for immediate feedback.

- **`disabledTooltipKey` field added to `ActionDef` / `PipelineActionRow`** to support mode-specific disabled messages (e.g. "domain not set") without a new component. Re-usable for future action-row entries that need context-specific disabled reasons.

## Deviations

- **UI: two `PipelineActionRow` entries instead of `q-btn-dropdown`.** Spec proposed a Quasar `q-btn-dropdown` dropdown. Two separate rows (one per mode) fit the existing `ArticleActionPanel` pattern with zero new component boilerplate and render cleanly in the mobile-first action list.

- **`PAGESPEED_INSIGHTS_API_KEY` added to `shared/src/config.ts`**, not only `.env.example`. Required for `getEnv()` to validate and expose the key to `PsiApiStep`. The spec only mentioned `.env.example`.

- **Acceptance criteria branch name**: implemented on `master` directly (working branch = master in this repo setup), not a separate `feature/22-5-pagespeed-dual-mode` branch.
