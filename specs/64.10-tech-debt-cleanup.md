## 3. Architektur

### 3.1 Cleanup-Script (Fix A)

**File:** `apps/api/src/scripts/cleanup-orphan-heroes.ts` (neu)

**Pattern:** Mirror `convert-existing-heroes` shape aus 64.6c. CAS-protected, idempotent, dry-run by default.

**Code Skeleton:**

```ts
import { db } from "@marketing-auto/db";
import { articles, projects } from "@marketing-auto/db/schema";
import { eq, or, isNotNull } from "drizzle-orm";
import { storage } from "@marketing-auto/adapter-storage";
import { parseArgs } from "node:util";
import { log } from "@marketing-auto/shared/logger";

interface CleanupOptions {
  projectSlug?: string;
  dryRun: boolean;  // ALWAYS true unless --apply explicit
  storagePrefix: string;  // default "toolwiki/articles/hero"
}

interface CleanupSummary {
  totalKeys: number;
  orphanedKeys: number;
  deletedKeys: number;
  retainedKeys: number;
  errors: Array<{ key: string; error: string }>;
}

async function cleanupOrphanHeroes(opts: CleanupOptions): Promise<CleanupSummary> {
  log.info({ opts }, "starting orphan hero cleanup");
  
  // Step 1: List all R2 keys under storagePrefix
  const allKeys = await storage.list({ prefix: opts.storagePrefix });
  log.info({ count: allKeys.length }, "listed R2 keys");
  
  // Step 2: Find all DB-referenced hero keys (current + originals)
  const referencedKeys = await db.query.articles.findMany({
    where: or(
      isNotNull(articles.heroImageR2Key),
      isNotNull(articles.heroImageOriginalR2Key),
    ),
    columns: {
      heroImageR2Key: true,
      heroImageOriginalR2Key: true,
      projectId: true,
    },
  });
  
  const referencedSet = new Set<string>();
  for (const row of referencedKeys) {
    if (row.heroImageR2Key) referencedSet.add(row.heroImageR2Key);
    if (row.heroImageOriginalR2Key) referencedSet.add(row.heroImageOriginalR2Key);
  }
  log.info({ count: referencedSet.size }, "loaded referenced keys from DB");
  
  // Step 3: Identify orphans
  const orphans = allKeys.filter(k => !referencedSet.has(k));
  log.info({ 
    orphans: orphans.length, 
    retained: allKeys.length - orphans.length,
  }, "identified orphan keys");
  
  // Step 4: Delete if --apply
  const summary: CleanupSummary = {
    totalKeys: allKeys.length,
    orphanedKeys: orphans.length,
    deletedKeys: 0,
    retainedKeys: referencedSet.size,
    errors: [],
  };
  
  if (opts.dryRun) {
    log.info({ orphans: orphans.slice(0, 10) }, "DRY RUN — first 10 orphans listed (no deletion)");
    return summary;
  }
  
  for (const key of orphans) {
    try {
      await storage.delete(key);
      summary.deletedKeys++;
      log.info({ key }, "deleted orphan key");
    } catch (err) {
      summary.errors.push({ key, error: String(err) });
      log.error({ key, err }, "failed to delete orphan");
    }
  }
  
  log.info({ summary }, "cleanup complete");
  return summary;
}

// CLI entry point
function parseOpts(): CleanupOptions {
  const { values } = parseArgs({
    args: Bun.argv.slice(2),
    options: {
      project: { type: "string" },
      apply: { type: "boolean", default: false },
      "storage-prefix": { type: "string", default: "toolwiki/articles/hero" },
    },
  });
  
  return {
    projectSlug: values.project,
    dryRun: !values.apply,  // CRITICAL: dry-run unless --apply
    storagePrefix: values["storage-prefix"] ?? "toolwiki/articles/hero",
  };
}

const opts = parseOpts();
const summary = await cleanupOrphanHeroes(opts);
log.info({ summary }, "exit");
process.exit(summary.errors.length > 0 ? 1 : 0);
```

**Plus: package.json entry**

```json
{
  "scripts": {
    "cleanup-orphan-heroes": "bun run apps/api/src/scripts/cleanup-orphan-heroes.ts"
  }
}
```

**Usage Examples:**

```bash
# Dry-run (default — safe, lists orphans)
bun --filter @marketing-auto/api cleanup-orphan-heroes

# Filter to specific project
bun --filter @marketing-auto/api cleanup-orphan-heroes --project=toolwiki

# ACTUALLY delete (explicit --apply flag required)
bun --filter @marketing-auto/api cleanup-orphan-heroes --apply

# Different storage prefix (other projects)
bun --filter @marketing-auto/api cleanup-orphan-heroes \
  --storage-prefix=automobilsalon/articles/hero
```

**Decision-Rationale:**
- `--dry-run` als default (unless `--apply`) → kein versehentliches delete
- `--apply` muss explicit gesetzt sein → high-friction für irreversible action
- Plus: hero_image_original_r2_key (64.6c migration) wird mit-protected → backfill-script kompatibel
- Plus: storage-prefix filter erlaubt cleanup für andere projects später

## 7. Risiken

| Risk | Mitigation |
|---|---|
| Script deletet versehentlich aktive hero-keys (z.B. race condition mit running pipeline) | Default `--dry-run` + explicit `--apply` required. Plus: DB-query ist transactional snapshot, falls Pipeline mid-flight → key exists in DB checkpoint → protected. |
| storage adapter hat kein `list()` method | Phase 2 minimal-implementation. Local-mount = fs.readdir(). Future S3 = ListObjectsV2 (when migrate to echtes R2). |
| Orphan-Count abweicht von Erwartung (18) | Dry-run zeigt actual count vor delete. Marcel verifies vor `--apply`. Plus: log first-10 orphans für sanity-check. |
| Root CLAUDE.md edit ist kontroversiell (Marcel will deferred-Tag behalten) | Phase 4 listing-only: zeigt alle stale candidates, Marcel-decision pro item. Default = remove aber kann overruled. |
| packages/*/CLAUDE.md hat 62.5.1 refs die noch valid sind | Phase 0 grep + Phase 4 individual review. Bei twijfel: behalten + flag in PR-description. |
| Cleanup-Script funktioniert anders auf prod-R2 (S3) vs local-mount (fs) | Lokale verification reicht für jetzt. Prod-R2 cleanup wenn deploy-time + R2 connection live. |
| `--apply` versehentlich gesetzt → irreversible delete | High-friction: kein default, explicit flag, log-output zeigt deletion. Plus: --dry-run shows preview vor commit. |
| Existing convert-existing-heroes script (64.6c) hat shared utility patterns die reused werden sollten | Phase 0 pre-read existing script. Refactor shared utilities nur wenn unproblematic, sonst eigenständig. |

## 10. Discovered & Deviations

| # | Discovery | Decision |
|---|---|---|
| 1 | Spec §1 said "~18 R2 keys cleanup". Local R2 dir actually has **114 files** total: 22 UUID-named `.webp` (pipeline output, all orphaned) + 92 slug-named `.webp` / `.avif` (Astro responsive-image artifacts emitted by the static-site build, NOT pipeline output). | Added a strict UUID-shape filter `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\.(webp\|jpg\|jpeg\|png)$` (plus `originals/<uuid>.<ext>` for 64.6c forensic copies) so the script only considers pipeline-shaped keys as orphan candidates. Astro responsive artifacts are skipped silently (`skippedNonUuidKeys: 92`). Test case #5 in `cleanup-orphan-heroes.smoke.test.ts` locks the protection in. Without this filter the script would have mass-deleted the entire Astro `<Image>` responsive set on `--apply`. |
| 2 | Spec §1 Finding B hypothesized ("vermutlich") a stale `deferred:` tag for Spec 62.5.1 in root CLAUDE.md. Grep across root + `apps/*/CLAUDE.md` + `packages/*/CLAUDE.md` shows **no such tag exists**: the 5 `62.5.1` mentions are all legitimate — 3 DO-NOT rules citing 62.5.1's snapshot-SSoT as the canonical pattern (lines 146/147/174), 1 completed-spec index entry (line 318), and 4 cross-references in 63.5 / 64.6b / 64.7 narrative. One additional "deferred" in `packages/pipelines/CLAUDE.md:938` documents a 62.0a edge-case design decision ("granular per-call overrides are deferred") — also legitimate. | Fix B is a **no-op**. Documented as a negative finding. No CLAUDE.md edits made. |
| 3 | `@marketing-auto/adapter-storage` had no `list()` method at the start of the task — only `put`, `exists`, `file` (getFile), `delete`, `presign`. Spec §3.2 anticipated this. | Added `listObjects({prefix, maxKeys?})` to `r2.ts` with dual-mode (real R2 via `S3Client.list` + paginated continuation; local fallback via recursive `node:fs/promises.readdir` + `Bun.file().stat()`). Mirrors the existing dual-mode pattern of `putObject`. Re-exported via `index.ts` + the `r2.list` convenience object. The verify-time `S3Client.list({maxKeys: 1})` call in `verify.ts` was already evidence that `S3Client.list` existed — re-used for paginated mode. |
| 4 | Bun's `node:fs/promises.readdir({withFileTypes: true})` returns `Dirent<NonSharedBuffer>[]` instead of `Dirent<string>[]` under the Bun TypeScript config, causing TS2322 ("Type 'Dirent<string>[]' is not assignable to type 'Dirent<NonSharedBuffer>[]'"). | Sidestepped by using plain `readdir(dir)` (returns `string[]`) and calling `Bun.file(full).stat()` to discriminate file vs directory. Two-call overhead is fine for a one-shot cleanup script. |
| 5 | Spec §3.1 code skeleton used `parseArgs({args: Bun.argv.slice(2), ...})` but `Bun.argv` differs from `process.argv`. The convention in sibling scripts (`convert-existing-heroes.ts`, `rebake-hero-samples.ts`) is `process.argv.slice(2)`. | Used `process.argv.slice(2)` for consistency. Also factored CLI parsing into an exported `parseCliArgs()` function for potential unit testing (not currently tested — covered indirectly by manual live-runs). |
| 6 | Spec §3.1 skeleton used `db.query.articles.findMany({where, columns})`. Drizzle in this repo does NOT have the `db.query.*` relational query API set up (verify: no `relations()` declarations in `packages/db/src/schema/content.ts`). | Switched to plain `db.select({heroImageR2Key, heroImageOriginalR2Key}).from(articles).where(or(isNotNull(...), isNotNull(...)))`. Cheaper anyway — no JOIN, just two columns. |
| 7 | Spec §3.1 imported drizzle operators directly from `drizzle-orm`. Per root CLAUDE.md hard-rule, workspace packages other than `packages/db` MUST import operators from `@marketing-auto/db` (workspace-version-incompatibility issue). | Imported `eq, isNotNull, or` from `@marketing-auto/db` alongside `articles, db, projects`. |
| 8 | Spec §4.1 test skeleton used `vi.mocked(...)` (Vitest). This codebase uses `bun:test`.
