# Spec 64.7 — Image-Batch Mode: Plan-Level Coordinator für Google Gemini Batch API

_Erweitert Spec 64.6 (Hero-Image Bundle, sync Nano Banana 2) um Batch-Mode für Plan-Approved Articles. 50% Cost-Saving auf Hero-Image-Generation._
_Status: Draft._
_Voraussetzung: Spec 64.6 deployed (Nano Banana 2 sync Adapter), Spec 64.6b deployed (Cost-Estimator)._
_Aufwand: ~1-2 Tage Implementation + ~2-3h Tests._

---

## 1. Problem

Spec 64.6 ist deployed (sync Nano Banana 2 via `@marketing-auto/adapter-nano-banana`). Spec 64.6b erweitert um Cost-Estimator + Resolution-Toggle + 429-Retry. Was fehlt: **Batch-Mode für 50% Cost-Saving auf Plan-Approved Articles**.

Google Gemini bietet **Batch-API mit 50% Discount** für async workloads. Bei 1K (Toolwiki default): $0.067 sync → $0.034 batch.

**Marcel-Decisions (2026-05-23):**
- Default-Batch für Plan-Approved Articles (cost-saving)
- Standalone-Tests bleiben Immediate (fast feedback)
- **Explicit Plan-Coordinator:** 1 batch-job pro Plan (N images aggregiert)
- Cost-Tracking: Submit (estimated) + Resume (actual)
- Service-Name 'google-gemini' für sync UND batch — `operation` als discriminator (konsistent mit Anthropic-Pattern)

**Cost-Impact bei 50 Articles/Monat (Toolwiki 1K):**
- Sync (Spec 64.6 + 64.6b): ~€3.10/Monat (1K × 50 articles × €0.062)
- **Batch (Spec 64.7): ~€1.55/Monat** (50% Saving)

**Pricing-Reference (verified 2026-05-23 — KORREKT):**

| Resolution | Sync USD | Sync EUR | Batch USD | Batch EUR |
|---|---|---|---|---|
| 0.5K | $0.045 | €0.041 | $0.022 | €0.020 |
| **1K (Toolwiki)** | **$0.067** | **€0.062** | **$0.034** | **€0.031** |
| 2K | $0.101 | €0.093 | $0.050 | €0.046 |
| 4K | $0.151 | €0.139 | $0.076 | €0.070 |

## 2. Ziel

Plan-Level Image-Batch-Coordinator der bei Plan-Approve:
1. Alle planned_items aufsammelt die Hero-Images brauchen
2. ONE Gemini Batch-Submit mit allen Image-Prompts
3. plan-Row bekommt `image_batch_id` reference
4. Bei Resume: distribute results an einzelne pipeline_runs

import type { NanoBananaInput, NanoBananaOutput, NanoBananaBatchSubmit, NanoBananaBatchResult } from "./types";

const GEMINI_BATCH_ENDPOINT = "https://generativelanguage.googleapis.com/v1beta/batches";

/**
 * Submit batch of image generation requests to Gemini Batch API.
 * Returns batch_id for later polling.
 */
export async function createImageBatch(
  requests: Array<{ customId: string; input: NanoBananaInput }>,
  apiKey: string,
): Promise<{ batchId: string; status: "pending" }> {
  const response = await fetch(`${GEMINI_BATCH_ENDPOINT}:create`, {
    method: "POST",
    headers: { "x-goog-api-key": apiKey, "Content-Type": "application/json" },
    body: JSON.stringify({
      requests: requests.map(r => ({
        custom_id: r.customId,
        request: {
          contents: [{ parts: [{ text: r.input.prompt }] }],
          generationConfig: {
            responseModalities: ["IMAGE"],
            imageConfig: { 
              aspectRatio: r.input.aspectRatio,
              outputResolution: "2K",  // Standard für unsere Use-Case
            },
          },
        },
      })),
      displayName: `toolwiki-hero-batch-${Date.now()}`,
    }),
  });
  
  if (!response.ok) throw new Error(`Gemini batch create failed: ${response.status}`);
  const data = await response.json();
  return { batchId: data.name, status: "pending" };
}

/**
 * Retrieve batch status. Returns 'processing' while pending, 'ended' when ready.
 */
export async function retrieveBatch(
  batchId: string,
  apiKey: string,
): Promise<{ status: "processing" | "ended" | "failed"; resultsUrl?: string }> {
  const response = await fetch(`${GEMINI_BATCH_ENDPOINT}/${batchId}`, {
    method: "GET",
    headers: { "x-goog-api-key": apiKey },
  });
  
  if (!response.ok) throw new Error(`Gemini batch retrieve failed: ${response.status}`);

  return {
    status: data.state === "BATCH_STATE_SUCCEEDED" ? "ended" :
            data.state === "BATCH_STATE_FAILED" ? "failed" : "processing",
    resultsUrl: data.outputUri,
  };
}

### 3.5 Plan-Image-Batch-Coordinator (NEU — Explicit Plan-Level)

**File:** `apps/api/src/lib/plan-image-batch-coordinator.ts` (NEU)

Marcel's Anforderung: "1 batch-job pro Plan (N images aggregiert)". Statt side-effect aggregation via 30-min cron, explicit Plan-Level Submit bei Plan-Approve.

```ts
/**
 * Called from plan-approve workflow after planned_items enqueued.
 * Collects all hero-image needs for the plan, submits ONE Gemini batch.
 * Updates weekly_plans.image_batch_id + image_batch_submitted_at.
 */
export async function submitPlanImageBatch(planId: string): Promise<{
  batchId: string;
  imageCount: number;
}> {
  // 1. Load plan + pending image batch requests
  const plan = await db.query.weeklyPlans.findFirst({ where: eq(weeklyPlans.id, planId) });
  if (!plan) throw new Error(`Plan ${planId} not found`);
  
  const pendingImages = await db.query.imageBatchRequests.findMany({
    where: and(
      eq(imageBatchRequests.weeklyPlanId, planId),
      eq(imageBatchRequests.status, "pending"),
    ),
  });
  
  if (pendingImages.length === 0) {
    log.info({ planId }, "no pending images for plan — skipping batch submit");
    return { batchId: "", imageCount: 0 };
  }
  
  // 2. Resolve API-Key (via project_credentials oder env)
  const apiKey = await resolveGeminiApiKey(plan.projectId);
  
  // 3. Submit batch via adapter
  const requests = pendingImages.map(img => ({
    customId: img.geminiCustomId,
    input: {
      prompt: img.requestBody.prompt,
      model: img.requestBody.model,
      aspectRatio: img.requestBody.aspectRatio,
      seed: img.requestBody.seed,
      outputFormat: "webp" as const,
    },
  }));
  
  const { batchId } = await createImageBatch(requests, apiKey);
  
  // 4. Update DB: image_batch_requests status + plan ref (in transaction)
  await db.transaction(async (tx) => {
    await tx.update(imageBatchRequests)
      .set({ 
        geminiBatchId: batchId, 
        status: "submitted", 
        submittedAt: new Date() 
      })
      .where(and(
        eq(imageBatchRequests.weeklyPlanId, planId),
        eq(imageBatchRequests.status, "pending"),
      ));
    
    await tx.update(weeklyPlans)
      .set({ 
        imageBatchId: batchId, 
        imageBatchSubmittedAt: new Date() 
      })
      .where(eq(weeklyPlans.id, planId));
  });
  
  log.info({ planId, batchId, imageCount: pendingImages.length }, 
    "submitted plan-level image batch");
  
  return { batchId, imageCount: pendingImages.length };
}
```

### 3.7 image-batch-resume.ts (Engine — Memory D130)

**File:** `packages/pipelines/src/engine/image-batch-resume.ts`

```ts
/**
 * Resume pipeline after image batch result arrives.
 * Validates status, supersedes stale substep, re-enqueues pipeline.
 */
export async function resumeImageBatchPipeline(imageBatchRequestId: string): Promise<void> {
  const request = await db.query.imageBatchRequests.findFirst({
    where: eq(imageBatchRequests.id, imageBatchRequestId),
  });
  
  if (!request || request.status !== "completed") {
    log.warn({ imageBatchRequestId, status: request?.status }, 
      "image batch resume: unexpected state");
    return;
  }
  
  const pipelineRun = await db.query.pipelineRuns.findFirst({
    where: eq(pipelineRuns.id, request.pipelineRunId!),
  });
  
  if (!pipelineRun) {
    log.warn({ pipelineRunId: request.pipelineRunId }, "pipeline run not found");
    return;
  }
  
  if (pipelineRun.status !== "image_batch_pending") {
    log.info({ ... }, "pipeline run no longer awaiting image batch — skipping");
    return;
  }
  
  // Memory D129: explicit existence check (not truthy)
  const imageUrl = request.responseBody?.image?.url;
  if (imageUrl === undefined) {
    throw new Error(`Image batch result missing imageUrl: ${imageBatchRequestId}`);
  }
  
  // Re-enqueue pipeline with batch-result + resume-from-step
  await enqueuePipeline({
    preRunId: pipelineRun.id,
    resumeFromStep: "hero-image",
    batchResult: { imageUrl, costEur: request.costEur },
    priorOutput: pipelineRun.suspensionCheckpoint?.priorOutput,
  });
  
  // Update pipeline_runs status
  await db.update(pipelineRuns)
    .set({ 
      status: "queued", 
      suspensionCheckpoint: null,
      updatedAt: new Date(),
    })
    .where(eq(pipelineRuns.id, pipelineRun.id));
}
```

export const IMAGE_COST_PER_CALL_EUR_SYNC: Record<ImageProvider, number> = {

export function estimateHeroImageCost(
  provider: ImageProvider | undefined | null,
  mode: "sync" | "batch" = "sync",
): number {

  return rates[provider] ?? rates["flux-1.1-pro"];

## 7. Risiken

| Risk | Mitigation |
|---|---|
| Gemini Batch-API ändert response shape | Adapter mit Zod-Validation + clear errors |
| Plan-Approve timing: Pipelines noch nicht bei HeroImageStep wenn coordinator triggert | 30s delayed BullMQ-Job (statt setTimeout) |
| Race: 2 concurrent Plan-Approves desselben Plans | jobId="plan-image-batch-${planId}" deduplication |
| Batch never completes (Google API issue) | Plus monitoring: alert if batch >24h pending |
| Resume verliert priorOutput (Memory D131) | suspensionCheckpoint speichert priorOutput vor batch-submit |
| ALTER TYPE in selbem Migration mit Seed (Memory D124) | Separate Seed-Migration falls nötig (hier: kein Seed) |
| Cost-Estimate vs Actual driftet auseinander | Beide loggen mit stage-metadata, UI kann diff zeigen |
| Standalone-Test landet versehentlich im Batch | overrideLlmMode='sync' explizit in articles-standalone.ts |
| Multi-Project: Project A Plan submits während Project B aktiv | Per-project apiKey resolution + per-plan batch (kein cross-plan) |
| Worker-Restart während Batch-Cron läuft | BullMQ persistence + concurrency:1 schützt |
| 4 slug-overlap Articles aus Phase 0: Test-Article slug clash | image_batch_requests hat keinen slug-link, nutzt pipelineRunId — kein Issue |
