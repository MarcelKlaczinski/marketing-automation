_Alle persistent state Tabellen für Theme 65 etabliert in einem fokussierten Schema-Sprint._

## 1. Problem

Theme 65 Master-Spec listet 13 Sub-Specs. Alle (außer 65.13 ManyChat) brauchen DB-Tabellen die heute nicht existieren:

- `recurring_content_definitions` — Marcel's recurring rubrics ("Top 5 LLMs weekly")
- `hook_templates` — Family B Hook-Library
- `tool_brand_assets` — Logos + colors für carousel-rendering
- `tool_persona_scores` — LLM-cached persona-scoring
- `end_slide_definitions` — End-Slide-Templates
- `engagement_resources` — PDFs/Resources für comment-to-get DM-funnel
- `template_usage_log` — LRU-Tracking für Template-Rotation

Plus typed metadata bucket auf `topic_briefs`: `recurringMetadata`.

Ohne diese Foundation blockiert: 65.2 (Brand-Assets), 65.3 (Persona-Scoring), 65.4 (Hook-Library), 65.5 (Brief-Generator + Cron), 65.6 (Template-Registry-Extension), 65.7-65.10 (Templates + Output).

Schema-only Sprint: keine Worker-Implementation, keine Business-Logic. Helpers für read+write damit folge-Specs sofort konsumieren können.

### 3.1 Migration 1 — Core Tables

**File:** `packages/db/drizzle/0113_recurring_content_system_tables.sql`

```sql
-- recurring_content_definitions: per-project rubrics with cron-frequency
CREATE TABLE recurring_content_definitions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  format_type TEXT NOT NULL,                                  -- validated runtime via shared Zod
  format_config JSONB NOT NULL DEFAULT '{}',                  -- per-format Zod-validated
  frequency TEXT NOT NULL,                                    -- 'weekly' | 'biweekly' | 'monthly' | cron-like
  next_run_at TIMESTAMPTZ NOT NULL,
  last_run_at TIMESTAMPTZ,
  output_targets JSONB NOT NULL DEFAULT '{"article":false,"social":true}',
  template_selection_strategy TEXT NOT NULL DEFAULT 'lru',    -- 'fixed' | 'lru' | 'llm-picks' | 'latest'
  fixed_template_key TEXT,                                    -- only if strategy='fixed'
  end_slide_strategy TEXT NOT NULL DEFAULT 'rotation',
  end_slide_pool JSONB NOT NULL DEFAULT '[]'::jsonb,          -- array of end_slide_definition IDs
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_recurring_defs_next_run ON recurring_content_definitions(next_run_at) WHERE is_active = TRUE;
CREATE INDEX idx_recurring_defs_project ON recurring_content_definitions(project_id);
CREATE INDEX idx_recurring_defs_format_type ON recurring_content_definitions(format_type) WHERE is_active = TRUE;

-- hook_templates: Hook-Library for Family B
CREATE TABLE hook_templates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  format_type TEXT NOT NULL,                                  -- which format-type this hook serves
  pattern TEXT NOT NULL,                                      -- "I lost my {profession} job because of {tool}"
  language TEXT NOT NULL,                                     -- 'de' | 'en'
  variables JSONB NOT NULL DEFAULT '[]'::jsonb,               -- ["profession", "tool"]
  usage_count INT NOT NULL DEFAULT 0,
  last_used_at TIMESTAMPTZ,
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_hook_templates_format_type ON hook_templates(format_type, language) WHERE is_active = TRUE;
CREATE INDEX idx_hook_templates_project ON hook_templates(project_id);
CREATE INDEX idx_hook_templates_lru ON hook_templates(last_used_at NULLS FIRST) WHERE is_active = TRUE;

-- tool_brand_assets: Brand-Assets per tool (project-agnostic, tools is global)
CREATE TABLE tool_brand_assets (
  tool_id UUID PRIMARY KEY REFERENCES tools(id) ON DELETE CASCADE,
  logo_url TEXT,                                              -- R2 key
  logo_dark_url TEXT,                                         -- variant for dark backgrounds
  primary_color TEXT,                                         -- hex #RRGGBB
  secondary_color TEXT,                                       -- hex #RRGGBB
  brand_name_canonical TEXT,
  source TEXT NOT NULL,                                       -- 'brandfetch' | 'clearbit' | 'favicon' | 'manual'
  needs_review BOOLEAN NOT NULL DEFAULT FALSE,
  fetched_at TIMESTAMPTZ NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_brand_assets_needs_review ON tool_brand_assets(needs_review) WHERE needs_review = TRUE;
CREATE INDEX idx_brand_assets_source ON tool_brand_assets(source);

-- tool_persona_scores: project-scoped per Marcel-Decision Q5
CREATE TABLE tool_persona_scores (
  tool_id UUID NOT NULL REFERENCES tools(id) ON DELETE CASCADE,
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  persona TEXT NOT NULL,                                      -- 'beginners' | 'students' | 'eltern' | ...
  score INT NOT NULL CHECK (score >= 0 AND score <= 10),
  reasoning TEXT NOT NULL,
  scored_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (tool_id, project_id, persona)
);

CREATE INDEX idx_persona_scores_persona ON tool_persona_scores(project_id, persona, score DESC);
CREATE INDEX idx_persona_scores_stale ON tool_persona_scores(scored_at) WHERE scored_at < NOW() - INTERVAL '6 months';

-- end_slide_definitions: pluggable end-slides
CREATE TABLE end_slide_definitions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  type TEXT NOT NULL,                                         -- 'follow-cta' | 'comment-to-get' | 'link-in-bio' | ...
  config JSONB NOT NULL DEFAULT '{}',                         -- type-specific Zod-validated
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_end_slides_project_type ON end_slide_definitions(project_id, type) WHERE is_active = TRUE;

-- engagement_resources: PDFs/Resources for comment-to-get
CREATE TABLE engagement_resources (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  file_url TEXT NOT NULL,                                     -- R2 key
  keyword TEXT NOT NULL,                                      -- "CLAUDE", "PROMPT", "FREE"
  resource_type TEXT NOT NULL,                                -- 'pdf' | 'link' | 'prompt-list'
  manychat_flow_id TEXT,                                      -- for future auto-DM integration (65.13)
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX uniq_engagement_resources_keyword_per_project ON engagement_resources(project_id, keyword);
CREATE INDEX idx_engagement_resources_type ON engagement_resources(project_id, resource_type);

-- template_usage_log: LRU tracking for template-rotation
CREATE TABLE template_usage_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  recurring_definition_id UUID NOT NULL REFERENCES recurring_content_definitions(id) ON DELETE CASCADE,
  template_key TEXT NOT NULL,
  end_slide_type TEXT,                                        -- which end-slide variant was used
  used_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_template_usage_def_time ON template_usage_log(recurring_definition_id, used_at DESC);
```

```typescript
import { sql } from 'drizzle-orm';
import { projects } from './projects';

export const recurringContentDefinitions = pgTable('recurring_content_definitions', {
  id: uuid('id').primaryKey().defaultRandom(),
  projectId: uuid('project_id').notNull().references(() => projects.id, { onDelete: 'cascade' }),
  name: text('name').notNull(),
  formatType: text('format_type').notNull(),
  formatConfig: jsonb('format_config').notNull().default({}),
  frequency: text('frequency').notNull(),
  nextRunAt: timestamp('next_run_at', { withTimezone: true }).notNull(),
  lastRunAt: timestamp('last_run_at', { withTimezone: true }),
  outputTargets: jsonb('output_targets').notNull().default({ article: false, social: true }),
  templateSelectionStrategy: text('template_selection_strategy').notNull().default('lru'),
  fixedTemplateKey: text('fixed_template_key'),
  endSlideStrategy: text('end_slide_strategy').notNull().default('rotation'),
  endSlidePool: jsonb('end_slide_pool').notNull().default([]),
  isActive: boolean('is_active').notNull().default(true),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
}, (t) => ({
  idxNextRun: index('idx_recurring_defs_next_run').on(t.nextRunAt).where(sql`${t.isActive} = TRUE`),
  idxProject: index('idx_recurring_defs_project').on(t.projectId),
  idxFormatType: index('idx_recurring_defs_format_type').on(t.formatType).where(sql`${t.isActive} = TRUE`),

export type RecurringContentDefinition = typeof recurringContentDefinitions.$inferSelect;
export type NewRecurringContentDefinition = typeof recurringContentDefinitions.$inferInsert;
```

```typescript
import { z } from 'zod';

const KNOWN_FREQUENCIES = ['weekly', 'biweekly', 'monthly'] as const;

export const frequencySchema = z.string().refine(
  (val) => KNOWN_FREQUENCIES.includes(val as any) || isValidCronExpression(val),
  { message: 'frequency must be weekly|biweekly|monthly OR valid cron expression' },
);

function isValidCronExpression(expr: string): boolean {
  // Basic validation: 5 or 6 space-separated tokens
  const parts = expr.split(/\s+/);
  if (parts.length !== 5 && parts.length !== 6) return false;
  return true; // Defer deeper validation to cron-parser library in 65.5
}

export type Frequency = z.infer<typeof frequencySchema>;
```

Per Marcel-Decision Q1: text mit Zod-validation gegen erlaubte Werte (best of both).

### 4.4 Format-Type Registry Skeleton (groundwork for 65.4)

**File:** `packages/shared/src/format-types/registry.ts`

```typescript
import { z } from 'zod';

export interface FormatTypeDefinition {
  family: 'A' | 'B';
  configSchema: z.ZodSchema;
  briefGenerator: string; // referenced in 65.5
  eligibleTemplates: string[]; // populated in 65.6
}

// Placeholder registry — populated in 65.4
export const FORMAT_TYPES: Record<string, FormatTypeDefinition> = {};

export function getFormatTypeSchema(formatType: string): z.ZodSchema {
  const def = FORMAT_TYPES[formatType];
  if (!def) {
    // V1: unknown format_type → permissive passthrough (validate at brief-generator-time)
    return z.record(z.string(), z.unknown());
  }
  return def.configSchema;
}

export function validateFormatConfig(
  formatType: string,
  config: unknown,
): { ok: true; data: unknown } | { ok: false; error: string } {
  const schema = getFormatTypeSchema(formatType);
  const result = schema.safeParse(config);
  if (result.success) return { ok: true, data: result.data };
  return { ok: false, error: result.error.message };
}
```

**Per Marcel-Decision Q2:** Zod-Schema per format_type, centrally registered. This file is the central registry. 65.4 populates it with all 5 v1-format-types.

## 6. Auto-Prune Cron Hook (per Marcel-Decision Q3)

`template_usage_log` capped at 50 entries per definition with auto-prune cron.

### 6.1 Implementation Location

Per Memory D3 — workers live in `apps/api/src/workers/`. Cron-orchestrator + worker:

```
apps/api/src/workers/template-usage-log-prune.cron.ts
```

### 6.2 Cron Implementation Skeleton

```typescript
// apps/api/src/workers/template-usage-log-prune.cron.ts
import { pruneAllTemplateUsageLog } from '@marketing-auto/db/helpers/template-usage-log-write';
import { logger } from '@marketing-auto/shared';
import { getEnv } from '@marketing-auto/shared/config';

const TEMPLATE_USAGE_LOG_CAP = 50;
const PRUNE_CADENCE_MS = 24 * 60 * 60 * 1000; // daily

let pruneInterval: NodeJS.Timeout | null = null;

export function startTemplateUsageLogPruneCron() {
  pruneInterval = setInterval(async () => {
    try {
      const result = await pruneAllTemplateUsageLog({ keepLastN: TEMPLATE_USAGE_LOG_CAP });
      logger.info('Template usage log prune complete', result);
    } catch (err) {
      logger.error('Template usage log prune failed', err);
    }
  }, PRUNE_CADENCE_MS).unref();
}

export function stopTemplateUsageLogPruneCron() {
  if (pruneInterval) {
    clearInterval(pruneInterval);
    pruneInterval = null;
  }
}
```

`.unref()` per Memory pattern from Engine Day 6 — prevents process-exit blocking.

### 6.3 Wiring

Add to API startup (apps/api/src/server.ts) AND worker process startup (apps/api/src/workers/index.ts):

- API process: starts the prune cron (single instance)
- Worker processes: do NOT start prune cron (would multi-run)

Per Memory D24 Cron-based Coordinator Pattern: single cron-instance owns the prune.

## 7. Multi-Domain Considerations

Per Memory D5 — multi-tenant exception: most tables have `project_id NOT NULL`.

**Project-scoped (project_id NOT NULL):**
- recurring_content_definitions
- hook_templates
- tool_persona_scores (Marcel-Decision Q5 — explicitly project-scoped, NOT global)
- end_slide_definitions
- engagement_resources

**Multi-table-key (project_id as part of composite PK):**
- tool_persona_scores: PRIMARY KEY (tool_id, project_id, persona)

**Tool-scoped, not project-scoped:**
- tool_brand_assets: PRIMARY KEY = tool_id (tools is global)
  - Reasoning: Logos/colors are tool-attributes, not project-attributes. Both BK and Toolwiki would benefit from the same Claude-logo if both display the Claude-tool. Avoids duplicate fetch-cost.

**Definition-scoped (child relationship):**

## 14. Discovered & Deviations

### D14.1 — `tools(id)` FK target doesn't exist (Marcel-decision Q1 reroute)

Spec §3.1 declared `tool_brand_assets.tool_id REFERENCES tools(id)` and `tool_persona_scores.tool_id REFERENCES tools(id)`. **There is no `tools` table** — tools live in `articles` with `collection='tools'` (verified Phase 0 by grep). Asked Marcel before starting; he picked **`articles(id)` ON DELETE CASCADE** (vs alternatives: `content_source_inventory.id` from Spec 64.20, or plain `uuid` without FK).

App-layer enforcement of `articles.collection='tools'` lives in `assertArticleIsTool()` inside both write helpers — same shape as `assertArticleCollectionForTool()` in `content-source-inventory-write.ts`. Throws on mismatch so caller bugs surface immediately.

### D14.2 — `idx_persona_scores_stale` partial index is structurally invalid

Spec §3.1 included `CREATE INDEX idx_persona_scores_stale ... WHERE scored_at < NOW() - INTERVAL '6 months'`. **PostgreSQL forbids non-IMMUTABLE functions in partial-index WHERE clauses** — `NOW()` is STABLE, not IMMUTABLE, so this would fail at migration-apply time with `functions in index predicate must be marked IMMUTABLE`.

**Replacement:** dropped the index entirely. Stale-detection is served via the `deleteStalePersonaScores({ olderThanDays })` helper which computes the cutoff in JS (`new Date(Date.now() - days * 86_400_000)`) and uses Drizzle's `lt(scoredAt, cutoff)` — same query plan as the partial index would have served, just without the optimisation. SQL comment in the migration documents the rationale.

This footgun is now in `packages/db/CLAUDE.md` for future schema authors.

### D14.3 — 10 test fixtures across 5 packages needed `recurringMetadata: null`

Adding any field to `topicBriefs` (even a nullable `$type<T>()` jsonb column) widens the inferred `TopicBrief` type with a required field — TypeScript treats jsonb `$type<>()` as `T | null` (required), not `T | null | undefined` (optional). 10 test fixtures across `packages/pipelines/test/` + `apps/api/test/scripts/` failed typecheck on the missing field; fixed via batch `perl -i -pe` after `starTrendMetadata: null`. Same gotcha will hit 65.5 when it widens the `source` enum + superRefine.

### D14.4 — Biome `--write` hoisted stray imports above file-leading JSDoc

`tool-persona-scores.ts` and `hook-templates.ts` had a single `import { desc } from "drizzle-orm"` / `import { sql }` line stranded above the file-leading `/** Spec 65.1 — ... */` JSDoc (artefact of my initial write order). Biome's `organizeImports` rule hoisted them to the literal top of the file, leaving the JSDoc as the second-statement — IDEs no longer treat it as the file's lead-in doc-comment. Re-ordered by hand so the JSDoc is the file's first statement and ALL imports follow.

**Footgun documented in root CLAUDE.md** — applies to any new schema/helper/util file.

### D14.5 — Helper API signatures held up (Spec §14 prediction)

The pre-spec deviation candidates (helper-API tweaks anticipated after 65.2/65.3 consumer perspective lands) DID NOT materialise during 65.1 — the helpers passed all 145 tests against contracts derived from Spec §5.2's API table. May still surface in 65.2-65.4; revisit then.

### D14.6 — Composite PK isolation tested but needs cross-project FK gymnastics

`tool_persona_scores`'s composite PK `(tool_id, project_id, persona)` was tested for project-isolation. Note: a tool-article is FK'd to one project, so testing "same tool different projects" actually requires creating a separate tool-article in the other project (with a different `articles.id`). The composite PK isn't tested with the SAME `tool_id` across projects because tools are not cross-tenant in the current schema — this is an architectural property of `articles.project_id`, not a gap in the persona-scores composite PK.

### D14.7 — Pre-existing flaky api tests (NOT caused by 65.1)

Baseline `bun --filter @marketing-auto/api test` against my-stashed-changes also fails on `bulk-approve 500 UUIDs → 5s timeout` and intermittently on `handleInventoryRefresh > GitHubRateLimitError`. Both are pre-existing flakiness against the shared dev DB and unrelated to Spec 65.1 (the only test file 65.1 touched is `backfill-brief-embeddings.test.ts` — adding `recurringMetadata: null` to a fixture). Documented for next session's awareness.
