# Discovery Prompt: Content Discovery Backend Inventory

**Purpose:** Inventory existing backend capabilities for Trends Discovery, Content-Gap Analysis, and Refresh Detection. Output feeds Spec 56.6 (Content Discovery UI).

**Run with:** `/discover-task content-discovery-inventory.md` or paste into a fresh Claude Code session

**Expected runtime:** ~30-45 minutes of code exploration

**Output:** Single Markdown file at `specs/_drafts/56-6-backend-inventory.md` answering all questions below with specific file paths, function names, and code excerpts. No speculation — only document what you can verify in the codebase.

---

## Investigation Areas

### Area A: Trends Discovery

**Goal**: Understand how trends are discovered, scored, and converted to briefs today.

**Questions to answer**:

1. **Pipeline existence**
  - Is there a pipeline named `trends:discover` or similar?
  - Path to pipeline definition file?
  - Path to runner/adapter files?
  - What does it produce as output (DB rows? in-memory? external storage?)

2. **Data model**
  - Is there a dedicated `trends` or `signals` DB table? Or are trends stored directly as `topic_briefs` with `source='trend_discovery'`?
  - Schema definition file path?
  - What fields exist on trend records? (score, signals, source attribution, freshness category, etc.)
  - Look at `topic_briefs.trendMetadata` JSONB column structure — paste the type definition

3. **Sources / data inputs**
  - Where do trend signals come from? (DataForSEO? Google Trends API? Reddit? Web scraping? LLM-generated?)
  - List all external services consulted in the trends pipeline
  - Are there configured "trend sources" per project, or is the input set hardcoded?

4. **Scoring logic**
  - Where is the trend score computed? (LLM call? deterministic algorithm? mix?)
  - What dimensions are scored? (volume / freshness / commercial intent / brand fit?)
  - Where is `scoreBreakdown` populated in the code? Paste the relevant function

5. **Triggering**
  - Can trends discovery be triggered manually via an API endpoint? List the endpoint path
  - Is there a cron / scheduled trigger? Where is it defined (BullMQ repeating job? cron config?)
  - Is the cron currently enabled or disabled? Where would I toggle it?
  - Per-project config flag for auto-discovery? Where stored?

6. **Brief creation from trends**
  - When a trend is discovered, is a brief auto-created (`approval_status='pending'` or `approval_status='approved'`)?
  - Or are trends stored separately and converted on user action?
  - If user action: what endpoint converts a trend → brief?

7. **Listing trends in the API**
  - Is there a dedicated `GET /api/projects/:slug/trends` endpoint?
  - If no, how does the existing UI (if any) list discovered trends?
  - What query params does it support (filter by score, freshness, source)?

8. **Trends UI today**
  - Search `apps/web/src` for any existing trends-related Vue component (look for "trend", "signal", "discovery" in filenames + content)
  - If anything exists: list file paths + brief description of what it does
  - If nothing exists: confirm "no existing UI"

### Area B: Content-Gap Analysis

**Goal**: Understand how content gaps in clusters are identified, stored, and surfaced.

**Questions to answer**:

1. **Pipeline / analysis logic**
  - Is there a pipeline or service that analyzes a cluster and identifies missing spokes/articles?
  - Look for files matching: `content-gap*`, `*gap-analysis*`, `cluster-gap*`
  - Path to the analysis function/pipeline?
  - Trigger: synchronous LLM call, or async pipeline?

2. **Data model**
  - Is there a `content_gaps` DB table?
  - Schema path + fields
  - How is a gap linked to a cluster? (clusterId column?)
  - How is a gap linked to a generated brief if accepted?
  - Status enum on gaps? (pending / accepted / dismissed?)

3. **API endpoints**
  - Look for routes matching `content-gaps`, `gaps`, `cluster/.../gaps`
  - List all such endpoints with HTTP method + path + what they do:
    - GET (list gaps for a cluster?)
    - POST (trigger gap analysis?)
    - POST (accept a gap → create brief?)
    - DELETE/PATCH (dismiss a gap?)

4. **LLM prompt for gap identification**
  - Where is the prompt that asks LLM "what's missing in this cluster"?
  - Paste a snippet of the prompt template
  - What context does it receive? (existing hub + spokes? pillar context? brand voice?)

5. **Triggering**
  - Can Marcel manually trigger gap analysis via an endpoint?
  - Is there an auto-trigger (after cluster completes? cron?)
  - Per-project config flag for auto-gap-analysis?

6. **Gap acceptance flow**
  - When Marcel accepts a gap, what happens?
  - Is a brief auto-created with `cluster_action='append_to_existing'`?
  - Does it auto-enqueue the article generation pipeline?
  - Or just create pending brief that Marcel approves separately?

7. **Existing UI**
  - Search `apps/web/src` for any gap-related components
  - Note: 56.2 Cluster Detail already shows pending spokes — is this related?
  - Confirm if gap analysis has any UI today

8. **Backend status**
  - Is the gap analysis pipeline fully implemented, or partially / stubbed?
  - Are there TODO comments in the code?
  - Has any cluster ever been analyzed for gaps in production? Check DB for any content_gaps rows

### Area C: Refresh Detection

**Goal**: Understand how outdated articles are detected and surfaced for refresh.

**Questions to answer**:

1. **Detection pipeline**
  - Is there a `refresh-detection` or `staleness-check` pipeline?
  - Path to pipeline definition?
  - How does it determine if an article needs refresh? (Last-updated date? LLM check on content freshness? External signals like "this tool was acquired"?)

2. **Data model**
  - Is there a `staleness_score` column on `articles`? Or in a separate table?
  - Schema path + relevant fields
  - How is "needs refresh" signaled? Score threshold? Boolean flag? Event-driven?

3. **API endpoints**
  - List endpoints matching `refresh`, `staleness`, `outdated`
  - Note: existing `POST /api/articles/:id/refresh` triggers the refresh PIPELINE (different from detection)
  - Is there a separate `POST .../refresh-detection` that just identifies candidates?
  - Is there a listing endpoint for "articles needing refresh"?

4. **Triggering**
  - Manual trigger endpoint?
  - Cron / scheduled trigger? (vermutlich monthly? weekly?)
  - Per-project config?

5. **Brief creation**
  - When refresh is detected, is a brief auto-created with `source='refresh_detection'`?
  - Where in the code does this happen?

6. **Refresh detection vs refresh execution**
  - The user wants to distinguish:
    - **Detection** = "this article is stale, consider refreshing" (passive signal)
    - **Execution** = "actually run the refresh pipeline that costs ~€0.40"
  - Confirm that backend has these as separate concerns
  - If detection is missing entirely → flag it

7. **Existing UI**
  - Search for refresh/staleness related components
  - Article Cards show a "needs refresh" indicator anywhere?
  - Filter for "stale articles" anywhere?

### Area D: Cross-cutting

1. **Cron infrastructure**
  - Is BullMQ used for repeating jobs? Or system cron? Or external scheduler?
  - Where are repeating jobs configured?
  - How do you enable/disable a cron job? (Code change? DB flag? Env var?)
  - List all currently configured repeating jobs related to content discovery

2. **Per-project config**
  - Where are project-level toggle flags stored? (`projects` table column? Separate config table?)
  - Existing examples: `translationAutoTrigger` — show the schema definition
  - Pattern for adding new toggles?

3. **Notification on discovery**
  - When a trend/gap/refresh is discovered, is there a notification mechanism?
  - SSE pipeline-events channel includes discovery events?
  - Are unread notifications created in `/api/notifications/*`?

4. **Cost tracking**
  - Discovery operations consume LLM tokens. Are they tracked in `cost_logs`?
  - What `operation` values exist for discovery? (e.g. `trends_discover`, `gap_analyze`, `staleness_check`)

5. **Approval workflow**
  - Existing briefs have `approval_status` enum: `pending`, `approved`, `dismissed`, `completed`
  - Do trends/gaps have separate approval enums, or do they all flow into the same `topic_briefs` lifecycle?

## Constraints

- **Do not implement anything.** This is read-only investigation.
- **Do not speculate.** If you can't find something in the code, say "not found — likely missing" rather than inferring.
- **Paste actual code.** When asked for schema or prompts, paste the real code, not paraphrases.
- **List actual file paths.** With `apps/api/src/...` or `packages/.../...` etc. — not vague "in the routes file".
- **Be exhaustive on file searches.** Use `rg` (ripgrep) and `fd` thoroughly. Don't stop after one search returns nothing.
- **Check git history if needed.** If a feature looks half-implemented, check recent commits to understand the state.
- **Time budget**: aim for ~30-45 minutes. If you're exceeding 1 hour, save what you have and note "investigation incomplete in section X".
