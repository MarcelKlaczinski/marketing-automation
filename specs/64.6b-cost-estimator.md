# Spec 64.6b — Cost-Estimator + Rate-Limits + Resolution-Toggle

_Extension of Spec 64.6 (Hero-Image Quality Bundle, DEPLOYED 2026-05-23)._
_Status: Draft._
_Voraussetzung: Spec 64.6 deployed — adapter `@marketing-auto/adapter-nano-banana`, projects.image_generation_provider column, cost_service enum erweitert um 'google-gemini'._
_Aufwand: ~1.5h Implementation + ~30 Min Tests._

---

## 1. Problem

Spec 64.6 ist deployed. Adapter funktioniert, Outline-Rule + seed sind durch. Aber:

**Was 64.6 NICHT adressiert:**
- **Cost-Estimator** ist hardcoded auf Flux-Rate (€0.038). Nach Migration auf Nano Banana 2 schätzt der Estimator Plans massiv zu niedrig. Marcel approved Plan mit falschen Erwartungen.
- **Resolution ist hardcoded** (vermutlich 1K). Premium-Quality (2K) braucht code-change pro Toolwiki-Wechsel. Sollte per-project toggleable sein.
- **Rate-Limit-Handling unklar.** 64.6 hat retry für 5xx + network errors, aber **kein 429-aware backoff**. Google's Tier 1 limit ist 250 RPD — bei Scale-Spike (z.B. Plan-Approve mit 14 Hero-Images simultan) könnten 429 errors auftreten.
- **Keine Quota-Documentation.** Bei Scale-Discussions (>100 Articles/Monat) gibt's keine Quelle wann wir Tier-Upgrade brauchen.

**Konsequenzen ohne 64.6b:**
- Plan-Cost-Drift (Estimate vs Actual)
- Resolution-Wechsel braucht code-deploy statt project-setting
- 429-Spike crasht Pipeline statt graceful retry
- Keine Scale-Planning-Basis

## 2. Ziel

**Vier orthogonale Erweiterungen:**

**Fix A: Cost-Estimator Provider + Resolution-Aware** — Plan-Estimator liest `projects.image_generation_provider` + `projects.image_generation_resolution`, nutzt korrekte rate aus 2D-Map.

**Fix B: Resolution-Toggle** — neue column `projects.image_generation_resolution` (analog zu provider-toggle pattern Memory D23). Adapter sendet entsprechende Resolution an Gemini API.

**Fix C: 429-Aware Retry im Adapter** — Adapter-level exponential backoff für rate-limit (1s/2s/4s). 5xx + network bleiben wie deployed (500ms/1s/2s).

**Fix D: Quota-Documentation** — packages/adapters/nano-banana/CLAUDE.md mit tier-limits + Toolwiki-Usage-Profile + Scale-Thresholds.

**In Scope:**
- DB Migration: `ALTER TABLE projects ADD COLUMN image_generation_resolution text NOT NULL DEFAULT '1k'`
- Adapter erweitern: `NanoBananaInput.resolution` parameter, sendet `imageConfig.outputResolution` to Gemini
- Cost-Estimator: 2D-Map (provider × resolution) für sync mode
- Plan-Cost-Estimator: liest project resolution + provider
- Adapter Retry-Logic: 429 backoff (1s/2s/4s) ergänzt zu existing 5xx/network
- CLAUDE.md: rate-limits + usage-profile + scale-thresholds
- Tests: cost-estimator (8 cases: provider × resolution), adapter retry (3 cases: 429)

**Out of Scope:**
- Batch-Mode für Cost-Reduction (50% discount) — eigene Spec 64.7
- Cost-Tracking Stages (estimate + actual) — eigene Spec 64.7 (mit Batch zusammen)
- Budget-Guardrails (cost_limits.max_eur_per_day) — eigene Mini-Spec wenn nötig
- Auto-Fallback zu Flux bei wiederholten 429 — defensive Decision
- Multi-Project Quota-Pooling — Toolwiki ist single project
- Nano Banana Pro 4K pricing (existing $0.24, irrelevant für Toolwiki)

**Aufwand:** ~1.5h Implementation + ~30 Min Tests.

```ts
import type { NanoBananaResolution } from "@marketing-auto/adapter-nano-banana";

// Existing NANO_BANANA_PRICING_USD_PER_IMAGE constants get widened from single value to map:

export const NANO_BANANA_2_PRICING_USD: Record<NanoBananaResolution, number> = {
  "0.5k": 0.045,
  "1k":   0.067,
  "2k":   0.101,
  "4k":   0.151,
};

export const NANO_BANANA_PRO_PRICING_USD: Record<NanoBananaResolution, number> = {
  "0.5k": 0.045,  // not officially supported, fallback to flash
  "1k":   0.134,
  "2k":   0.134,  // Google charges same as 1K (same token count)
  "4k":   0.240,
};

export const EUR_PER_USD = 0.92;  // existing constant

/**
 * Calculate cost in EUR for nano-banana image generation.
 * Used by adapter post-call AND cost-estimator pre-flight.
 */
export function nanoBananaImageCostEur(input: {
  model: "nano-banana-2" | "nano-banana-pro";
  resolution: NanoBananaResolution;
  count: number;  // batch-friendly
}): number {
  const usdMap = input.model === "nano-banana-2" 
    ? NANO_BANANA_2_PRICING_USD 
    : NANO_BANANA_PRO_PRICING_USD;
  return usdMap[input.resolution] * input.count * EUR_PER_USD;
}
```

```ts
};
```

### 3.5 Adapter Retry-Logic Erweiterung (Fix C)

**File:** `packages/adapters/nano-banana/src/client.ts` (von 64.6 deployed)

**Existing (64.6):** 3× retry mit exponential backoff für 5xx + network errors. 4xx fail-fast.

**Erweiterung für 429:**

```ts
async function callGeminiWithRetry(...): Promise<GeminiResponse> {
  for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt++) {
    const response = await fetch(...);
    
    // NEW: 429 rate-limit → longer backoff (1s/2s/4s)
    if (response.status === 429) {
      const backoffMs = Math.pow(2, attempt) * 1000;
      log.warn({ attempt, backoffMs, status: 429, model: input.model }, 
        "gemini rate-limited, backing off");
      
      if (attempt < MAX_ATTEMPTS - 1) {
        await sleep(backoffMs);
        continue;
      }
      throw new NanoBananaGenerationError("Rate limited after 3 attempts");
    }
    
    // EXISTING: 5xx + network handling (unchanged)
    if (response.status >= 500) { /* ... */ }
    
    // EXISTING: 4xx fail-fast (unchanged)
    if (!response.ok) { /* ... */ }
    
    return parsed;
  }
}
```

**Decision:** 429 backoff (1s/2s/4s = max 7s) ist deutlich aggressiver als 5xx (500ms/1s/2s = max 3.5s). Begründung: rate-limit recovery braucht längere Recovery-Window. Plus: 4xx (non-429) bleibt fail-fast — 400 invalid prompt soll nicht retry'd werden.

```markdown
## Rate Limits & Quota Management

### Tier 1 (paid) Limits (verified 2026-05-23)

Quotas apply **per Google Cloud Project**, NOT per API-key.

| Limit | Value | Reset |
|---|---|---|
| RPM (Requests/Min) | 150-300 | rolling 60s |
| TPM (Tokens/Min) | tier-specific | rolling 60s |
| **RPD (Requests/Day)** | **250** | midnight Pacific Time |
| IPM (Images/Min) | tier-specific | rolling 60s |

### Toolwiki Usage Profile (May 2026)

- ~3.4 images/day avg
- ~14 images/day burst (Plan-Approve-Spike)
- **Massiv unter Tier 1 limits — kein Quota-Issue erwartet bei aktueller Article-Rate**

### Scale Thresholds (wann Tier-Upgrade nötig)

| Article-Rate | Daily Hero-Images | Headroom vs 250 RPD |
|---|---|---|
| 50/Monat (current) | ~3.4/day | 70× |
| 200/Monat | ~13/day | 19× |
| 500/Monat | ~33/day | 7× |
| 1000/Monat | ~66/day | 3.8× |
| **2500/Monat** | **~165/day** | **1.5× — close to limit** |

**Decision-Point:** Bei >1000 articles/Monat: Tier 2 upgrade ($250 cumulative spend, 3 days minimum).

### Adapter Retry-Logic

Bei 429:
1. Exponential backoff: 1s → 2s → 4s
2. Nach 3 attempts: throw `NanoBananaGenerationError`
3. Pipeline-runner catches, marks pipeline_run failed
4. BullMQ retries job (configured retry count)

Bei 5xx:
1. Faster backoff: 500ms → 1s → 2s
2. Nach 3 attempts: throw
3. Plus: log.warn mit response-body

Bei 4xx (non-429):
- Fail-fast (kein retry)
- 400 invalid prompt → User-fix nötig

### Resolution Pricing Reference

| Resolution | USD/Image | EUR/Image | Use-Case |
|---|---|---|---|
| 0.5K (512px) | $0.045 | €0.041 | Thumbnails, social-preview |
| **1K (1024px)** | **$0.067** | **€0.062** | **Editorial Hero (Toolwiki default)** |
| 2K | $0.101 | €0.093 | Premium-Quality, Retina-displays |
| 4K (4096px) | $0.151 | €0.139 | Print-Quality (overkill für blog) |

Toggleable via `projects.image_generation_resolution`. Default '1k'.

### API-Key Management

API-Key live im vault: `setGlobal('nano-banana', 'api_key', '<key>')` oder env `GOOGLE_GEMINI_API_KEY`.

Plus: aktiviere "Restrict to Gemini API" in AI Studio damit Key bei leak nicht für andere Google-APIs missbraucht werden kann.

Plus: <https://aistudio.google.com/apikey> regelmäßig nutzen damit Dormant-Block (May 2026 policy change) nicht greift.
```

## 7. Risiken

| Risk | Mitigation |
|---|---|
| Existing `NANO_BANANA_PRICING_USD_PER_IMAGE` constant (single value) bricht callers wenn umstrukturiert | Sanftere Migration: alte constant deprecaten, neue Map-API parallel, deprecation-warn |
| Gemini API rejects '2048' als outputResolution string (vielleicht nur "2K" akzeptiert) | Phase 0 verifiziert exact API schema; falls Format anders, MAP entsprechend anpassen |
| EUR_PER_USD ändert sich (aktuell 0.92) | Existing constant in cost-tracker — periodisches Review als Phase-E Item |
| Plan-Cost-Estimator zählt translation-sibling-hero-images getrennt | Phase 0 verifiziert (Discovery 64.7 hat das bestätigt: sibling-inheritance per 59.2); sollte nicht double-counted sein |
| 4xx-fail-fast verliert legitimate retries (z.B. transient 401) | 401 sehr selten; bewusst nicht retry'd |
| Adapter-Tests Mocking-Frameworks brechen wegen response-shape-changes | Tests updaten parallel zu adapter changes |
| Resolution-column rejected wenn CHECK constraint zu strict | Initial migration, kein widening — wenn 0.5k später nicht akzeptabel, eigene Migration |
