# Spec 64.6b — Cost-Estimator Update + Rate-Limits Handling for Nano Banana 2

_Extension of Spec 64.6 (Hero-Image Quality Bundle). Status: Draft._
_Voraussetzung: Spec 64.6 deployed (Nano Banana 2 Adapter + Hero-Image Step migration + project_configurations.image_generation)._
_Aufwand: ~1h Implementation + ~20 Min Tests._

---

## 1. Problem

Spec 64.6 migriert Hero-Image von Flux 1.1 Pro ($0.04) auf Nano Banana 2 (~$0.062). Plus: provider-config wird per-project konfigurierbar (`project_configurations.image_generation.provider`).

**Was 64.6 NICHT adressiert:**
- Plan-Cost-Estimator hardcoded auf Flux-Rate (€0.04) — schätzt Plans zu niedrig
- Keine Rate-Limit-Aware Retry-Logic (429 errors werden hart geworfen statt backoff)
- Keine Documentation der Google Gemini Quotas

**Konsequenzen ohne 64.6b:**
- **Cost-Drift:** Marcel approved Plan basierend auf €0.04-Estimate, real-cost €0.062 → +55% pro Hero-Image (Plan-Budget vs Real-Spend Mismatch)
- **Brittle bei Rate-Limits:** 429 errors crashen Pipeline statt graceful retry
- **Plus später bei Scale:** ohne Documentation kein Bewusstsein wann wir an Limits stoßen

## 2. Ziel

**Drei orthogonale Erweiterungen:**

**Fix A: Cost-Estimator Provider-Aware** — Plan-Estimator liest `project.image_generation.provider` und nutzt korrekte rate.

**Fix B: 429-Aware Retry im Adapter** — Adapter-level exponential backoff für rate-limit + 5xx errors.

**Fix C: Quota-Documentation** — packages/adapters/nano-banana/CLAUDE.md dokumentiert tier-limits damit zukünftig bei Scale-Discussions klar ist wann wir an Wände stoßen.

**In Scope:**
- Cost-Estimator File finden + IMAGE_COST_PER_CALL_EUR Map erweitern
- estimateHeroImageCost() provider-aware
- Plan-Cost-Estimation liest project.image_generation.provider
- Adapter-Code 429-aware (1s/2s/4s backoff)
- Adapter-Code 5xx-aware (500ms/1s/2s backoff)
- CLAUDE.md in adapter package mit quota docs
- Tests: 3 cost-estimator cases + 2 retry cases

**Out of Scope:**
- Budget-Guardrails (cost_limits.hero_image.max_eur_per_day) — eigene Spec wenn nötig
- Distributed-Tracing für rate-limit-events — eigene Spec
- Multi-Project Quota-Pooling (Google project-level limit) — Toolwiki ist single project, kein Issue
- Batch-Mode für Cost-Reduction (50% discount async, aber 24h SLA inkompatibel)
- Auto-Fallback zu Flux bei wiederholten 429 — siehe §6 Risiken (defensive Decision)

**Aufwand:** ~1h Implementation + ~20 Min Tests.

```ts
// packages/cost-tracker/src/image-rates.ts (vermutlich neu oder existing erweitert)

export type ImageProvider = "nano-banana-2" | "nano-banana-pro" | "flux-1.1-pro";

/**
 * Per-image generation cost in EUR (2K resolution).
 * Verified 2026-05-23 against provider pricing pages.
 */
export const IMAGE_COST_PER_CALL_EUR: Record<ImageProvider, number> = {
  "nano-banana-2": 0.062,   // Google Gemini Flash Image, $0.067 @ 0.93 EUR/USD
  "nano-banana-pro": 0.124, // Google Gemini Pro Image, $0.134 @ 0.93 EUR/USD
  "flux-1.1-pro": 0.038,    // Replicate Black Forest Labs, $0.04 @ 0.93 EUR/USD
};

/**
 * Estimate hero-image cost based on project's configured provider.
 * Falls back to flux-1.1-pro rate if project config missing.
 */
export function estimateHeroImageCost(provider: ImageProvider | undefined | null): number {
  if (!provider) return IMAGE_COST_PER_CALL_EUR["flux-1.1-pro"];
  return IMAGE_COST_PER_CALL_EUR[provider] ?? IMAGE_COST_PER_CALL_EUR["flux-1.1-pro"];
}
```

### 3.3 Adapter Retry-Logic (Fix B)

**File:** `packages/adapters/nano-banana/src/client.ts` (von Spec 64.6)

**Pattern:**

```ts
async function callGeminiApi(
  endpoint: string,
  payload: Record<string, unknown>,
  apiKey: string,
): Promise<GeminiResponse> {
  const MAX_ATTEMPTS = 3;
  let lastError: Error | null = null;
  
  for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt++) {
    try {
      const response = await fetch(endpoint, {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "x-goog-api-key": apiKey,
        },
        body: JSON.stringify(payload),
      });
      
      // Rate-limited — exponential backoff
      if (response.status === 429) {
        const backoffMs = Math.pow(2, attempt) * 1000; // 1s, 2s, 4s
        log.warn(
          { attempt, backoffMs, status: 429 },
          "gemini api rate-limited, backing off",
        );
        await sleep(backoffMs);
        lastError = new Error("Rate limited (429)");
        continue;
      }
      
      // Server error — retry with shorter backoff
      if (response.status >= 500) {
        const backoffMs = Math.pow(2, attempt) * 500; // 500ms, 1s, 2s
        log.warn(
          { attempt, backoffMs, status: response.status },
          "gemini api server error, backing off",
        );
        await sleep(backoffMs);
        lastError = new Error(`Server error (${response.status})`);
        continue;
      }
      
      // 4xx (non-429) — don't retry, fail immediately
      if (!response.ok) {
        const errorText = await response.text();
        throw new Error(`Gemini API client error: ${response.status} - ${errorText}`);
      }
      
      // Success
      return await response.json();
    } catch (err) {
      // Network error — retry
      if (attempt < MAX_ATTEMPTS - 1) {
        const backoffMs = Math.pow(2, attempt) * 500;
        log.warn({ attempt, backoffMs, err }, "gemini api network error, retrying");
        await sleep(backoffMs);
        lastError = err as Error;
        continue;
      }
      throw err;
    }
  }
  
  throw lastError ?? new Error("Gemini API failed after 3 attempts");
}
```

**Decision:** 429 backoff (1s/2s/4s) ist aggressiver als 5xx (500ms/1s/2s) weil rate-limits längere Recovery brauchen. Plus: 4xx non-429 sofort fehlschlagen (z.B. 400 invalid prompt → kein retry sinnvoll).

### 3.4 Quota-Documentation (Fix C)

**File:** `packages/adapters/nano-banana/CLAUDE.md` (neu oder erweitert)

**Inhalt:**

```markdown
# Nano Banana Adapter (Google Gemini Image API)

## Rate Limits (verified 2026-05-23)

Quotas apply **per Google Cloud Project**, NOT per API-key.
Multiple keys share the same quota pool.

### Tier 1 (paid)

| Limit Type | Value | Reset |
|---|---|---|
| RPM (Requests/Min) | 150-300 | rolling 60s |
| TPM (Tokens/Min) | tier-spezifisch | rolling 60s |
| **RPD (Requests/Day)** | **250** | midnight Pacific Time |
| IPM (Images/Min) | tier-spezifisch | rolling 60s |

### Toolwiki Usage (May 2026)

~3.4 images/day avg, ~14 images/day burst (Plan-Approve-Spike).
**Massiv unter Tier 1 limits — kein Quota-Issue erwartet bei aktueller Article-Rate.**

### Scale-Thresholds (wann wir aufpassen müssen)

| Article-Rate | Daily Hero-Images | Headroom vs 250 RPD |
|---|---|---|
| 50/Monat (current) | ~3.4/day | 70x |
| 200/Monat | ~13/day | 19x |
| 500/Monat | ~33/day | 7x |
| 1000/Monat | ~66/day | 3.8x |
| **2500/Monat** | **~165/day** | **1.5x — close to limit** |

Bei >1000 articles/Monat: Tier 2 upgrade ($250 cumulative spend) oder Google Cloud Project split.

### Beim 429 — Adapter Behavior

Adapter retry-logic (siehe client.ts):
1. Exponential backoff: 1s → 2s → 4s
2. Nach 3 attempts: throw Error
3. Pipeline-runner catches, marks pipeline_run as failed
4. BullMQ retries job (configured retry count + delay)

### Beim 5xx — Adapter Behavior

Adapter retry-logic:
1. Faster backoff: 500ms → 1s → 2s
2. Nach 3 attempts: throw Error
3. Plus: log.warn mit response-body für debugging

### Plus: Restrict-to-Gemini-API enable

API-Key sollte in AI Studio mit "Restrict to Gemini API" gesetzt sein
(prevents misuse als general Google Cloud key).

Plus: <https://aistudio.google.com/apikey> regelmäßig nutzen damit
Dormant-Block (May 2026 policy change) nicht greift.
```

## 7. Risiken

| Risk | Mitigation |
|---|---|
| Cost-Estimator File existiert nicht — neuer Helper nötig | Phase 0 klärt; falls fehlt, in packages/cost-tracker bauen |
| EUR-Wechselkurs für USD-Cost ändert sich (aktuell ~0.93) | Rates als Konstanten dokumentiert; periodisches Review als Phase-E Item |
| Plan-Cost-Estimator zählt sibling-hero-images getrennt → doppelte Cost-Schätzung | Phase 0 verifiziert sibling-inheritance; falls double-counted → separater Bug, eigene Mini-Spec |
| Retry-Logic Backoff zu aggressiv für lange Pipelines (Worker-Timeout) | Max retry-time = 4s + 2s + 4s = 10s max delay, weniger als typische worker-timeouts |
| 4xx-fail-fast verliert legitimate retries (z.B. transient 401 wegen token-refresh) | 401 ist sehr seltener Edge-Case; bewusst nicht retry'd weil "user fix" nötig |
| Tier-2 upgrade ($250 spend) nicht möglich für Toolwiki | Bei aktueller Scale (50 articles/Monat) Tier 1 ausreichend; Upgrade-Discussion bei >500/Monat |
