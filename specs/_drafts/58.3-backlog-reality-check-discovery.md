# Discovery Prompt: Backlog Reality-Check

**Purpose:** Verify the current state of the codebase against the Master Backlog. After Themes 54–58 (lots of overlapping work), the Backlog has accumulated items where it's unclear if they're still relevant, partially built, or fully implemented. This prompt produces a verified list mapping each Backlog item to its actual code state — so the next Master Backlog revision is grounded in reality, not memory.

**Run with:** `/discover-task backlog-reality-check.md`

**Expected runtime:** ~60-90 minutes

**Output:** Single Markdown file at `specs/_drafts/backlog-reality-check.md`. Read-only investigation, no code changes.

**Scope:** Full-stack — backend (routes, DB, pipelines, workers, queues), frontend (Vue components, composables, routes, i18n), tests, build system, CLAUDE.md docs.

---

## How to Use This Prompt

For each item below, the report should answer THREE questions:

1. **State**: ❌ Not built / 🟡 Partially built / ✅ Fully built / 🪦 Fossil (existed once, dead now)
2. **Evidence**: File paths, function names, schema fields, line counts proving the state
3. **Recommendation**: Keep in backlog / Update backlog estimate / Remove from backlog / Needs migration

Be **specific**. "Looks done" is not useful. "GET /api/projects/:slug/articles/count exists at `apps/api/src/routes/articles/count.routes.ts` with implementation that joins articles + filters by created_at window — but the frontend `DashboardHeader.vue` line 47 still has hardcoded `'0'` instead of calling it" is useful.

## Constraints

- **Read-only.** No code changes.
- **Be specific.** Paste file paths, function names, schema fields. Vague verdicts are useless.
- **Distinguish "exists" from "complete".** A stub TemplateKey in a union is NOT the template being built.
- **Acknowledge uncertainty.** If a verification is ambiguous (e.g. "looks unused but I'm not 100% sure if there's a UI consumer I missed"), say so explicitly.
- **Time budget**: ~60-90 min. Sections 1 + 2 (verification + possibly-built) are highest priority — spend more time there. Section 3 + 4 (sweep) can be brief. Section 5 ("what did we forget") is most valuable if you find anything unexpected.
