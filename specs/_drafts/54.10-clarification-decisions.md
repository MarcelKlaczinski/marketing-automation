## Q-B4 Followup: Adaptive Decision Mechanism

**Choice: (1) LLM-Call beim Start der Translation**

The translation pipeline starts with a Sonnet 4.6 call (or Haiku 4.5 — see optimization note below) that evaluates:
- DE article body
- Target locale (EN)
- Brief metadata if available
- Returns: `{ needsOwnOutline: boolean; reasoning: string }`

**Rationale for LLM-Decision over alternatives**:
- Heuristic-based (option 3) blind for nuanced cases (e.g., article uses "Made in Germany" framing that needs reframing for US audience but no obvious German-specific keywords)
- Per-Cluster config (option 2) requires upfront classification work; doesn't adapt to per-article variation within cluster
- LLM-Call costs ~€0.02 per translation, less than the cost saved by avoiding unnecessary Outline runs (~€0.15 saved when translate-only path chosen)

**Optimization note**: This decision call is good Haiku 4.5 task (classification with reasoning).
- Cost with Haiku: ~€0.005 per decision call
- Cost with Sonnet: ~€0.02 per decision call
- Decision logic is binary classification; Haiku exzellent for this

**Decision criteria the LLM evaluates**:
- Does the article reference German-specific pricing (EUR amounts that map poorly to USD)?
- Does it reference German market context (DSGVO emphasis, BaFin, German-only tools)?
- Does it use cultural framing that needs adaptation ("Mittelstand", "Made in Germany", local examples)?
- Does the source brief explicitly request audience-specific framing?

**Workflow integration**:
```
[DE Blog Pipeline completes]
    ↓
[Translation Pipeline starts]
    ↓
[LLM Decision Call: needs own Outline?]
    ├─ YES → Run Outline (EN-audience) → Draft (translate-aware) → SelfReview → Schema
    └─ NO  → Draft (translate-only) → SelfReview → Schema
                                                           ↓
                                                  [EN Article persisted]
```

**Cost impact**:
- Translate-only path: €0.50 + €0.005 (decision call) = ~€0.51
- Adaptive path with Outline: €0.65 + €0.005 = ~€0.66
- Average per EN sibling: ~€0.55 (assuming 30% need full Outline)

**LLM Prompt sketch** (for 54.10 spec writeup):
```
You are evaluating whether a German blog article needs an English-audience-specific outline 
adaptation or can be translated directly.

DE Article Body:
{body_md}

Brief Context:
{brief_metadata}

Evaluate whether the article should be:
- "literal": EN version preserves DE outline; only language changes
- "adaptive": EN audience needs different angles (US/UK market context, different examples, different pricing model)

Respond in JSON:
{
  "decision": "literal" | "adaptive",
  "reasoning": "brief explanation (max 100 words)"
}
```

## Cost Implications

Combined Phase C+ blog pipeline cost per fresh article + EN sibling:

| Step | Cost EUR | Note |
|---|---|---|
| DE Blog Pipeline (Spec 54.9) | ~1.17 | Sonnet+Haiku, validated in 54.9 Session 5 |
| Translation Decision Call (Haiku) | ~0.005 | Per EN sibling |
| EN Translation (translate-only path) | ~0.50 | 70% of articles fall here (estimate) |
| EN Translation (adaptive path, with Outline) | ~0.65 | 30% of articles fall here (estimate) |
| **Avg EN sibling cost** | **~0.55** | 0.005 + (0.7 × 0.50) + (0.3 × 0.65) |
| **Total per DE+EN pair (avg)** | **~1.72** | DE + EN sibling avg |

Refresh:
| Step | Cost EUR |
|---|---|
| DE Refresh (full re-gen with voice-continuity) | ~1.20 |
| Translation Decision Call (for refresh's EN sibling) | ~0.005 |
| EN Translation (auto-triggered if DE-EN pair exists) | ~0.55 (avg) |
| **Total per refresh (DE+EN)** | **~1.76** |

For toolwiki at scale (30 fresh + 5 refreshes / month):
- 30 × €1.72 = €51.60 fresh
- 5 × €1.76 = €8.80 refresh
- **Total monthly: ~€60** for content generation (DE+EN combined)

This is sustainable for solo-dev cost target. Original all-Opus estimate would have been ~€140/month for same volume — €80/month savings from model selection.
