## Goal

Migrate the existing Cold-Start onboarding wizard to the new glassmorphism design system. This is **the final sub-spec of Theme 56** — after this, the entire UI refactoring is complete (modulo the Cleanup-Audit pass in 56.5).

Cold-Start onboards a new project: gather basics (name, domain, industry) → brand identity → seed content (authors, pillars) → optional Astro Repo connection → confirm. Triggers initial content generation pipelines.

After this spec lands:
- The wizard matches the glassmorphism design language used throughout the rest of the app
- All wizard steps use the FormSection/FormField components from 56.3
- All user-visible text via i18n keys
- Multi-step wizard with progress indicator
- "Save & Continue Later" exit at any step

What's NOT in 56.4: changes to the Cold-Start backend logic itself. The pipeline behavior, prompt content, and step structure stay as-is. This is **polish only**.

## What this is NOT

- Not changing Cold-Start pipeline logic — that's a separate concern
- Not adding new Cold-Start phases — the 5-phase structure stays
- Not adding Social Media template selection to Cold-Start — Theme 57 territory
- Not adding multi-project simultaneous-onboarding flow — single-project at a time
- Not adding "import existing project" wizard variant — Phase E
- Not running a full UX redesign of Cold-Start — visual + interaction polish only

## Section A: Inventory of Existing Cold-Start

### A.1 Backend endpoints (no changes)

The current backend exposes these Cold-Start endpoints which remain unchanged:

- `POST /api/cold-start/initialize` — create draft project from basics
- `PATCH /api/cold-start/:draftId` — update draft data
- `GET /api/cold-start/:draftId` — load draft for resume
- `GET /api/cold-start/:draftId/state` — current phase + completion state
- `POST /api/cold-start/:draftId/advance` — move to next phase
- `POST /api/cold-start/:draftId/back` — return to previous phase
- `POST /api/cold-start/:draftId/finalize` — convert draft to active project
- `POST /api/cold-start/:draftId/abandon` — discard draft
- `POST /api/cold-start/:draftId/brand-discovery` — async LLM brand discovery from domain
- `GET /api/cold-start/:draftId/brand-discovery/status` — poll brand discovery
- `POST /api/cold-start/:draftId/seed-pillars` — generate pillar suggestions via LLM
- `POST /api/cold-start/:draftId/seed-authors` — generate author personas via LLM
- `POST /api/cold-start/:draftId/connect-astro` — link Astro repo

### A.2 The 5 phases

```
Phase 1: Basics
  - Project name
  - Domain (optional, used for brand-discovery)
  - Industry
  - Target locales (DE, EN, both)
  - Marketing context (free text or "skip for now")

Phase 2: Brand Identity
  - Trigger brand-discovery from domain (async LLM call)
  - Review + edit discovered brand tokens
  - Manual override if discovery fails or Marcel disagrees

Phase 3: Content Seed
  - Pillar suggestions (LLM-generated based on industry + brand)
  - Author personas (3-5 personas, LLM-generated)
  - Marcel approves, rejects, or edits suggestions

Phase 4: Astro Integration (optional)
  - Path to local Astro repo
  - Deploy target
  - Skip if Marcel will set this up later

Phase 5: Confirm + Launch
  - Summary of all decisions
  - Cost estimate for initial content generation
  - "Create project" button → triggers backend finalize
  - Auto-navigates to new project's Dashboard
```

### A.3 What the legacy UI did

The legacy UI rendered Cold-Start as a Quasar Stepper with 5 sequential pages. Each page used Material-design `q-input`, `q-select`, `q-card`. Submit-on-blur for fields. No glassmorphism. No animations between steps.

The migration replaces all visual layer but keeps the same step structure + backend flow.

### B.4 useColdStartDraft composable

```typescript
// apps/web/src/composables/useColdStartDraft.ts
import { ref, computed, watch } from "vue";
import { useRoute, useRouter } from "vue-router";
import { useQuery, useMutation, useQueryClient } from "@tanstack/vue-query";

/**
 * Shared composable for cold-start draft state across all phases.
 * Loads draft from URL param, exposes state + actions.
 */
export function useColdStartDraft() {
  const route = useRoute();
  const router = useRouter();
  const queryClient = useQueryClient();
  
  const draftId = route.params.draftId as string;
  
  const { data: draftData, isLoading } = useQuery({
    queryKey: ["cold-start-draft", draftId],
    queryFn: () => apiGet(`/api/cold-start/${draftId}`),
    enabled: () => !!draftId,
  });
  
  const { data: stateData } = useQuery({
    queryKey: ["cold-start-state", draftId],
    queryFn: () => apiGet(`/api/cold-start/${draftId}/state`),
    enabled: () => !!draftId,
    refetchInterval: (query) => {
      // Poll during brand-discovery (phase 2 has async LLM call)
      const state = query.state.data?.data;
      if (state?.currentPhase === 2 && state?.brandDiscoveryStatus === "running") {
        return 2000;
      }
      return false;
    },
  });
  
  const updateDraft = useMutation({
    mutationFn: (updates: Partial<ColdStartDraft>) => 
      apiPatch(`/api/cold-start/${draftId}`, updates),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["cold-start-draft", draftId] });
    },
  });
  
  const advance = useMutation({
    mutationFn: () => apiPost(`/api/cold-start/${draftId}/advance`),
    onSuccess: (response) => {
      queryClient.invalidateQueries({ queryKey: ["cold-start-state", draftId] });
      const nextPhase = response.data?.currentPhase;
      if (nextPhase) {
        router.push(`/cold-start/${draftId}/phase-${nextPhase}`);
      }
    },
  });
  
  const back = useMutation({
    mutationFn: () => apiPost(`/api/cold-start/${draftId}/back`),
    onSuccess: (response) => {
      queryClient.invalidateQueries({ queryKey: ["cold-start-state", draftId] });
      const prevPhase = response.data?.currentPhase;
      if (prevPhase) {
        router.push(`/cold-start/${draftId}/phase-${prevPhase}`);
      }
    },
  });
  
  const finalize = useMutation({
    mutationFn: () => apiPost(`/api/cold-start/${draftId}/finalize`),
    onSuccess: (response) => {
      const projectSlug = response.data?.project?.slug;
      if (projectSlug) {
        router.push(`/projects/${projectSlug}/dashboard`);
      }
    },
  });
  
  return {
    draftId,
    draft: computed(() => draftData.value?.data),
    state: computed(() => stateData.value?.data),
    isLoading,
    updateDraft: updateDraft.mutateAsync,
    advance: advance.mutateAsync,
    back: back.mutateAsync,
    finalize: finalize.mutateAsync,
    finalizing: finalize.isPending,
  };
}
```

        </label>
      </div>
    </FormField>
    
    <FormField
      :label="$t('coldStart.phases.basics.fields.marketingContext')"
      :helper="$t('coldStart.phases.basics.fields.marketingContextHelper')"
    >
      <FormTextarea
        v-model="form.marketingContext"

      />

<script lang="ts">
import { defineComponent } from "vue";
import { useColdStartDraft } from "@/composables/useColdStartDraft";

export default defineComponent({
  name: "ColdStartPhase1Basics",
  setup() {
    return useColdStartDraft();
  },
  data: () => ({
    form: {
      name: "",
      domain: "",
      industry: "",
      targetLocales: ["de"] as string[],
      marketingContext: "",
    },
    busy: false,
  }),
  computed: {
    isValid(): boolean {
      return this.form.name.length >= 2 && this.form.targetLocales.length > 0;
    },
    localeOptions() {
      return [
        { value: "de", flag: "🇩🇪", labelKey: "coldStart.locales.de" },
        { value: "en", flag: "🇬🇧", labelKey: "coldStart.locales.en" },
      ];
    },
  },
  watch: {
    draft: {
      immediate: true,
      handler(newDraft) {
        if (newDraft) {
          this.form.name = newDraft.name ?? "";
          this.form.domain = newDraft.domain ?? "";
          this.form.industry = newDraft.industry ?? "";
          this.form.targetLocales = newDraft.targetLocales ?? ["de"];
          this.form.marketingContext = newDraft.marketingContextMd ?? "";
        }
      },
    },
  },
  methods: {
    onToggleLocale(locale: string) {
      const idx = this.form.targetLocales.indexOf(locale);
      if (idx >= 0) {
        this.form.targetLocales.splice(idx, 1);
      } else {
        this.form.targetLocales.push(locale);
      }
    },
    async onAdvance() {
      if (!this.isValid) return;
      this.busy = true;
      try {
        await this.updateDraft({
          name: this.form.name,
          domain: this.form.domain || null,
          industry: this.form.industry || null,
          targetLocales: this.form.targetLocales,
          marketingContextMd: this.form.marketingContext || null,
        });
        await this.advance();
      } finally {
        this.busy = false;
      }
    },
  },
});
</script>

          type: "negative",
          message: err instanceof Error ? err.message : this.$t("coldStart.errors.initFailed"),

## Decisions Made

**Decision 1: Cold-Start is full-page outside AppShell.**
No sidebar, no topbar, no project context. Separate experience until project is created.

**Decision 2: 5-phase structure unchanged from legacy.**
Backend phases stay. Only UI visual + interaction polish.

**Decision 3: PhaseShell as wizard primitive.**
Consistent card-on-mesh layout across all phases. Back/Skip/Advance pattern uniform.

**Decision 4: Brand discovery polling at 2s during running state.**
Backend takes 10-30s for LLM brand-discovery. 2s polling balances UX vs server load.

**Decision 5: Form data pre-fills from draft on mount via watch.**
Per 56.3 `watch(project, resetFromUpstream)` pattern. Draft data loads async, form must wait.

**Decision 6: Phase 5 cost estimate is approximate.**
Based on real Spec 54.9 + 54.12 cost data. Pillar cluster ≈ €3.99, monthly ≈ €5. Not precise but useful expectation-setting.

**Decision 7: Save & Exit doesn't require explicit save action.**
Each PATCH saves draft. Save & Exit just navigates away. Draft can be resumed later.

**Decision 8: Cold-Start uses FormSection/FormField from 56.3.**
Reuse, don't reinvent. Same form pattern as Settings.

**Decision 9: No autosave-on-blur in Cold-Start.**
Each phase advances via explicit "Continue" button which saves. Aligns with 56.3 explicit-save pattern.

**Decision 10: AddProject entry in ProjectSelector.**
Single entry point to start onboarding. Discoverable via the project switcher Marcel already uses daily.

**Decision 11: Resume Draft option in ColdStartNewPage.**
If draft exists, offer to continue instead of starting fresh. Single draft per user, simple.

**Decision 12: Phase 3 Authors disabled until Pillars exist.**
Authors need pillar context for LLM generation. Sequential UX prevents broken state.

**Decision 13: PhaseShell allows custom advance label.**
Default "Continue", phase 5 shows "Launch Project" — context-appropriate.

**Decision 14: No new endpoints needed.**
All existing Cold-Start backend endpoints work. This is pure UI migration.

**Decision 15: i18n keys use `coldStart.phases.<phase>.<field>` structure.**
Hierarchical, predictable. Easy to find missing keys via grep.

## Discovered During Implementation

- `useColdStartDraft` composable: spec showed `stateData.value?.data` but `apiGet` already unwraps the `{ ok, data }` envelope — corrected to `stateData.value` (no `.data`). Same for draft query.
- The `refetchInterval` callback receives the TanStack Query query object; data lives at `query.state.data` (not `query.state.data?.data`).
- Phase 3 watch handler TypeScript error: `map((p) => ...)` parameters were implicitly `any` — fixed by adding explicit import types inline in the handler.
- No `/cold-start/drafts` route was defined; added a redirect to `/cold-start/new` (MVP: single draft per user at a time).
- Three hardcoded placeholder strings found in i18n audit (Phase2Brand `example.com`, Phase4Astro `/Users/me/my-astro-blog` and `src/content`) — extracted to `coldStart.phases.brand.placeholders.domain` and `coldStart.phases.astro.placeholders.*` keys.
- Session 1 and Session 2 commits were both deferred to end of Session 2; all three sessions committed sequentially after typecheck passed.

## Deviations

- `/cold-start/drafts` listed in spec as "Resume Draft" navigation target has no dedicated page spec. Implemented as a redirect to `/cold-start/new` — the new page already shows the resume button when drafts exist.
- Backend endpoints (`/cold-start/initialize`, `/cold-start/:draftId/*`) listed in Section A.1 are new wizard endpoints not yet implemented in the backend. Frontend is wired as spec'd; backend implementation is a separate task.
