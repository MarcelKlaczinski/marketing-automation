# Spec 64.20 — GitHub Tool-Inventory V1

**Status:** Proposed
**Effort:** ~5d code + 4–5h Marcel-Seed (Option C from discovery)
**Depends on:** none (vault key `"github"` already in use by signal-collector)
**Successor of:** [_drafts/github-inventory-discovery.md](_drafts/github-inventory-discovery.md)
**Strategic context:** Closes the content-foundation gap for Theme 65 Family A data-driven content (Profile-Pages + Comparison). Stable structured metadata (stars, releases, topics, language, license) sourced from GitHub-API — orthogonal to Theme 65.3 Part B's web-search-based `tool-data-refresh.worker.ts` (currency: pricing/features).

---

## 1. Problem

Toolwiki today has 108 tool-articles (`collection='tools'`) and a small SKILL.md ecosystem ready to be tracked. Both lack reliable, structured GitHub-side metadata:

- **Profile-pages** show static "stars: ~12k" hand-copied at write-time and drifting by the day.
- **Comparison articles** assert "Tool X has more stars than Tool Y" without an updatable source.
- **No tracking for Anthropic Skills** at all (the SKILL.md open standard, Dec 2025) — Marcel can't write "Top Skills" content because the data layer doesn't exist.
- **No Marcel-curated catalog** to which a recurring-content cron (Theme 65) can later attach.

Manual refresh per article doesn't scale; LLM-extracted refresh (Theme 65.3 Part B) is expensive and unreliable for structured numeric data. GitHub-API is free, structured, rate-limited but ample with a PAT.

## 2. Ziel

### In-scope (V1)

- **`content_source_inventory` table** — dedicated, source-agnostic, project-scoped (Schema α from discovery §4).
- **Two object-types:** `tool` + `skill`.
- **Marcel-Seed** (no Auto-Discovery V1): seed-CSV import + per-row CRUD in Settings-UI.
- **`@marketing-auto/adapter-github-inventory`** — typed adapter, vault-first, live-verify CLI.
- **Cron-Worker** `github-inventory-refresh.worker.ts` — refreshes rows whose `last_fetched_at` is older than the row's `refresh_interval_hours`.
- **Manual-Trigger endpoint** — `POST /api/projects/:slug/inventory/refresh` (bulk + per-row).
- **Settings-UI** — list/create/edit/delete inventory rows, refresh-now button, fetch-status badges.
- **Approve-gate column** — `approved_at NULL` rows are not refreshed; Marcel-Seed sets `approved_at` at INSERT, so V1 rows are pre-approved (the column exists for V1.1 Auto-Discovery additive-only).

### Out-of-scope (deferred)

- **Auto-Discovery** — GitHub Search-API + awesome-list-parser (discovery §5.3). Defer to V1.1 once V1 has data flowing; the schema's `approved_at NULL` path is forward-compat.
- **Release-Tracking news-content** (Angle C) — defer V1.1; pacing needs observation first.
- **Star-Trend-Stories** (Angle D) — defer V2 or never; brand-risk per discovery §3.4.
- **Profile-Pages article-template + Comparison-Article-template integration** — H3 ships only the data layer; the templates that consume `content_source_inventory` are Theme 65.7/65.10 work.
- **Cost-tracking** — GitHub-API is free; the existing `github-trending` signal adapter does NOT log to `cost_logs`. H3 follows the same convention (X-RateLimit headers monitored at worker-level only).

### Phase-0 corrections to the discovery doc

- **No `tools` table exists** — the 108 Toolwiki tools are `articles` rows with `collection='tools'`. Discovery §4.2 Option α had `tool_id REFERENCES tools(id)`; the spec FKs against `articles(id)` instead with `ON DELETE SET NULL` (inventory survives article deletion as historical record).
- **`cost_service` enum stays unchanged** — no `'github'` value added. Cost-tracking is skipped (free API).
- **Vault key `"github"` already in use** — `readAdapterCreds("github")` is the canonical path (signal-collector since Spec 59.1b). The H3 adapter shares the credential; no new credential-type.

## 3. Schema

### 3.1 New table `content_source_inventory`

```sql
-- Migration 0105_content_source_inventory.sql
CREATE TABLE content_source_inventory (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,

  -- Source taxonomy (forward-compat for gitlab/npm/pypi)
  source TEXT NOT NULL CHECK (source IN ('github')),
  object_type TEXT NOT NULL CHECK (object_type IN ('tool', 'skill')),
  source_identifier TEXT NOT NULL,
    -- Tool: "anthropics/claude-code"
    -- Skill (standalone): "coleam00/excalidraw-diagram-skill"
    -- Skill (in mono-repo): "anthropics/skills:web-design"

  -- Human-facing
  display_name TEXT NOT NULL,
  description TEXT,
  homepage_url TEXT,

  -- Structured metadata (typed bucket — D143 pattern, no generic field name)
  github_metadata JSONB NOT NULL DEFAULT '{}'::jsonb,
    -- { starsCount, forksCount, watchersCount, primaryLanguage, license,
    --   topics: string[], defaultBranch, createdAt, pushedAt,
    --   latestRelease: { tag, name, publishedAt } | null,
    --   skillFrontmatter?: { name, description, category, version } }

  -- Lifecycle
  fetch_status TEXT NOT NULL DEFAULT 'pending'
    CHECK (fetch_status IN ('pending', 'fetching', 'ok', 'error')),
  fetch_error TEXT,
  last_fetched_at TIMESTAMPTZ,
  refresh_interval_hours INT NOT NULL DEFAULT 168 CHECK (refresh_interval_hours BETWEEN 1 AND 8760),
    -- 168 = weekly default; 24 for high-priority; per-row tunable

  -- Approve-gate (V1: pre-approved via Marcel-Seed; V1.1: Auto-Discovery candidates)
  approved_at TIMESTAMPTZ,
  approved_by_user_id UUID REFERENCES users(id) ON DELETE SET NULL,

  -- Optional link to corresponding tool-article (NULL for skills + new tools)
  article_id UUID REFERENCES articles(id) ON DELETE SET NULL,
    -- Convention: if object_type='tool' AND article_id IS NOT NULL,
    -- THEN that articles row MUST have collection='tools'.
    -- Enforced at the application layer (helper-write + tests).

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Partial unique on approved rows (D108 pattern from Spec 005 IR1)
CREATE UNIQUE INDEX csi_project_source_identifier_approved_unique
  ON content_source_inventory (project_id, source, source_identifier)
  WHERE approved_at IS NOT NULL;

-- Cron candidate index (fetch-due rows)
CREATE INDEX csi_due_for_refresh_idx
  ON content_source_inventory (last_fetched_at NULLS FIRST)
  WHERE approved_at IS NOT NULL AND fetch_status IN ('ok', 'pending');

-- Lookup by article (for join in Settings-UI + future template consumers)
CREATE INDEX csi_article_id_idx
  ON content_source_inventory (article_id)
  WHERE article_id IS NOT NULL;

-- Lookup by project + object-type (Settings-UI list)
CREATE INDEX csi_project_object_type_idx
  ON content_source_inventory (project_id, object_type, fetch_status);
```

### 4.2 Client surface

```typescript
// packages/adapters/github-inventory/src/client.ts

export interface GitHubCredentials {
  personalAccessToken: string;
}

export interface RateLimitStatus {
  limit: number;
  remaining: number;
  resetAt: Date;
}

// Re-use error classes by re-export from github-trending if available,
// otherwise define identical: GitHubAuthError, GitHubRateLimitError, GitHubNotFoundError
export class GitHubAuthError extends Error { /* githubErrorKind = 'auth' */ }
export class GitHubRateLimitError extends Error { /* githubErrorKind = 'rate_limit' */ }
export class GitHubNotFoundError extends Error { /* githubErrorKind = 'not_found' */ }

export async function fetchRepoMetadata(
  fullName: string,             // "owner/repo"
  credentials: GitHubCredentials,
): Promise<RepoMetadataResponse>;

export async function fetchLatestRelease(
  fullName: string,
  credentials: GitHubCredentials,
): Promise<ReleaseResponse | null>;          // null when no releases

export async function fetchRepoContents(
  fullName: string,
  path: string,
  credentials: GitHubCredentials,
): Promise<ContentsResponse>;                // for skill detection

export async function fetchRateLimit(
  credentials: GitHubCredentials,
): Promise<RateLimitStatus>;
```

All functions:
- Use `Authorization: Bearer <PAT>` + `Accept: application/vnd.github+json` + `X-GitHub-Api-Version: 2022-11-28` + `User-Agent: toolwiki-inventory`.
- Parse `X-RateLimit-Remaining` / `X-RateLimit-Reset` from response headers.
- Retry 5xx with backoff (500ms/1s/2s, 3 attempts max).
- 401/403 → `GitHubAuthError`. 429 → `GitHubRateLimitError`. 404 → `GitHubNotFoundError`.
- Zod-parse the body via `schemas.ts` before returning.

### 4.3 `repo-metadata.ts` fetcher (combines 2 calls)

```typescript
export async function fetchFullRepoMetadata(
  fullName: string,
  credentials: GitHubCredentials,
): Promise<GithubInventoryMetadata> {
  const repo = await fetchRepoMetadata(fullName, credentials);
  const release = await fetchLatestRelease(fullName, credentials);  // null OK

  return {
    starsCount: repo.stargazers_count,
    forksCount: repo.forks_count,
    watchersCount: repo.watchers_count,
    primaryLanguage: repo.language,
    license: repo.license?.spdx_id ?? "no-license",
    topics: repo.topics ?? [],
    defaultBranch: repo.default_branch,
    createdAt: repo.created_at,
    pushedAt: repo.pushed_at,
    latestRelease: release && {
      tag: release.tag_name,
      name: release.name,
      publishedAt: release.published_at,
    },
  };
}
```

For skills in mono-repos (`source_identifier="anthropics/skills:web-design"`), an additional fetch reads `SKILL.md` at the subdir path and parses YAML frontmatter → populates `skillFrontmatter`.

## 5. Cron-Worker

### 5.1 `apps/api/src/workers/github-inventory-refresh.worker.ts`

Structure mirrors `apps/api/src/workers/comparison-discovery.worker.ts` (Spec 63.3b) — closest sibling pattern.

```typescript
import { Worker } from "bullmq";
import { startOfMinute, subSeconds } from "date-fns";
import { db } from "@marketing-auto/db";
import { listInventoryDueForRefresh, markInventoryFetching, markInventoryOk, markInventoryError } from "@marketing-auto/db/helpers/content-source-inventory-write";
import { fetchFullRepoMetadata, GitHubAuthError, GitHubRateLimitError, GitHubNotFoundError } from "@marketing-auto/adapter-github-inventory";
import { readAdapterCreds } from "../lib/system-service";
import { getEnv } from "@marketing-auto/shared/config";
import { redis } from "../lib/redis";
import { registerCronJob, seedGithubInventoryRefreshCron } from "../lib/cron-orchestrator";

const REFRESH_AGE_BUFFER_S = 30;          // transactional race buffer
const BATCH_SIZE = 10;                     // rows per worker tick

export const githubInventoryWorker = new Worker(
  "github-inventory-refresh",
  async (job) => {
    if (job.name === "refresh-due-rows") {
      const creds = await readAdapterCreds("github");          // { service: "github", api_key: ... }
      const pat = creds.api_key as string;

      const dueRows = await listInventoryDueForRefresh({
        limit: BATCH_SIZE,
        ageBufferSeconds: REFRESH_AGE_BUFFER_S,
      });

      for (const row of dueRows) {
        const claimed = await markInventoryFetching(row.id);     // CAS guard
        if (!claimed) continue;

        try {
          const fullName = row.sourceIdentifier.split(":")[0];   // strip ":subdir" for mono-repo skills
          const metadata = await fetchFullRepoMetadata(fullName, { personalAccessToken: pat });
          // (skill subdir: additional fetcher call here)
          await markInventoryOk(row.id, metadata);
        } catch (err) {
          if (err instanceof GitHubRateLimitError) throw err;    // bubble up; retry next tick
          await markInventoryError(row.id, String(err));
        }
      }
    } else if (job.name === "refresh-manual") {
      // Manual-trigger path — payload carries explicit ids[]
      const { ids } = job.data as { ids: string[] };
      // ... same per-row logic
    }
  },
  { connection: redis, concurrency: 1 }
);

// Startup hook — idempotent seed of cron_state row
await seedGithubInventoryRefreshCron();
```

### 5.2 Cron pattern

Default: `*/15 * * * *` (every 15 min). Worker scans for rows whose row-level `refresh_interval_hours` has elapsed. Per-row interval is the user-tunable knob; cron cadence is the worker tick frequency.

Env: `INVENTORY_REFRESH_CRON_PATTERN` in `packages/shared/src/config.ts` (default `*/15 * * * *`).

### 5.3 Rate-limit handling

GitHub-API: 5000 requests/hour with PAT. Per refresh: 2 calls for tools, 3 for skills (+ SKILL.md read). At 108 tools + 20 skills, weekly refresh = ~280 calls/week = trivial.

Cron monitors `X-RateLimit-Remaining` from each response. If `< 100`, worker logs WARN and sleeps until reset (`X-RateLimit-Reset`). No re-enqueue needed — next `*/15` tick picks up after reset.

No `cost_logs` write (free API, see §2 deviation note).

## 6. Manual-Trigger Endpoint

### 6.1 `POST /api/projects/:slug/inventory/refresh`

```typescript
// apps/api/src/routes/projects/inventory.ts

const refreshBodySchema = z.object({
  ids: z.array(z.string().uuid()).optional(),   // empty/missing = all due-now
});

inventoryRouter.post("/:slug/inventory/refresh", async (c) => {
  const { slug } = c.req.param();
  const body = refreshBodySchema.parse(await c.req.json());
  const project = await loadProjectBySlugOrThrow(slug);

  const queue = getQueue("github-inventory-refresh");
  const jobId = `inventory-refresh-${project.id}-${Date.now()}`;
  await queue.add(
    body.ids?.length ? "refresh-manual" : "refresh-due-rows",
    body.ids?.length ? { projectId: project.id, ids: body.ids } : { projectId: project.id },
    { jobId, removeOnComplete: 100 }
  );

  return c.json({ ok: true, jobId });
});
```

## 17. Discovered & Deviations

Pre-spec corrections from Phase 0 (discovery → spec):

1. **No `tools` table exists** — Toolwiki tools are `articles` rows with `collection='tools'`. Discovery §4 assumed a dedicated `tools` table; spec FKs `content_source_inventory.article_id → articles(id) ON DELETE SET NULL` instead.
2. **`cost_service` enum stays unchanged** — GitHub-API is free; existing signal-adapter doesn't log to `cost_logs` either. H3 follows the same convention. Discovery §6.1 had proposed logging requests-as-budget-proxy; deferred until rate-limit pressure surfaces.
3. **Vault key `"github"` already exists** — `readAdapterCreds("github")` (Spec 59.1b signal-collector). H3 reuses; no new credential-type.
4. **Migration count corrected** — Discovery §13 listed two migrations; spec uses two (table + enum) since `cron_state` seed is in worker startup per Memory D124.

### Day 1 discoveries

5. **`articles.status` enum doesn't include `'draft'`** — first test fixture asserted `status: "draft"`; typecheck rejected with "not assignable to `'approved' | 'superseded' | 'failed' | 'published' | 'proposed' | ...'`". Used `"proposed"` (the canonical early-state value). The enum's intentional narrowness is from Spec 001 + others — `draft` is an editorial mental model, not a DB lifecycle.
6. **`$type<>()` jsonb union with `Record<string, never>` is non-codebase-pattern** — initial draft used `$type<GithubInventoryMetadata | Record<string, never>>()` to capture the "empty-default" runtime reality. Grep found zero precedent across all `$type<>()` jsonb columns in the schema; convention is `$type<T>()` and consumer-contract for empty-states (e.g. `fetchStatus === 'ok'`). Simplified to `$type<GithubInventoryMetadata>()` + a JSDoc reminder; lets consumer code read fields without a cast or in-guard.
7. **`articles` cross-import in helpers** — `content-source-inventory-write.ts` needs `articles` for the `assertArticleCollectionForTool` guard. Direct import from `../schema/content.ts` works because both live in `packages/db` (no cross-package boundary). The guard runs an extra DB round-trip per INSERT/PATCH-with-articleId, which is acceptable given the rarity of the operation.
8. **Partial-index `WHERE` predicate** — Drizzle declares the partial via `.where(sql\`${t.approvedAt} IS NOT NULL\`)`. The migration's WHERE clause must match exactly (Memory D108) — written by hand in the migration SQL since Drizzle-kit `generate` is non-interactive-unsafe.

### Day 2 discoveries

9. **`HeadersInit` is a DOM type not available under `lib: ["ESNext"]`** — initial `client.ts` typed `buildHeaders(): HeadersInit`, typecheck failed with `Cannot find name 'HeadersInit'`. Fixed to `Record<string, string>` which is structurally compatible with `fetch()`'s headers param. Codebase pattern check: other adapters (anthropic/replicate/nano-banana) use inline object literals or `Record<string, string>`; none use `HeadersInit`. Could be promoted to root CLAUDE.md as a footgun.
10. **`@marketing-auto/adapter-github-trending` dep on `@marketing-auto/pipelines` not needed for inventory adapter** — `github-trending` has that dep (legacy from signal-source integration), `github-inventory` does NOT. Credentials flow via the worker layer; the adapter stays leaf. Confirms the discovery-§4 split (signal-collection vs stable-inventory) is structurally different.
11. **`Bun.mock` global `fetch` injection pattern** — `globalThis.fetch = mock(...) as unknown as typeof fetch` chain is the established pattern in this codebase (github-trending precedent). The `as unknown as` chain is the only way to bridge `mock()`'s loose return type to `fetch`'s precise signature; documented in CLAUDE.md as a justified TS escape hatch in test code.
12. **HTTP 429 vs HTTP 403 with `x-ratelimit-remaining=0`** — both map to `GitHubRateLimitError` but are distinct GitHub-API states. 403+remaining=0 is the standard quota-exhausted response; 429 is a soft-throttle (sub-quota burst limit). Adapter handles both → same error class, both surface `resetAt` when available.
13. **`/releases/latest` 404-on-no-releases is by design** — most repos have no releases; the adapter's `fetchLatestRelease` uses `doGet({allow404: true})` to return `{body: null}` instead of throwing. Spec §4.3 wrote this as a passing comment; tests confirm the behavior. Same `allow404` pattern for `/contents/{path}` (missing SKILL.md).
14. **`/contents/{path}` directory-vs-file shape** — GitHub returns a single-file object when path = file, array when path = directory. The adapter rejects arrays as "not what we want" by returning `{body: null}` rather than parsing as the file schema. Defensive: skill-detector only ever queries file paths, but the runtime check protects against future misuse.

15. **Removed 3 unused imports** from test file (`inArray`, `isNotNull`, `sql`) — `void` suppression lines were a workaround for not-yet-used imports; cleaner to drop them.
16. **Removed unnecessary `as GithubInventoryMetadata` casts** in test reads (3 sites) — became redundant after simplifying the schema's `$type<>()` (deviation #6). One remaining cast kept (deliberate invalid-data construction for Zod-reject test) with a justifying comment.

### Day 3 discoveries

18. **Inventory cron defaults `isActive: true`, unlike sibling crons** — comparison-discovery (Spec 63.3b), planner-weekly (Spec 62.7), trends-synthesizer (Spec 63.4) all default `isActive: false` because each tick burns LLM cost (discovery / plan / synthesis). GitHub-API is free; inventory cron is cheap when there are no rows (empty-inventory = no-op). Defaulting `true` means inventory rows refresh on the next `*/15` tick without Marcel toggling. Documented in code comments + spec §5.
19. **Adapter dep needed in `apps/api/package.json`** — workspaces don't auto-link; without the explicit `"@marketing-auto/adapter-github-inventory": "workspace:*"` line in apps/api's `dependencies`, TypeScript errors with `Cannot find module '@marketing-auto/adapter-github-inventory'` even though the package exists in the monorepo. Required `bun install` after editing package.json so the workspace symlink lands in `apps/api/node_modules/`. Same pattern as every other adapter (`adapter-replicate`, `adapter-anthropic`, etc.) — the existing list at apps/api/package.json line 55-67 is the canonical reference.
20. **`readAdapterCreds('github')` returns `Record<string, string>` — defensive `as Record<string, string | undefined>` cast was over-engineering**. The existing signal-collector pattern reads `creds.personal_access_token` directly + runtime-checks `if (!creds.personal_access_token)`. TypeScript's `Record<string, string>` doesn't model "missing key returns undefined" but the `if (!...)` runtime check captures it correctly. Initial worker draft had unnecessary defensive casts (`(creds as Record<string, string | undefined>).api_key ?? .personal_access_token`); cleaned up to match signal-collector + dropped the dual-key fallback (`api_key` was a misread of the convention — vault key is `personal_access_token`).
21. **Cron-orchestrator update touches 4 sites per Discovery 133** — confirmed by `apps/api/CLAUDE.md` "Adding a new cron job type" rule: (1) SQL migration `ALTER TYPE` (done 0106), (2) Drizzle `cronJobTypeEnum` in `packages/db/src/schema/cron.ts`, (3) `getQueueForJobType()` switch in `cron-orchestrator.ts`, (4) `allQueues` array AND `isCronOrchestrated` `startsWith` check in `syncCronJobs()`. Missing any one site = silent broken cron. All 4 updated together in this spec.
22. **Worker-level `attempted` counter is coarse on purpose** — initial draft tried to track success/failure separately at the tick level (`succeeded` + `failed` vars), but per-row outcomes are captured in structured logs emitted by `refreshOne`; double-counting at the tick level adds no diagnostic value. Cleaned to single `attempted` counter + `rateLimited` flag. Pattern: tick-level summaries are coarse; per-row outcomes are in the structured per-row logs.
23. **`unique-constraint violation` error message detection by substring** — used `message.includes("csi_project_source_identifier_approved_unique")` in the POST create route to map duplicate-source_identifier errors to 409. Fragile (depends on PostgreSQL error format + index name staying stable), but the alternative is parsing PG error codes from the thrown `Error.cause`, which Drizzle doesn't expose cleanly. Acceptable for V1; tag for revisit if Drizzle gains structured error access.
24. **HTTP route audit confirms `apps/api/CLAUDE.md` "Mixed public/private routes pattern" doesn't apply** — `inventoryRoutes.use(requireAuth)` at router level is fine because ALL inventory endpoints require auth (no public sub-routes). Matches signal-sources precedent.

### Day 4 discoveries

25. **Spec §7 originally proposed 3 separate pages (list / new / :id), but the codebase convention is 1 page with inline modals** — SettingsCredentialsPage / SettingsSignalSourcesPage / SettingsPlannerPage are all single-page CRUD with no `/new` or `/:id` sub-routes. Followed the codebase convention. Multi-page split would add 2 unnecessary router entries with no UX benefit; the modal-based create/edit dialog covers the same surface in less code. Spec §7 marked superseded.
26. **Quasar `$q.notify` does NOT accept `dark: true`** — only `$q.dialog` does. Initial draft of `SettingsInventoryPage.vue` copy-pasted `dark: true` into 9 notify calls + 1 dialog call from existing pages; typecheck rejected the 9 notify cases. Quasar's notify uses type-based theming (`type: "positive" | "negative"`) which respects the global Dark plugin from `quasar.config.ts`. Removed from notify, kept on dialog. Could be a root-CLAUDE.md DO-NOT entry if this is a frequent footgun.
27. **German typographic quote-marks (`„..."`) inside double-quoted TypeScript strings break parsing** — root CLAUDE.md already documents this DO-NOT rule. Caught twice in initial i18n draft: `empty` and `deleteConfirmMessage` keys used `„` (Unicode opening German quote, `„`) inside double-quoted strings — TypeScript saw the opening `"` end at the first inner `"`, breaking parse. Switched outer quotes to single-quote.
28. **`fetchStatus === 'ok'` gates jsonb reads** — initial draft used `as Partial<{starsCount: number}>` casts to handle the empty-default case (pending rows have `{}`). Cleaner pattern is the explicit fetch-status gate: returns early with `—` placeholder for non-ok rows, then casts to the full populated type. Matches the consumer-contract pattern established by the `$type<GithubInventoryMetadata>()` simplification in deviation #6.
29. **Composables can be called inside Vue Options API computed properties** — `inventory(): ReturnType<typeof useInventory> { return useInventory(this.projectSlug, {...filters}) }` runs the composable on every reactivity recomputation (filter change). TanStack Query's internal cache keys (queryKey tuple) handle dedup, so calling `useInventory()` repeatedly with the same filters is cheap. Pattern matches the existing "MaybeRef" convention for Options API consumers of Composition-API composables (apps/web/CLAUDE.md).

- **"Stable-data inventory" architecture** — project-scoped, source-agnostic via `text NOT NULL CHECK (source IN ('github'))` column (not `pgEnum`) — forward-compat for gitlab/npm/pypi without migrations. Mirrors how `topic_briefs.source` modeled growth from 1→6 source values via CHECK widening.
- **Vault-key sharing across adapters that hit the same external API** — `globalCredentials.service='github'` is the canonical vault key, used by BOTH `@marketing-auto/adapter-github-trending` (signal-collector, Spec 59.1b) AND `@marketing-auto/adapter-github-inventory` (Spec 64.20). No per-consumer credential-type. Same rule should apply to future GitLab/Bitbucket adapters (one vault key per provider, not per consumer).
- **Per-row refresh-interval + system-wide cron tick** — `refresh_interval_hours INT` per row, cron tick is `*/15 * * * *` system-wide. Worker scans rows where `now() - last_fetched_at >= interval`. User tunes the per-row knob; cron cadence is the worker tick frequency. Applies to any future stable-data inventory (npm-registry, brand-asset-refresh, etc.).
- **Skip cost-tracking for free rate-limited APIs** — GitHub-API has no €-cost; `x-ratelimit-*` response headers are monitored at worker-level. No `cost_service` enum widening, no `cost_logs` write. Matches the existing `github-trending` signal-adapter convention.
- **`as unknown as typeof fetch` for global fetch mock in adapter tests** — the only way to bridge Bun's loose `mock()` return type to `fetch`'s precise signature. Test-code escape hatch; justified.

**Footguns to add as root CLAUDE.md DO-NOTs:**

- DO NOT type fetch-headers as `HeadersInit` in workspace packages — DOM type, not available under `lib: ["ESNext"]`. Use `Record<string, string>` instead (structurally compatible with `fetch()`'s headers param). Pattern caught while bootstrapping `@marketing-auto/adapter-github-inventory`; other adapters (anthropic/replicate/nano-banana) avoid the import altogether.
- DO NOT write `$type<T | Record<string, never>>()` to model "empty default + populated by background fetch" jsonb columns — convention is `$type<T>()` and consumer-contract gating (e.g. `fetchStatus === 'ok'`). The empty-union over-models reality and forces casts at every read site. Codebase has zero `Record<string, never>` precedent in `$type<>()` declarations.
- DO NOT assume `articles.status` accepts `'draft'` — the enum is intentionally narrow (`'approved' | 'superseded' | 'failed' | 'published' | 'proposed' | 'generating' | 'outline_review' | 'drafting' | 'final_review' | 'schema_extending' | 'ready_to_publish'` + ~4 more). Use `'proposed'` as the canonical early-state value for test fixtures.

**Schema lessons:**

- Partial unique index `WHERE approved_at IS NOT NULL` (D108 pattern) lets V1.1 Auto-Discovery add `approved_at NULL` rows without tripping the V1 uniqueness constraint — forward-compat by construction. Same as `articles_project_source_coll_locale_slug_active_unique` (Spec 005 IR1) + `topic_briefs_unique_open_per_gap` (Spec 0032+0084).
- `ALTER TYPE ... ADD VALUE` migrations are irreversible by PostgreSQL design — codebase convention (0054, 0056, 0057, 0058, 0068, 0076, 0080, 0106) is to ship them as one-off forward-only and seed `cron_state` rows in worker startup (Memory D124).

**Worker + cron lessons (Day 3):**

- **Cron-orchestrator integration is 4-site, not 1-site.** Adding a new cron job type requires updating ALL of: (1) SQL `ALTER TYPE`, (2) Drizzle `cronJobTypeEnum`, (3) `getQueueForJobType()` switch, (4) `allQueues` array AND `isCronOrchestrated` `startsWith` check. Per-new-project INSERT in `routes/projects.ts` POST `/` is a fifth site if you want new projects to get the cron immediately rather than waiting for the next worker restart.
- **Refresh cron defaults differ by cost model.** Cost-burning crons (LLM-based: trends-synthesizer, comparison-discovery, planner-weekly) default `isActive: false`. Free-API refresh crons (inventory-refresh; future: brand-asset-refresh) can default `isActive: true` since empty-data = no-op tick. The default is a per-cron decision, not a system-wide convention.
- **`readAdapterCreds(service)` returns `Record<string, string>` — read fields directly + runtime-check** rather than defensive `as Record<string, string | undefined>` casts. The existing signal-collector pattern (Spec 59.1b) is the canonical reference: `if (!creds.personal_access_token) throw ...; const pat = creds.personal_access_token;`. Don't introduce alternative vault-key fallbacks (`api_key` etc.) unless the adapter specifically supports multiple credential shapes (e.g. github_app's private-key-content OR path — see apps/api/CLAUDE.md DO-NOT entry).
- **Adapter packages must be listed in `apps/api/package.json` dependencies even though they're workspace siblings** — Bun workspaces don't auto-link by directory presence. Forgetting the line produces `Cannot find module` at typecheck time. Pattern: every consumer adapter gets a `"@marketing-auto/adapter-foo": "workspace:*"` entry. Same convention exists in `packages/pipelines/package.json` for pipelines that consume an adapter.
