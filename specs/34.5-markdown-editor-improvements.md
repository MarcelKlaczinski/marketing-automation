# Spec 34.5: MarkdownEditor Improvements

**Phase:** 4 (Welle 3 Vorbereitung — kleines Bugfix-Spec)
**Estimated Effort:** 0.5 days (1 session)
**Dependencies:** Spec 34 (existing MarkdownEditor)
**Status:** Ready for implementation
**Recommended Model:** Sonnet 4.6 (UI/CSS work, kein Architektur-Aufwand)

---

## Goal

Bring the MarkdownEditor (created in Spec 34) to **production-quality**. Two bugs found during Spec 34 implementation block heavy use:

1. **Bug A: Editor doesn't scroll vertically inside its bounded height.** When content exceeds the visible area, the editor extends outside its container instead of scrolling internally.
2. **Bug B: No formatting toolbar.** Users have to type markdown syntax manually — no buttons for Bold, Italic, Headings, etc.

This spec fixes both bugs and adds a comprehensive toolbar. The improved editor will be used in:
- Spec 34 (`marketing_context.md` editing) — already in place
- Spec 35 (Cornerstone description editing in Phase 4) — currently in development
- Spec 36 (Article body editing with change-tracking) — next wave

Building this improvement **once** here means all three specs benefit without duplicating work.

## Architecture Decisions

**Decision 1: Toolbar above the editor body, full-width, sticky.**
The toolbar lives in a row above the existing tabs (Edit / Preview / Split). It has the same horizontal width as the editor. When scrolling inside the editor body, the toolbar stays visible (sticky at top).

**Decision 2: Toolbar buttons act on the CodeMirror selection.**
Each button calls a CodeMirror command that wraps the current selection in markdown syntax (e.g., `**` for bold), or inserts a new structure at cursor position (e.g., a list item, a table skeleton).

**Decision 3: Toolbar is implemented via CodeMirror's `EditorView.dispatch()` API.**
We dispatch transactions that modify the document and selection. Standard markdown editor behavior. No external library needed — just our own helper functions.

**Decision 4: Scroll fix uses CSS `min-height: 0` + `overflow: auto` on the right ancestor.**
The bug is that `.cm-scroller` (CodeMirror's scrollable element) inherits `height: 100%`, but the parent flex container doesn't enforce a constrained height. Standard flex-shrink trick.

**Decision 5: All button labels and tooltips via i18n.**
No hardcoded strings. Existing convention from Spec 33+ Reports.

**Decision 6: Keyboard shortcuts attached to the same actions.**
Standard shortcuts (`Ctrl+B`/`Cmd+B` for bold, `Ctrl+I` for italic, etc.) using CodeMirror's `keymap` extension. Marcel doesn't have to use the toolbar — power-user via shortcuts.

**Decision 7: Tables get a dialog, not direct insertion.**
Table syntax is annoying to write and easy to mess up. Clicking the Table button opens a small dialog: "How many rows? How many columns?" → inserts a properly formatted skeleton.

**Decision 8: Code-Blocks insert with language placeholder.**
Inserts ` ```language\n\n``` ` with cursor positioned on the language slot, so user can immediately type `typescript` or whatever.

## Non-Goals

- **No WYSIWYG mode** — markdown source remains the canonical view, toolbar just helps write it
- **No spell-check / grammar-check** — out of scope, future spec if needed
- **No autocomplete for headings/links** — too complex for this spec
- **No table editing UI after insertion** — once inserted, edit raw markdown
- **No image upload via toolbar** — out of scope (add later if Article-Body editing needs it)
- **No drag-and-drop file upload** — same reason
- **No collaborative editing / multi-cursor** — single user
- **No find-and-replace** — CodeMirror has built-in `Ctrl+F` if we add the search extension; not in this spec

import type { EditorView } from '@codemirror/view';

/**
 * Toolbar button action signature. Returns true if action consumed the event.
 */
export type ToolbarAction = (view: EditorView, dispatch?: (open: 'table' | 'link') => void) => boolean;

export interface ToolbarItem {
  id: string;
  iconName: string;
  i18nKey: string;
  action: ToolbarAction;
  shortcut?: string;
  /** When true, renders a divider after this item */
  dividerAfter?: boolean;
}

/**
 * Wraps the current selection with `before` and `after` strings.
 * If selection is empty, just inserts the wrappers and positions cursor between them.
 */
function wrapSelection(view: EditorView, before: string, after: string = before): boolean {
  const { state } = view;
  const { from, to } = state.selection.main;
  const selectedText = state.sliceDoc(from, to);

  if (selectedText.length === 0) {
    // No selection — insert wrappers and place cursor between them
    view.dispatch({
      changes: { from, insert: `${before}${after}` },
      selection: { anchor: from + before.length },
    });
  } else {
    view.dispatch({
      changes: { from, to, insert: `${before}${selectedText}${after}` },
      selection: { anchor: from + before.length, head: from + before.length + selectedText.length },
    });
  }
  view.focus();
  return true;
}

/**
 * Adds a prefix to each line of the current selection (or current line if no selection).
 * Used for headings, lists, blockquotes.
 */
function prefixLines(view: EditorView, prefix: string): boolean {
  const { state } = view;
  const { from, to } = state.selection.main;
  const startLine = state.doc.lineAt(from);
  const endLine = state.doc.lineAt(to);

  const changes: { from: number; insert: string }[] = [];
  for (let i = startLine.number; i <= endLine.number; i++) {
    const line = state.doc.line(i);
    changes.push({ from: line.from, insert: prefix });
  }

  view.dispatch({ changes });
  view.focus();
  return true;
}

/**
 * Inserts a freshly formatted block at the current cursor position,
 * placing cursor at `cursorOffset` characters into the inserted text.
 */
function insertBlock(view: EditorView, block: string, cursorOffset: number): boolean {
  const { state } = view;
  const { from } = state.selection.main;

  // Ensure block starts on its own line
  const lineStart = state.doc.lineAt(from);
  const needsNewlineBefore = from > lineStart.from;
  const insertText = (needsNewlineBefore ? '\n' : '') + block;

  view.dispatch({
    changes: { from, insert: insertText },
    selection: { anchor: from + (needsNewlineBefore ? 1 : 0) + cursorOffset },
  });
  view.focus();
  return true;
}

/**
 * Builds a markdown table skeleton with the given dimensions.
 * @param rows Number of data rows (excluding header)
 * @param cols Number of columns
 */
export function buildTable(rows: number, cols: number): string {
  const headerCells = Array(cols).fill('Header').map((h, i) => `${h} ${i + 1}`);
  const separatorCells = Array(cols).fill('---');
  const dataRow = Array(cols).fill('').map((_, i) => `Cell ${i + 1}`);

  const lines: string[] = [];
  lines.push(`| ${headerCells.join(' | ')} |`);
  lines.push(`| ${separatorCells.join(' | ')} |`);
  for (let r = 0; r < rows; r++) {
    lines.push(`| ${dataRow.join(' | ')} |`);
  }
  return lines.join('\n') + '\n';
}

/**
 * Inserts a markdown link at cursor: [text](url)
 * If text is empty, uses url as text.
 */
export function insertLink(view: EditorView, text: string, url: string): void {
  const { from } = view.state.selection.main;
  const linkText = text || url;
  view.dispatch({
    changes: { from, insert: `[${linkText}](${url})` },
    selection: { anchor: from + linkText.length + url.length + 4 },
  });
  view.focus();
}

/**
 * Inserts a markdown table at cursor.
 */
export function insertTable(view: EditorView, rows: number, cols: number): void {
  const { from } = view.state.selection.main;
  const lineStart = view.state.doc.lineAt(from);
  const needsNewlineBefore = from > lineStart.from;
  const tableText = (needsNewlineBefore ? '\n\n' : '') + buildTable(rows, cols);

  view.dispatch({
    changes: { from, insert: tableText },
  });
  view.focus();
}

<script lang="ts">
import { defineComponent, markRaw } from 'vue';
import { Codemirror } from 'vue-codemirror';
import { markdown } from '@codemirror/lang-markdown';
import { oneDark } from '@codemirror/theme-one-dark';
import { EditorView, keymap } from '@codemirror/view';
import { defaultKeymap, historyKeymap, history } from '@codemirror/commands';
import { marked } from 'marked';
import {
  TOOLBAR_ITEMS,
  insertLink,
  insertTable,
  type ToolbarItem,
} from './markdown-editor-toolbar-config';

export default defineComponent({
  name: 'MarkdownEditor',

  components: { Codemirror },

  props: {
    modelValue: { type: String, default: '' },
    height: { type: Number, default: 320 },
  },

  emits: ['update:modelValue', 'blur'],

  data() {
    const isDark = document.body.classList.contains('body--dark');

    const baseTheme = EditorView.theme({
      '&': {
        fontSize: '14px',
        height: '100%',
      },
      '.cm-content': {
        fontFamily: '"JetBrains Mono", "SF Mono", Menlo, Consolas, monospace',
      },
      '.cm-scroller': {
        lineHeight: '1.55',
        overflow: 'auto', // Critical: enables vertical scrolling
      },
      '.cm-editor': {
        height: '100%', // Fill container
      },
      '.cm-editor.cm-focused': {
        outline: 'none',
      },
    });

    // Build keymap from toolbar items that have shortcuts
    const toolbarKeymap = TOOLBAR_ITEMS.filter((it) => it.shortcut).map((it) => ({
      key: it.shortcut!,
      run: (view: EditorView) => {
        const dispatch = (kind: 'table' | 'link') => {
          if (kind === 'link') (this as { linkDialogOpen?: boolean }).linkDialogOpen = true;
          if (kind === 'table') (this as { tableDialogOpen?: boolean }).tableDialogOpen = true;
        };
        return it.action(view, dispatch);
      },
    }));

    return {
      mode: 'edit' as 'edit' | 'preview' | 'split',
      localValue: this.modelValue,
      editorView: null as EditorView | null,
      toolbarItems: TOOLBAR_ITEMS,
      linkDialogOpen: false,
      tableDialogOpen: false,
      linkDialog: { text: '', url: '' },
      tableDialog: { rows: 3, cols: 3 },
      isMac: /Mac|iPod|iPhone|iPad/.test(navigator.platform),
      extensions: markRaw([
        markdown(),
        history(),
        keymap.of([...defaultKeymap, ...historyKeymap, ...toolbarKeymap]),
        baseTheme,
        EditorView.lineWrapping,
        ...(isDark ? [oneDark] : []),
      ]),
    };
  },

  computed: {
    rendered(): string {
      const result = marked.parse(this.localValue, { async: false });
      return typeof result === 'string' ? result : '';
    },
  },

  watch: {
    modelValue(newVal: string): void {
      if (newVal !== this.localValue) {
        this.localValue = newVal;
      }
    },
  },

  methods: {
    formatShortcut(shortcut: string): string {
      // Convert "Mod-b" → "Cmd+B" on Mac, "Ctrl+B" elsewhere
      const modKey = this.isMac ? 'Cmd' : 'Ctrl';
      return shortcut.replace('Mod', modKey).replace('-', '+').toUpperCase();
    },

    onChange(value: string): void {
      this.localValue = value;
      this.$emit('update:modelValue', value);
    },

    onCmReady(payload: { view: EditorView }): void {
      this.editorView = markRaw(payload.view) as EditorView;
      payload.view.dom.addEventListener('blur', () => {
        this.$emit('blur');
      }, true);
    },

    onToolbarClick(item: ToolbarItem): void {
      if (!this.editorView) return;
      item.action(this.editorView, (kind) => {
        if (kind === 'link') {
          // Pre-fill text with current selection
          const selected = this.editorView!.state.sliceDoc(
            this.editorView!.state.selection.main.from,
            this.editorView!.state.selection.main.to,
          );
          this.linkDialog.text = selected;
          this.linkDialog.url = '';
          this.linkDialogOpen = true;
        }
        if (kind === 'table') {
          this.tableDialogOpen = true;
        }
      });
    },

    confirmLinkInsert(): void {
      if (!this.editorView) return;
      insertLink(this.editorView, this.linkDialog.text, this.linkDialog.url);
      this.linkDialogOpen = false;
      this.linkDialog = { text: '', url: '' };
    },

    confirmTableInsert(): void {
      if (!this.editorView) return;
      const rows = Math.max(1, Math.min(20, this.tableDialog.rows));
      const cols = Math.max(1, Math.min(10, this.tableDialog.cols));
      insertTable(this.editorView, rows, cols);
      this.tableDialogOpen = false;
    },
  },
});
</script>

## Testing Strategy

Manual smoke tests (~15 min):

1. **Scroll fix**: Open a project's marketing-context page. Paste a 200-line markdown document. Verify the editor scrolls internally — page does NOT extend infinitely.
2. **Bold/Italic**: Type `Hello world`, select `world`, click Bold. Verify becomes `Hello **world**`.
3. **Heading**: Place cursor on a line, click H2. Verify line starts with `## `.
4. **Multi-line lists**: Select 3 lines, click Bullet list. Verify all 3 lines now start with `- `.
5. **Link dialog**: Select `click here`, click Link button. Dialog shows `click here` as text. Enter URL. Confirm. Editor shows `[click here](https://...)`.
6. **Table dialog**: Place cursor on empty line. Click Table. Enter 5 rows, 3 cols. Verify a 3-column markdown table with 6 rows total (header + 5) is inserted, properly formatted.
7. **Code block**: Click code block button. Verify cursor is on the language slot (between ` ``` ` and `\n`).

## Open Questions / Decisions Made

**Decision 1: Toolbar uses Material Icons.**
Already loaded for the rest of the app via Quasar. No new icon library.

**Decision 2: Link dialog pre-fills text from selection.**
If the user has `click here` selected and clicks Link, the dialog opens with `click here` already in the text field. Common UX pattern (e.g., Notion, GitHub).

**Decision 3: Table dialog max 20 rows / 10 cols.**
Larger tables become unwieldy in markdown source. If Marcel needs 50-row tables, he should use a CSV import (future spec).

**Decision 4: No "save shortcut" (Ctrl+S) in this spec.**
The MarkdownEditor itself doesn't know how to save — its parent does. If we wanted Ctrl+S we'd need to expose an event. Out of scope; parent components can wire it themselves if needed.

**Decision 5: `editorView` stored via `markRaw`.**
Pinia/Vue's reactivity proxies don't play well with CodeMirror's internals. `markRaw` keeps the editor instance non-reactive. Already used for extensions; same pattern.

**Decision 6: No "format painter" or copy-formatting.**
Markdown doesn't really have rich formatting to paint. The toolbar inserts syntax; that's all.

**Decision 7: Lists don't toggle.**
Clicking Bullet list on already-bulleted lines adds `- ` again (would result in `- - text`). True toggle behavior would need parser-aware detection of existing list state. Defer; the simple insert is fine for now and matches GitHub's web editor behavior.

**Decision 8: No undo/redo button.**
CodeMirror's built-in `Ctrl+Z` / `Ctrl+Shift+Z` from `historyKeymap` works without UI. Adding redundant buttons would clutter the toolbar.

## Discovered During Implementation

- **markRaw + reactive data TypeScript mismatch**: Storing a CodeMirror `EditorView` in Vue's reactive `data()` via `markRaw` still yields a proxy-typed value that TypeScript treats as structurally incompatible with `EditorView`. All call-sites need `this.editorView as unknown as EditorView` with a justification comment. This is now documented in `apps/web/CLAUDE.md`.
- **`placeholder` is user-visible**: The URL input placeholder `"https://"` must go through `$t()` like any other user-facing string. Added `markdownEditor.linkDialog.urlPlaceholder` to both `de` and `en` i18n files. The existing web CLAUDE.md rule already covers this ("all visible text") but the explicit mention of `placeholder=` attribute is easy to miss.

## Deviations

- **`$t()` cast for Quasar `:label` props**: The spec omits the `as string` cast on `$t()` calls used as `:label` values. In practice Quasar's `label` prop is typed `string | undefined`, while `$t()` returns a broader type, so `as string` is required. This matches the established pattern in the codebase (same cast used in Quasar validator rule functions).
