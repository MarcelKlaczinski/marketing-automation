## Goal

Complete the content lifecycle for toolwiki by adding three capabilities to the existing Blog Pipeline:

1. **ChainStep enum migration**: Add `"blog"` to the `ChainStep` enum so `/automate` routes new briefs through Spec 54.9's Blog Pipeline instead of the legacy `article:outline` chain. Inherited from Spec 54.9 Deviation 3.

2. **Refresh-Mode**: Marcel can manually trigger a refresh on any existing article. The pipeline re-generates outline + draft using the existing body as voice-style reference, persists old body to `article_versions`, writes new body to `articles.body_md`. Audit trail preserved.

3. **Translation-Mode**: After a DE blog article completes, the system automatically generates an EN sibling. Uses a Haiku decision call to choose between literal translation (faster, cheaper) and adaptive outline (when EN audience needs different framing). Integrates with the existing `localize` ChainStep slot.

After this spec lands, toolwiki has end-to-end automated content lifecycle:
```
Brief approved → Cluster Creator (54.7) → Blog Pipeline DE (54.9)
                                              ↓
Marcel reviews → Refresh if stale (54.10) → Translation EN sibling (54.10)
                                              ↓
Versioning preserved (article_versions)
```

## What this is NOT

- Not auto-refresh detection (heuristic-based staleness scanner) — Phase E backlog
- Not per-cluster refresh configuration — Phase E backlog
- Not translation quality reviews (LLM-as-Judge) — Phase E backlog
- Not bidirectional EN→DE translation — toolwiki is DE-first
- Not a comparisons-collection generator (54.9b) — separate spec
- Not ki-wissen / usecases / tool-categories generators (54.9c-e) — separate specs
- Not changing the existing Blog Pipeline architecture — extends and reuses
- Not adding new UI for translation review — translations land in DB, Marcel reviews via existing article detail page
- Not introducing new model selection patterns — uses same Sonnet/Haiku split as 54.9

## Section A: ChainStep Enum Migration

**Why**: Spec 54.9 Deviation 3 documented that `/automate` (the chain orchestrator's auto-progression endpoint) still routes through `article:outline` because adding `"blog"` to the `ChainStep` enum required a migration. That migration lands here.

**Files affected**:

- `packages/db/src/schema/content.ts` (update ChainStep type definition)
- `apps/api/src/lib/chain-orchestrator.ts` (update `startChain()` routing)

**Migration**:


```typescript
// Pseudocode — exact function signature determined by current implementation
async function startChain(brief: TopicBrief): Promise<void> {
  const firstStep: ChainStep = isBlogEligible(brief) ? "blog" : "outline";
  
  await db.insert(pipelineChains).values({
    projectId: brief.projectId,
    gapId: brief.gapId,
    articleId: null, // set later when article created
    status: "queued",
    currentStep: firstStep,
    stepRuns: {},
    totalCostEur: "0",
    autoPublish: project.autoPublish ?? false,
  });
  
  // Trigger the appropriate pipeline
  if (firstStep === "blog") {
    await enqueueBlogGeneration({ briefId: brief.id, projectId: brief.projectId });
  } else {
    await enqueueOutlinePipeline({ briefId: brief.id });
  }
}

function isBlogEligible(brief: TopicBrief): boolean {
  // Same detection as Spec 54.9 Deviation 3 fix:
  return brief.locale !== null 
    && brief.clusterId !== null
    && brief.source !== "refresh_detection"  // refresh goes elsewhere, see Section B
    && /* not a translation_created routing kind */;
}
```

**Backward compatibility**:

- Existing in-flight chains with `current_step = 'outline'` continue executing as-is
- The `step_runs` JSONB mapping in pipeline_chains supports both old chain shapes (outline → draft → schema → localize → schema-en → astro-transfer) and new (blog → localize → schema-en → astro-transfer) without schema changes
- No deletion or rewrite of historical data

## Section B: Refresh-Mode

### B.1 Trigger flow

Marcel clicks "Refresh this article" in the UI on an existing article. The UI POSTs to a new endpoint:

```
POST /api/projects/:slug/articles/:articleId/refresh
Body: { reason: string }
```

The endpoint:
1. Validates the article exists, has `source = 'generated'` and `status = 'published'` (or another published state)
2. Creates a `refresh_detection` brief tied to the article (`topic_briefs.refreshMetadata.targetArticleId = articleId`)
3. Approves the brief automatically (user clicked = approval)
4. Enqueues the Refresh Pipeline

### B.3 Refresh Pipeline

`packages/pipelines/src/article/refresh/pipeline.ts`:

```typescript
export async function runRefreshPipeline(input: RefreshPipelineInput): Promise<RefreshResult> {
  // 1. Load existing article + brief
  const article = await loadArticle(input.articleId);
  const brief = await loadBrief(input.briefId);
  
  // 2. Persist current body to article_versions (BEFORE regeneration)
  await persistVersion(article);
  
  // 3. Load voice references — articles in same cluster + locale, last 3 by created_at
  const voiceRefs = await loadVoiceReferences({
    projectId: article.projectId,
    clusterId: article.clusterId,
    locale: article.locale,
    excludeArticleId: article.id,
    limit: 3,
  });
  
  // 4. Build refresh-aware context for prompts
  const refreshContext = buildRefreshContext({
    originalBody: article.bodyMd,
    refreshReason: brief.refreshMetadata.reason,
    daysSinceLastUpdate: brief.refreshMetadata.staleness.daysSinceLastUpdate,
  });
  
  // 5. Run pipeline steps with refresh + voice context
  const outline = await runOutlineStep({
    brief,
    sourceContext: buildSourceContextFragment(brief),  // refresh_detection variant
    toolsContext: await buildToolsContext(brief),
    voiceReferences: voiceRefs,  // NEW: passed to prompt
    refreshContext,                // NEW: passed to prompt
    pipelineRunId: input.pipelineRunId,
    articleId: input.articleId,
  });
  
  const draft = await runDraftStep({
    brief,
    outline,
    sourceContext: buildSourceContextFragment(brief),
    toolsContext: await buildToolsContext(brief),
    voiceReferences: voiceRefs,
    refreshContext,
    pipelineRunId: input.pipelineRunId,
    articleId: input.articleId,
  });
  
  // 6. Linkify tools
  const linkified = await linkifyMarkdown(draft.bodyMd, article.projectId, article.locale);
  
  // 7. Update article in place (NOT insert new row)
  await db.update(articles)
    .set({
      bodyMd: linkified.bodyMd,
      wordCount: countWords(linkified.bodyMd),
      outline: outline.value,
      updatedAt: new Date(),
      // status stays 'published' — refresh doesn't unpublish
    })
    .where(eq(articles.id, article.id));
  
  // 8. Run remaining downstream (SelfReview, SchemaExtension)
  // Re-uses existing steps unchanged
  await runSelfReviewStep({ articleId: article.id, pipelineRunId: input.pipelineRunId });
  await runSchemaExtensionStep({ articleId: article.id });
  
  // 9. Trigger Translation Mode if locale='de' and EN sibling exists
  if (article.locale === "de") {
    const enSibling = await findEnSibling(article);
    if (enSibling) {
      await enqueueTranslationPipeline({ 
        sourceArticleId: article.id, 
        targetArticleId: enSibling.id, 
        mode: "refresh_propagation" 
      });
    }
  }
  
  return {
    articleId: article.id,
    versionId: persistedVersion.id,
    bodyMdLengthBefore: article.bodyMd?.length ?? 0,
    bodyMdLengthAfter: linkified.bodyMd.length,
    toolsLinked: linkified.linkedTools,
  };
}
```

### B.4 article_versions persistence

Persist BEFORE regeneration to ensure no data loss if the pipeline fails mid-way.

```typescript
// packages/pipelines/src/article/refresh/persist-version.ts

async function persistVersion(article: Article): Promise<ArticleVersion> {
  const latestVersion = await db.select({ versionNumber: articleVersions.versionNumber })
    .from(articleVersions)
    .where(eq(articleVersions.articleId, article.id))
    .orderBy(desc(articleVersions.versionNumber))
    .limit(1);
  
  const nextVersion = (latestVersion[0]?.versionNumber ?? 0) + 1;
  
  const [inserted] = await db.insert(articleVersions).values({
    articleId: article.id,
    versionNumber: nextVersion,
    title: article.title,
    bodyMd: article.bodyMd,
    metaDescription: article.metaDescription,
    outline: article.outline,
    wordCount: article.wordCount,
    author: article.author,
    versionReason: "refresh",
    snapshotAt: new Date(),
  }).returning();
  
  return inserted;
}
```

### B.5 Source-context fragment for refresh

New variant of `buildSourceContextFragment` for `source = 'refresh_detection'`:

```typescript
function buildRefreshContextFragment(brief: TopicBrief): string {
  const meta = brief.refreshMetadata;
  return `
**Refresh Context:**
This is a refresh of an existing article (last updated ${meta.staleness.daysSinceLastUpdate} days ago).
Refresh reason: ${meta.reason}.

You are NOT writing a new article from scratch. The original body is provided as voice-style reference.
Goals:
1. Preserve the article's narrative arc and voice
2. Update outdated facts (pricing, tool versions, statistics)
3. Add relevant new information (tools/trends that didn't exist or weren't important when first written)
4. Rewrite weak sections, keep strong ones
`;
}
```

### C.2 Translation Decision Call (Haiku)

Before running the translation pipeline, a Haiku call determines whether the EN article needs its own outline (adaptive path) or can use the DE outline as-is (literal path).

```typescript
// packages/pipelines/src/article/translation/decision.ts

export async function decideTranslationStrategy(input: {
  deArticle: Article;
  brief: TopicBrief;
}): Promise<{ decision: "literal" | "adaptive"; reasoning: string }> {
  const prompt = `
You are evaluating whether a German blog article needs an English-audience-specific outline adaptation or can be translated directly.

DE Article Title: ${input.deArticle.title}
DE Article Body (first 2000 chars):
${input.deArticle.bodyMd?.substring(0, 2000)}

Brief context:
- Primary keyword: ${input.brief.primaryKeyword}
- Intent: ${input.brief.intentType}
- Source: ${input.brief.source}

Evaluate whether the article should be:
- "literal": EN version preserves DE outline; only language changes. The content is universally relevant; no German-specific context that needs reframing.
- "adaptive": EN audience needs different angles. Examples: German-specific pricing (EUR only, no USD), DSGVO/BaFin emphasis, "Made in Germany" framing, Mittelstand-specific examples, German market data.

Respond in JSON:
{
  "decision": "literal" | "adaptive",
  "reasoning": "brief explanation (max 100 words)"
}
`;
  
  const response = await anthropic.messages.create({
    model: "claude-haiku-4-5-20251001",
    max_tokens: 200,
    messages: [{ role: "user", content: prompt }],
  });
  
  await logCost({
    projectId: input.deArticle.projectId,
    service: "anthropic",
    operation: COST_OPS.TRANSLATION_DECISION,
    costEur: 0.005, // approximate
    articleId: input.deArticle.id,
  });
  
  return parseJsonResponse(response);
}
```

### C.3 Translation Pipeline

Two paths based on decision:

```typescript
// packages/pipelines/src/article/translation/pipeline.ts

export async function runTranslationPipeline(input: TranslationPipelineInput): Promise<TranslationResult> {
  const deArticle = await loadArticle(input.sourceArticleId);
  const brief = await loadBrief(deArticle.briefId ?? "");
  
  // 1. Decision call
  const decision = await decideTranslationStrategy({ deArticle, brief });
  
  // 2. Load voice references — top 3 EN articles with similar topic
  const voiceRefs = await loadVoiceReferences({
    projectId: deArticle.projectId,
    clusterId: deArticle.clusterId,
    locale: "en",
    excludeArticleId: null,  // no exclusion since we're creating
    limit: 3,
  });
  
  // 3. Build EN brief skeleton
  const enBrief = await buildEnBrief({ deArticle, decision, brief });
  
  // 4. Create EN article row (status='proposed' initially)
  const enArticle = await db.insert(articles).values({
    projectId: deArticle.projectId,
    source: "generated",
    collection: "blog",
    locale: "en",
    translationKey: deArticle.translationKey ?? generateTranslationKey(),
    slug: enArticle.slug,
    title: null,  // filled by pipeline
    cornerstoneKeyword: deArticle.cornerstoneKeyword,
    clusterId: deArticle.clusterId,
    intentType: deArticle.intentType,
    author: deArticle.author,  // SAME author for translation
    status: "proposed",
    approvalMode: deArticle.approvalMode,
  }).returning();
  
  // Update DE article to link translationKey if not yet set
  if (!deArticle.translationKey) {
    await db.update(articles)
      .set({ translationKey: enArticle.translationKey })
      .where(eq(articles.id, deArticle.id));
  }
  
  // 5. Pipeline branch
  if (decision.decision === "adaptive") {
    // Run own Outline + Draft + SelfReview + Schema
    const outline = await runOutlineStep({
      brief: enBrief,
      sourceContext: buildTranslationContextFragment(deArticle, decision),
      toolsContext: await buildToolsContext(enBrief),
      voiceReferences: voiceRefs,
      pipelineRunId: input.pipelineRunId,
      articleId: enArticle.id,
    });
    
    const draft = await runDraftStep({
      brief: enBrief,
      outline,
      sourceContext: buildTranslationContextFragment(deArticle, decision),
      toolsContext: await buildToolsContext(enBrief),
      voiceReferences: voiceRefs,
      pipelineRunId: input.pipelineRunId,
      articleId: enArticle.id,
    });
    
    var bodyMd = draft.bodyMd;
  } else {
    // literal: skip outline, run Translate-Draft step
    const translateResult = await runTranslateDraftStep({
      deBody: deArticle.bodyMd!,
      deOutline: deArticle.outline,
      enBriefHints: enBrief,
      voiceReferences: voiceRefs,
      pipelineRunId: input.pipelineRunId,
      articleId: enArticle.id,
    });
    
    var bodyMd = translateResult.bodyMd;
  }
  
  // 6. Linkify EN tools
  const linkified = await linkifyMarkdown(bodyMd, deArticle.projectId, "en");
  
  // 7. Update EN article
  await db.update(articles)
    .set({
      title: extractTitle(linkified.bodyMd),
      bodyMd: linkified.bodyMd,
      wordCount: countWords(linkified.bodyMd),
      outline: decision.decision === "adaptive" ? outline.value : translateOutline(deArticle.outline),
      status: "draft_done",
      updatedAt: new Date(),
    })
    .where(eq(articles.id, enArticle.id));
  
  // 8. SelfReview + Schema for EN
  await runSelfReviewStep({ articleId: enArticle.id, pipelineRunId: input.pipelineRunId });
  await runSchemaExtensionStep({ articleId: enArticle.id });
  
  return {
    sourceArticleId: deArticle.id,
    enArticleId: enArticle.id,
    decision: decision.decision,
    decisionReasoning: decision.reasoning,
    toolsLinked: linkified.linkedTools,
  };
}
```

```typescript
    pipelineRunId: input.pipelineRunId,
  });

```

Prompt structure (sketch):
```
You are translating a German blog article into idiomatic English for an international audience.

Voice references (existing English articles in the same content space):
{voice_references}

The DE article body to translate:
{de_body}

Requirements:
- Preserve the article's narrative structure (don't reorder sections)
- Use idiomatic English, not literal word-for-word translation
- Match the voice tone of the reference articles (anti-hype, concrete, pragmatic)

Output: the translated article body in markdown, no preamble or commentary.
```

### C.5 Refresh propagation to EN sibling

When a DE article is refreshed (Section B), and an EN sibling exists, automatically refresh the EN sibling:

```typescript
// At end of Refresh Pipeline (Section B.3, step 9):
if (article.locale === "de") {
  const enSibling = await findEnSibling(article);
  if (enSibling) {
    await enqueueTranslationPipeline({ 
      sourceArticleId: article.id, 
      targetArticleId: enSibling.id, 
      mode: "refresh_propagation",
    });

}
```

The `mode: "refresh_propagation"` variant:
- Persists EN sibling's current body to `article_versions` (same as Refresh)
- Runs Translation Pipeline with EN article as target (UPDATE not INSERT)
- Decision call still fires (literal vs adaptive based on refreshed DE content)

### D.1 Voice-Reference Loader

```typescript
// packages/pipelines/src/article/voice-reference/loader.ts

export interface VoiceReference {
  articleId: string;
  title: string;
  bodyMdExcerpt: string;  // first 1500 chars
  intentType: string | null;
  selfReviewScore: number | null;
}

export async function loadVoiceReferences(input: {
  projectId: string;
  clusterId: string | null;
  locale: "de" | "en";
  excludeArticleId: string | null;
  limit?: number;
}): Promise<VoiceReference[]> {
  const limit = input.limit ?? 3;
  
  // Strategy: same cluster + locale, highest self-review-score, most recent
  const conditions = [
    eq(articles.projectId, input.projectId),
    eq(articles.collection, "blog"),
    eq(articles.locale, input.locale),
    sql`${articles.bodyMd} IS NOT NULL`,
    sql`${articles.bodyMd} != ''`,
  ];
  
  if (input.clusterId) {
    conditions.push(eq(articles.clusterId, input.clusterId));
  }
  
  if (input.excludeArticleId) {
    conditions.push(sql`${articles.id} != ${input.excludeArticleId}`);
  }
  
  const rows = await db.select({
    id: articles.id,
    title: articles.title,
    bodyMd: articles.bodyMd,
    intentType: articles.intentType,
    selfReviewScore: articles.selfReviewScore,
  })
    .from(articles)
    .where(and(...conditions))
    .orderBy(desc(articles.selfReviewScore), desc(articles.createdAt))
    .limit(limit);
  
  // Fallback: if no cluster-matched articles, try project-wide
  if (rows.length === 0 && input.clusterId) {
    return loadVoiceReferences({ ...input, clusterId: null });
  }
  
  return rows.map(r => ({
    articleId: r.id,
    title: r.title ?? "",
    bodyMdExcerpt: r.bodyMd?.substring(0, 1500) ?? "",
    intentType: r.intentType,
    selfReviewScore: r.selfReviewScore,
  }));
}
```

```typescript
export async function findEnSibling(deArticle: Article): Promise<Article | null> {
  if (deArticle.locale !== "de" || !deArticle.translationKey) {
```

```typescript
// apps/api/src/lib/chain-orchestrator.ts (existing file, add helper)

function determineChainPath(brief: TopicBrief): ChainStep[] {
  if (brief.source === "refresh_detection") {
    // Refresh chains: blog → localize → schema-en → astro-transfer
    // The blog step in refresh mode targets the existing article
    return ["blog", "localize", "schema-en", "astro-transfer"];
  }
  
  if (isBlogEligible(brief)) {
    // Fresh blog: blog → localize → schema-en → astro-transfer
    return ["blog", "localize", "schema-en", "astro-transfer"];
  }
  
  // Legacy/other: outline → draft → schema-de → localize → schema-en → astro-transfer
  return ["outline", "draft", "schema-de", "localize", "schema-en", "astro-transfer"];
}
```

The `localize` step (existing) is the integration point for Translation-Mode. Its implementation reads the chain's article and enqueues Translation Pipeline.

## Open Questions / Decisions Made

**Decision 1: Refresh operates in place + versioning, not new article row.**

Per clarification A2(b): `article_versions` preserves history. Article ID stays the same so URLs, internal links, and external references remain valid. Versioning gives audit trail.

**Decision 2: Refresh trigger is manual only in 54.10.**

Per clarification A1(a): auto-detection and heuristic-based stale detection deferred to Phase E backlog. Manual button is the only trigger.

**Decision 3: Refresh uses full re-gen with voice continuity.**

Per clarification A3(d): Full pipeline (outline+draft+self-review+schema) with existing body as style reference. Maximum content quality at cost of higher compute.

**Decision 4: New `cluster_action` value: `"refresh"`.**

Refresh briefs use `cluster_action = 'refresh'` distinct from `'standalone'`, `'create_new'`, `'add_to_cluster'`, `'translation'`. Already in the enum per Reference Pack Section 6 — just needs to be utilized.

**Decision 5: Translation auto-triggers, with project toggle for opt-out.**

Per clarification B1(a): toolwiki gets auto-translation. New column `projects.translation_auto_trigger` (boolean, default true). Other projects can disable.

**Decision 6: DE is source-of-truth.**

Per clarification B2(a): EN always translated from DE. EN modifications outside the pipeline (via UI editing) are tracked but don't sync back to DE. No bidirectional sync in 54.10.

**Decision 7: Voice-specific translation with reference articles.**

Per clarification B3(c): LLM gets DE body + 3 existing EN articles as voice style references. Avoids stilted direct translations.

**Decision 8: Adaptive decision via Haiku call.**

Per clarification B4 followup (1): Haiku call before translation decides literal vs adaptive. Cost €0.005, value: avoids unnecessary Outline run when content is universal.

**Decision 9: ChainStep migration is included here, not deferred.**

Per Spec 54.9 Deviation 3: this migration was already postponed once. Including in Section A of 54.10 closes the loop.

**Decision 10: Refresh propagates to EN sibling automatically.**

When DE article refreshes and EN sibling exists, EN auto-refreshes via Translation Pipeline in `refresh_propagation` mode. Keeps content in sync without manual coordination.

**Decision 11: Translation uses same author as source.**

EN sibling has the same `articles.author` as the DE source. No Author-Picker call. Maintains author consistency across language pairs (avoiding "thomas-mueller for DE, anna-weidner for EN" inconsistency).

**Decision 12: No new article status enum values.**

Refresh keeps article at `published`. Translation creates EN article that flows through normal status progression (proposed → draft_done → final_review → ... → published).

**Decision 13: Translation cost lower than originally estimated.**

Per Brief 1 real data (€0.39 vs €1.17 estimate): all generation costs are ~70% under original estimates. 54.10 cost table reflects this. Voice validation in 54.9 was the deciding factor.

**Decision 14: article_versions persistence happens BEFORE regeneration, not after.**

Defensive: if the refresh pipeline fails mid-way, the original body is already preserved. Worst case: a phantom version row with no corresponding article update. Better than: pipeline failure mid-write corrupting the article.

**Decision 15: Voice references are read-only operational data.**

They're loaded per pipeline run, not cached long-term. Articles change (refreshes, edits), and stale references would degrade voice quality. Each pipeline run gets fresh references.
