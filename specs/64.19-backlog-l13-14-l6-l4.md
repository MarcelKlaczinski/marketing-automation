## 1. Problem

Vier Backlog-Items, alle aus Backlog v3.1 Low Priority, alle isoliert vom aktiv laufenden Cluster-Toolification Stream:

**L13 — F2 Pipeline-Run-Count Visibility:**
`astro:repo-import` produziert 11 pipeline_runs Rows pro Trigger (1 parent + 10 step-children, by-design per Section 9 Pattern 6). UI zeigt verwirrend "11 runs" als wären 11 Imports passiert. Memory D8 dokumentiert dass per-step outputs als child rows mit parent_run_id+step_name leben — die UI weiß das nicht.

**L14 — Articles-Lane-Filter `superseded` im UI:**
8 superseded articles in Toolwiki nach Cleanup-Cycle (Anomaly-A revert + Branch-B-Refactor-Aftermath). UI ArticlesLanePage zeigt nur active status. Audit-Trail-Sichtbarkeit fehlt — wenn Marcel fragt "warum ist X plötzlich weg?", muss er heute SQL fahren.

**L6 — maxAgeDays per-source config:**
RSS feeds können stale content produzieren — items mit recent fetch-dates aber tatsächlich Wochen alt. Heute hardcoded threshold pro source-adapter. Multi-Tenant-relevant: Balkon-Kraftwerk-Domain wird andere Stale-Toleranz brauchen als Toolwiki.

**L4 — Adjustable trend score weights per project:**
Trend-scoring formula in `packages/pipelines/src/topic-sources/trend-discovery/score.ts` gewichtet (recency, signal-strength, novelty, source-diversity, etc.) sind hardcoded. Memory D8 §144 sagt: "Score-Knobs als API-Input fields erlauben live re-tune ohne deploy". Multi-Domain-Pattern via 64.14 jsonb-override verfügbar.

### 6.2 Score-Function Update

`packages/pipelines/src/topic-sources/trend-discovery/score.ts`:

```typescript
import { getTrendScoreWeights } from "@marketing-auto/shared";

const DEFAULT_WEIGHTS: TrendScoreWeights = {
  recency: 0.4,
  signal_strength: 0.3,
  novelty: 0.2,
  source_diversity: 0.1,
};

export async function scoreBrief(brief: Brief, projectId: string): Promise<number> {
  const override = await getTrendScoreWeights(projectId);
  const weights = { ...DEFAULT_WEIGHTS, ...override };
  
  return (
    weights.recency * recencyScore(brief) +
    weights.signal_strength * signalStrengthScore(brief) +
    weights.novelty * noveltyScore(brief) +
    weights.source_diversity * sourceDiversityScore(brief)
  );
}
```

## 11. Discovered & Deviations

13 deviations from the original spec sketch, ordered roughly by impact:

1. **Phase A premise was outdated** — spec §1+§3.1 assumed the UI shows "11 rows" for `astro:repo-import`. Code-read of [apps/api/src/routes/projects/pipeline-runs.ts:76](apps/api/src/routes/projects/pipeline-runs.ts:76) confirmed the API already filters parent rows only (`isNull(pipelineRuns.stepName)`) since Spec 62.6. The spec's premise was based on stale code; Spec 004 / F2 documented the parent+children pattern. The remaining win was `(N steps)` discoverability hint + header counter — implemented as a much smaller change than the spec sketched.

2. **Phase B no `superseded_at`/`superseded_by` columns** — verified Phase B §4.1 verify-point 7: only the `status` enum value was added by Spec 001 migration 0102. Tooltip falls back to the `updatedAt` relative-time hint; replacement-link feature deferred.

3. **Phase B `VALID_ARTICLE_STATUSES` allow-list was the gate** — spec §4 framed this as a UI-only filter, but the backend's status-validation Zod array at [apps/api/src/routes/projects/articles.ts:30](apps/api/src/routes/projects/articles.ts:30) didn't include `superseded`. Widening the allow-list was a prerequisite. Added `includeSuperseded` query param + default-exclude behaviour with `ne(articles.status, "superseded")` (per Memory rule — never `sql\`!= \``).

4. **Phase C — chose existing `signal_sources` jsonb pattern over spec's project_planner_config column** — reddit + github already had per-project `maxAgeDays` in [packages/db/src/schema/project-config.ts](packages/db/src/schema/project-config.ts) `SignalSourcesSchema` (Spec 64.14 pattern). Extending the existing schema for hackernews + vendor_rss was cleaner than introducing a parallel storage location on `project_planner_config`. Result: **NO Phase C migration needed** — pure Zod schema extension + adapter wiring.

5. **Phase C — both inner AND outer `.default(...)` blocks need the new field** — the `SignalSourcesSchema` has nested `.default()` at the object-level AND a top-level `.default(...)` for entirely-missing rows. Updating only the inner schema would leave a stale shape on outer-default-path rows. Both blocks updated for hackernews (default 30) and vendor_rss (default 14) to match the adapter-side schema constants.

6. **Phase D — score knob names differ from spec** — spec §6.1 sketched `recency / signal_strength / novelty / source_diversity`. Actual `W` constant in [score.ts:12](packages/pipelines/src/topic-sources/trend-discovery/score.ts:12) is `{buzz, growth, official, serp, diversity, coverage}` (Spec 54.5b rebalance — positive weights sum to 100, coverage is the existing-coverage penalty). Used actual knob names + defaults (15/15/25/20/25/40).

7. **Phase D — `ResolvedTrendScoreWeights` separate from `TrendScoreWeights`** — Zod's `z.number().optional()` infers `number | undefined`, and `Required<TrendScoreWeights>` under `exactOptionalPropertyTypes` doesn't strip the `undefined` (only flips `?` → required). Introduced a concrete `interface ResolvedTrendScoreWeights` so `resolveTrendScoreWeights()` returns a fully-narrowed shape and the `weights.buzz` usages in score.ts don't trip TS18048.

8. **Phase D — projects.ts new-project literal needed `maxAgeDays` too** — the Zod schema widening caused the literal in [apps/api/src/routes/projects.ts:262](apps/api/src/routes/projects.ts:262) (POST `/` new-project) to fail the type check. TypeScript surfaced this as a confusing "projectId does not exist in […][]" overload-mismatch error (fell back to the array-form overload). Same fix needed in [apps/api/test/plan-generation.test.ts](apps/api/test/plan-generation.test.ts) and [packages/planner/test/signal-refresh.test.ts](packages/planner/test/signal-refresh.test.ts) fixture seeds.

9. **Phase D — pre-existing two fixture sites for `projectPlannerConfig` literals also needed `trendScoreWeights: null`** — both [packages/pipelines/test/planning/{budget-gate-step,select-overage-items-step}.test.ts](packages/pipelines/test/planning/) had hand-rolled config fixtures requiring all schema fields. Pattern continues from 64.14 (when `signalSourceContentTypeMap` was added).

10. **Phase D — `trendScoreWeights` NOT snapshotted into `plannerConfigSnapshotSchema`** — unlike 62.5.1 llmMode + 63.5 diversity, trend score weights are consumed at trend-synthesis time (when briefs are scored for the `min_trend_score` threshold), NOT at plan-generation time. Plan-replay reproducibility doesn't depend on the weights snapshot. Deliberate omission, contrast with the snapshot-everything pattern.

11. **Phase D — `buildTrendScoreWeightsPayload()` returns `null` when all defaults match** — UX trade-off: instead of persisting `{buzz:15, growth:15, ...}` (a copy of the code defaults), the helper returns `null` to clear the column. Means future code-default changes auto-apply to projects that hadn't customised; downside is loss of "Marcel explicitly set these as defaults" intent. Defensible — `NULL = use defaults` is the cleaner contract.

12. **Phase D — `score.ts` no longer keeps the local `W` constant** — replaced with `DEFAULT_TREND_SCORE_WEIGHTS` import + `resolveTrendScoreWeights()` call. The dead `W` line removal triggered a TS6133 unused-import — caught + fixed in the same pass.

13. **Pre-existing test failures fixed in the same session** (per Marcel's request "fix die pre existing test failures gleich mit"):
    - `@marketing-auto/core` `buildHashtagInstructions` 2 fails — test asserted DE anchor tags appear in EN-locale output, but the impl is explicitly English-only ("English only — NO German hashtags" rule). Test was wrong, impl was correct. Split into separate `deCases` + `enCases` `it.each` blocks asserting the right invariants per locale.
    - `@marketing-auto/adapter-{voyage, producthunt, pagespeed}` — empty `test/` directories caused Bun's `bun test` runner to exit 1 with confusing "Tests need .test/.spec in filename" message. Added smoke-level `surface.test.ts` files (5 + 3 + 3 cases) covering public exports + sane error-class construction + cheap input-schema validation without network calls.
