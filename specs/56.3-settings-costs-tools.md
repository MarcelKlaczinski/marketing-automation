# Spec 56.3: Settings + Costs + Article Tools

**Theme:** 56 / UI Refactoring — Sub-spec 3 of 4
**Phase:** Project-Independent Views
**Estimated Effort:** ~4-5 days (~28 focused hours across 6 sessions)
**Dependencies:**
- Spec 56.1 (Dashboard MVP — foundation: AppShell, design tokens, atomic components)
- Spec 56.2 (Multi-pane Views — shared components, form patterns)
- Spec 55.1 (Backend Routes Foundation — cost-summary endpoint)

**Status:** Ready for implementation
**Recommended Model:** Sonnet 4.6 for implementation work.

---

## Goal

Build the three platform-level views that complete Marcel's "alle einstellungen machen können" requirement:

1. **Settings** — project config, brand tokens, brand assets, system credentials. Forms-heavy. Explicit Save per section with dirty tracking.

2. **Costs** — overview dashboard with monthly trends + service/operation breakdown. Plus alerts management (acknowledge, view triggered alerts).

3. **Article Tools** — power-user toolbox. Tab 1: Generate single article from scratch (Topic → Keyword → Intent → Author → Collection → Locale → Submit). Tab 2: Manual pipeline triggers for existing articles (re-trigger outline, re-trigger draft, regen hero image, extend schema, refresh, localize, sync).

After this spec lands, Marcel has full control panel: pipeline orchestration (56.1), content visibility (56.2), platform configuration + manual interventions (56.3). Cold-Start onboarding is the final piece (56.4).

## What this is NOT

- Not Cold-Start migration — that's 56.4
- Not Pipeline Templates editor — Phase E (rarely changed)
- Not Push Subscriptions UI in Settings — those are user-account-level, accessible via user menu in topbar
- Not User/Auth/Session settings — Phase E (solo-dev, single user)
- Not cost forecasting / predictions — Phase E
- Not creating new backend endpoints for Article Tools — existing pipeline triggers reused
- Not redesigning Pipeline Run Detail Pane — that's already in 56.1 Dashboard

- **Section A**: Backend additions (minimal — mostly UI on existing endpoints)

### A.2 Single new endpoint: `POST /api/projects/:slug/articles/generate-standalone`

For Article Tools "Generate New Single Article" wizard. Existing `POST /articles/generate` requires a `cornerstoneSlug` (an existing cornerstone_spec). For a from-scratch wizard, we need an endpoint that accepts raw inputs:

```typescript
// apps/api/src/routes/projects/articles-standalone.ts

const standaloneGenerateSchema = z.object({
  topic: z.string().min(5).max(200),
  primaryKeyword: z.string().min(2).max(100),
  collection: z.enum(["blog", "tools", "comparisons", "ki-wissen", "usecases", "tool-categories"]),
  locale: z.enum(["de", "en"]),
  intentType: z.enum([
    "overview", "general", "review", "comparison",
    "pricing", "tutorial", "use-cases", "features"
  ]).default("general"),
  authorSlug: z.string().optional(),  // if not provided, author-picker runs
  clusterId: z.string().uuid().optional(),  // if not provided, article is standalone (no cluster)
  approvalMode: z.enum(["assist", "auto"]).default("assist"),
  estimatedWordCount: z.number().int().min(500).max(5000).default(2000),
});

async function handleStandaloneGenerate(c: Context) {
  const { slug } = c.req.param();
  const input = standaloneGenerateSchema.parse(await c.req.json());

  const project = await loadProjectBySlug(slug);
  if (!project) return c.json({ ok: false, error: "project_not_found" }, 404);

  // Cost + pause check
  const triggerCheck = await checkTriggerAllowed({
    projectId: project.id,
    operation: "article:blog",
  });
  if (!triggerCheck.allowed) {
    return c.json({ ok: false, ...triggerCheck.errorPayload }, triggerCheck.errorStatus);
  }

  // Generate slug from topic
  const articleSlug = slugify(input.topic);

  // Create synthetic brief (source='manual') for audit trail
  const [brief] = await db.insert(topicBriefs).values({
    projectId: project.id,
    source: "manual",
    topicTitle: input.topic,
    primaryKeyword: input.primaryKeyword,
    locale: input.locale,
    intentType: input.intentType,
    clusterId: input.clusterId ?? null,
    clusterAction: input.clusterId ? "add_to_cluster" : "standalone",
    suggestedTitle: input.topic,
    suggestedSlug: articleSlug,
    suggestedMeta: "",
    approvalStatus: "approved",
    approvedBy: "user",
  }).returning();

  // Create article row (will be filled by pipeline)
  const articleId = generateArticleId();
  await db.insert(articles).values({
    id: articleId,
    projectId: project.id,
    source: "generated",
    collection: input.collection,
    locale: input.locale,
    slug: articleSlug,
    title: null,  // filled by pipeline
    cornerstoneKeyword: input.primaryKeyword,
    clusterId: input.clusterId ?? null,
    intentType: input.intentType,
    author: input.authorSlug ?? null,  // null = author-picker decides
    status: "proposed",
    approvalMode: input.approvalMode,
  });

  // Enqueue blog pipeline
  const runId = await enqueueBlogGeneration({
    projectId: project.id,
    articleId,
    briefId: brief.id,
    targetWordCount: input.estimatedWordCount,
  });

  return c.json({
    ok: true,
    data: {
      articleId,
      briefId: brief.id,
      runId,
      jobId: runId,  // backward compat
    },
  }, 202);
}
```

**Note**: this is the only new endpoint in 56.3. Everything else uses existing routes from prior specs.

### B.4 useFormDirty composable

Tracks dirty state for a form section.

```typescript
// apps/web/src/composables/useFormDirty.ts
import { ref, computed, watch } from "vue";
import type { MaybeRef } from "vue";

/**
 * Tracks dirty state by comparing current to original.
 * Use unref() pattern for Options API compatibility (per 56.1 pattern).
 *
 * Pattern usage in component:
 *   const dirty = useFormDirty(() => this.formData, () => this.originalData);
 */
export function useFormDirty<T extends Record<string, unknown>>(
  current: MaybeRef<T> | (() => T),
  original: MaybeRef<T> | (() => T),
) {
  const dirty = computed(() => {
    const currentVal = typeof current === "function" ? current() : unref(current);
    const originalVal = typeof original === "function" ? original() : unref(original);
    return JSON.stringify(currentVal) !== JSON.stringify(originalVal);
  });

  return { dirty };
}
```

**Note**: JSON.stringify comparison is acceptable for shallow form data. For deeply nested or fields with order-sensitive arrays, use a proper deep equality library (lodash isEqual). For Settings forms in 56.3, JSON.stringify works.

### B.5 useSectionForm composable

High-level form pattern for sections with explicit save.

```typescript
// apps/web/src/composables/useSectionForm.ts
import { ref, watch } from "vue";
import { useMutation, useQueryClient } from "@tanstack/vue-query";

interface UseSectionFormOptions<TFormData, TResponse> {
  initialData: () => TFormData;
  onSave: (data: TFormData) => Promise<TResponse>;
  invalidateKeys?: string[][];
  onSuccess?: (response: TResponse) => void;
  onError?: (error: Error) => void;
}

/**
 * Section-scoped form with explicit save pattern.
 * Returns:
 * - formData: editable reactive copy
 * - originalData: pristine reference for dirty comparison
 * - dirty: boolean computed
 * - save: action that calls onSave + invalidates queries
 * - cancel: revert formData to originalData
 * - saving: boolean
 * - lastSavedAt: timestamp of last successful save
 */
export function useSectionForm<TFormData, TResponse>(
  options: UseSectionFormOptions<TFormData, TResponse>,
) {
  const queryClient = useQueryClient();
  const formData = ref<TFormData>(options.initialData());
  const originalData = ref<TFormData>(options.initialData());
  const lastSavedAt = ref<string | null>(null);

  const { mutateAsync, isPending } = useMutation({
    mutationFn: options.onSave,
    onSuccess: (response) => {
      originalData.value = JSON.parse(JSON.stringify(formData.value));
      lastSavedAt.value = new Date().toISOString();

      if (options.invalidateKeys) {
        for (const key of options.invalidateKeys) {
          queryClient.invalidateQueries({ queryKey: key });
        }
      }

      options.onSuccess?.(response);
    },
    onError: options.onError,
  });

  const dirty = computed(() =>
    JSON.stringify(formData.value) !== JSON.stringify(originalData.value)
  );

  const cancel = () => {
    formData.value = JSON.parse(JSON.stringify(originalData.value));
  };

  // Reset if upstream initialData changes (e.g. refetch)
  const resetFromUpstream = () => {
    const fresh = options.initialData();
    formData.value = JSON.parse(JSON.stringify(fresh));
    originalData.value = JSON.parse(JSON.stringify(fresh));
  };

  return {
    formData,
    originalData,
    dirty,
    saving: isPending,
    lastSavedAt,
    save: () => mutateAsync(formData.value),
    cancel,
    resetFromUpstream,
  };
}
```

This composable lives in `src/composables/useSectionForm.ts` per the 56.2 pattern (Composition API primitives MUST live in composables, not inline).

        clusterId: null as string | null,
        estimatedWordCount: 2000,
      },

      intentOptions() {
        return ["overview", "general", "review", "comparison", "pricing", "tutorial", "use-cases", "features"];

        // Based on Spec 54.9 real data (€0.39 per article)
        const baseCost = 0.39;
        const wordCountMultiplier = this.form.estimatedWordCount / 2000;
        return baseCost * wordCountMultiplier;

            ...this.form,

            type: "negative",

          });
        } finally {

        }
      },

  import { defineComponent, PropType } from "vue";

  type ActionKey =
    | "outline" | "draft" | "hero-image" | "schema"
    | "refresh" | "localize" | "continue"
    | "sync" | "pagespeed" | "preview";

  const ACTION_ENDPOINTS: Record<ActionKey, string> = {
    outline: "generate-outline",
    draft: "generate-draft",
    "hero-image": "generate-hero-image",
    schema: "extend-schema",
    refresh: "refresh",
    localize: "localize",
    continue: "continue",
    sync: "sync",
    pagespeed: "validate-pagespeed",
    preview: "local-preview",
  };

  export default defineComponent({
    name: "ArticleTriggersPanel",
    emits: ["triggered"],
    props: {
      article: { type: Object as PropType<Article>, required: true },
    },
    data: () => ({
      loadingAction: null as ActionKey | null,
    }),
    methods: {
      async onTrigger(action: ActionKey) {
        // Confirm for destructive/expensive actions
        if (action === "refresh") {
          const ok = await this.$q.dialog({
            title: this.$t("articleTools.manual.confirmRefresh.title"),
            message: this.$t("articleTools.manual.confirmRefresh.message"),
            cancel: true,
            persistent: true,
          }).then(() => true).catch(() => false);
          if (!ok) return;
        }

        this.loadingAction = action;
        try {
          const endpoint = ACTION_ENDPOINTS[action];
          const response = await apiClient.articles.triggerAction({
            articleId: this.article.id,
            action: endpoint,
          });

          this.$q.notify({
            type: "positive",
            message: this.$t("articleTools.manual.triggerSuccess", {
              action: this.$t(`articleTools.manual.actions.${action}.title`),
            }),
          });

          this.$emit("triggered", { action, runId: response.data.runId });
        } catch (err) {
          this.$q.notify({
            type: "negative",
            message: err instanceof Error ? err.message : this.$t("articleTools.manual.triggerError"),
          });
        } finally {
          this.loadingAction = null;
        }
      },
    },
  });
</script>

## Deviations (Sessions 1–2)

**D1: `clusterAction` value for clustered standalone articles.**
Spec said `"add_to_cluster"` but the DB schema enum (`packages/db/src/schema/content.ts`) only has `"append_to_existing"`, `"create_new"`, `"translation"`, `"refresh"`, `"standalone"`. Implementation correctly uses `"append_to_existing"`.

**D2: `lastSavedAt` prop binding uses `?? ''` not `?? undefined`.**
Spec showed `lastSavedAt` as nullable. With `exactOptionalPropertyTypes`, passing `string | undefined` to a `String` prop fails. All FormSection usages pass `form.lastSavedAt.value ?? ''` (empty string is falsy so the display guard still works).

**D3: Number form fields stored as strings.**
Spec showed `v-model="costForm.formData.value.monthlyBudgetEur"` with a `number` field. `FormInput.modelValue` is typed `String`, so number inputs must store strings in form data and parse on save. `useSettingsProjectPage` uses `String(n)` on read and `parseFloat()/parseInt()` on save.

**D4: `translationAutoTrigger` added to PATCH schema.**
Spec omitted this field from the `updateProjectSchema`. Added in Session 2 since SettingsProjectPage's translation section requires it.

## Discovered During Implementation (Sessions 1–2)

- Module-level helper functions in `.vue` files cannot call `this.$t()`. Any formatting that produces user-visible strings must live in a computed property. `FormSection.formatRelative()` had hardcoded German strings — fixed by inlining in `relativeSavedAt` computed.
- `useSettingsProjectPage` uses the `watch(project, resetFromUpstream)` pattern: composable initializes with empty defaults, watch fires on data load and calls `resetFromUpstream()` on all 6 form handles. This is the canonical pattern for composables whose `initialData` depends on an async query.

## Discovered During Implementation (Sessions 3–4)

- Module-level time-formatting function recurs as footgun: `CostAlertCard.vue` repeated the exact same mistake with `formatRelative()` returning hardcoded English strings. Rule is now in CLAUDE.md. Every relative-time display must use `this.$t("forms.justNow")` / `forms.minutesAgo` etc. from the `forms` namespace inside a method or computed.
- Window-selector + reactive fetch: `CostsPage` uses `data.currentWindow` + `watch: { currentWindow() { void this.fetchCostData() } }` + `mounted(){ void this.fetchCostData() }` instead of TanStack Query because reactive `data()` values cannot be passed as queryKeys to `setup()`. For any filter/window/tab that lives in `data()`, use direct `apiGet()` + watcher pattern. TanStack is only suitable when the queryKey parameters are known at mount time.
- Raw `fetch()` for multipart upload is justified (apiPost assumes JSON), but GET requests must always use `apiGet()`. Initial `SettingsBrandAssetsPage` used raw fetch for the list GET — fixed.
- Session 3 was split into 3a (form editor) and 3b (JSON editor + page) due to compound complexity of CodeMirror init + form toggle. SettingsBrandAssetsPage was moved to start of Session 4.

## Discovered During Implementation (Sessions 5–6)

- **`v-for` + `v-else` on the same element is invalid in Vue 3.** `ArticleManualTriggersTab` had `<ArticleListItem v-for="…" v-else>` — Vue silently drops one directive. Fix: `<template v-else><Item v-for="…" /></template>`. Rule added to `apps/web/CLAUDE.md`.
- **`data()` label strings are not translatable.** `SettingsCredentialsPage` stored `label: "API Key"` inside the adapter definitions in `data()`. `data()` has no access to `this.$t()`. Fix: store the i18n key path as `labelKey: "settings.credentials.keys.apiKey"` and resolve in the template with `$t(keySpec.labelKey) as string`. Rule added to `apps/web/CLAUDE.md`.
- **`<option>` text recurs as hardcoded-string footgun.** `ArticleGenerateTab` had hardcoded "Blog", "Tools", "DE", "EN" in option labels. Fix: computed array of value strings + `$t(\`articles.filters.collections.\${col}\`)`. Reuse existing `articles.filters.collections.*`, `articles.filters.locales.*`, `articles.status.*` keys. Rule added to `apps/web/CLAUDE.md`.
- **`article.collection` / `.locale` / `.status` in metadata spans still need `$t()`.** Even inside `.mono`-styled technical badges, these are DB enum values and must be translated. Pattern: `$t(\`articles.filters.collections.\${col}\`, col) as string` — second argument is the raw value fallback for keys not yet in i18n.
- **AuthorPicker is a plain `FormInput`** because no `/authors` API endpoint exists. No select/dropdown possible without an API. The spec's mention of `GET /projects/:slug/articles?collection=authors` was not implemented — deferred until an authors management page is built.
