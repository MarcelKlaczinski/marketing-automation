**Status:** ✅ shipped 2026-05-28

## 1. Context

V1.6 shipped Hook-Library, Brand-Stamp, NB2 + Visual-Style presets, and Tool-Tier-Ranking. The first cron-fires + Marcel's live-renders surfaced bugs that unit-tests could not catch — production output was systematically broken across 3 social_posts:

| social_post.id | template | issue |
|---|---|---|
| `d0845843-…` | lifestyle-listicle | literal `"the tool"` in narrative + EN-in-DE + "??" icons |
| `7246dd40-…` | opinion-recommendation | `<CAPTION>` + `<HASHTAGS>` tags rendered IN slide-text |
| `18ea5f58-…` | story-arc-clickbait | off-topic Pexels-BTS stock photo on cover |

## 2. Root Causes (post-mortem 2026-05-28)

1. **Splitter greedy-capture:** `splitNarrativeByBeats` in `packages/social/src/compositions/_shared/family-b/helpers.ts` captured everything from `## topPick` to EOF, leaking trailing `<CAPTION>…</CAPTION>` + `<HASHTAGS>…</HASHTAGS>` tagged blocks into the last beat's text → rendered verbatim in slide.
2. **Literal LLM-prompt fallback:** template `buildInput()` fallback `name: "the tool"` propagated verbatim into every narrative beat under the Sonnet prompt's "Every item beat MUST name the tool" rule.
3. **Brand-stamp asset-content gap:** `project_brand_assets` row `asset_key='main'` had `source='wordmark'` which `resolveLogoUrl` deliberately skips (Spec 65.15) — Toolwiki had no `inline-svg` variant for the resolver to consume.
4. **Stock-photo relevance failure:** photographic-pipeline systematically picked off-topic Pexels images (vision-pick has 40-char beat-text context only; query-keyword generator is generic).

## 7. Discovered & Deviations

1. **Phase 1.3 dropped:** Family-A multi-slide `tools[]` synthesis (Spec 65.7-followup-2) doesn't apply to Family-B (single `featuredTool`, different shape). Covered by Phase 1.4 + 1.5 instead.
2. **Phase 1.6 was a no-op:** post-mortem audit-agent's "missing CoverComposition injection" was incorrect — `SlideComposition.tsx` dispatcher already wires `<DsBrandStamp>` for `variant === "cover"`. The actual gap was upstream (Phase 0 asset-content).
3. **Phase 4 skipped:** triple-defense at composition-side would be redundant — Phase 1.1 (splitter) + Phase 1.2 (extractNarrative scrub) cover all known leaks.
4. **`as wordmark` row stays untouched:** existing `project_brand_assets.main` row keeps `source='wordmark'` for other surfaces. Resolver finds the new `main-light`/`main-dark` rows first per the 3-tier chain (Spec 65.15).
5. **/review-task caught a BLOCKER:** Phase 2 originally only flipped `packages/pipelines/.../stage-family-b-images.step.ts` — the parallel `apps/api/.../resolve-image-style-preset.ts` table was missed. JSDoc comments explicitly say "keep in sync" but TypeScript doesn't enforce. Caught + fixed in /review-task.
6. **Independent code-reviewer agent gave 2 MINOR findings, both already invalid:** (a) claimed `apps/api/.../resolve-image-style-preset.ts` doesn't exist — the file DOES exist and was the BLOCKER above; (b) "missing test coverage" for fallback path — accepted as V1.6.2 follow-up since fallback fires rarely in production.
7. **Two DB-resolver helpers intentionally duplicate** (`resolve-featured-tool.ts` in apps/api + `load-family-b-tool.ts` in packages/social) — package boundaries forbid `packages/social → @marketing-auto/db` static imports because that pulls pipelines/Anthropic into the renderer bundle. The template-side helper uses `await import("@marketing-auto/db")` for cold-path-cheap; the brief-generator-side uses a static top-level import because apps/api always has the DB context.
8. **`console.warn` in template `buildInput`:** annotated with `// biome-ignore lint/suspicious/noConsole: pure helper, no logger in scope` + justification. Fires only on broken legacy briefs (rare path). Same pattern other template files use.
